# Правила работы с макетом

Над репозиторием работают несколько человек, все в ветке `main`, без PR.
Макет смотрят через GitHub Pages: https://ndm234234.github.io/consolem/

## index.html — только согласованное

`index.html` — основной макет. Он работает через API: интерфейс читает и меняет данные запросами к встроенному тестовому серверу (`api/`), своих данных у него нет. API — универсальная модель объектов (с контракта 0.2.0; текущая версия — `info.version` в `api/openapi.json`): виды объектов приходят с сервера (`/kinds`), объекты — одним складом (`/units`, адрес — `uid`), ручные экраны привязаны к профилю вида (`vms.camera/1`…), незнакомый вид показывается формой по схеме. Прежний макет и прежний контракт (`/devices`, `/servers`…) — только в истории git: `git show 47d1310:index.html`, `git show 47d1310:api/openapi.json`; таблица перехода — `api/README.md`, «Ломающие изменения против контракта старого макета». Его меняют **только по явной просьбе**: «в основной», «в index.html», «перенеси в основной» — или по запросу команды VMS (скилл `vms-requests`).

Любая правка `index.html` — с проверками из `api/TESTS.md`: как минимум `python3 tools/check_api.py`, `python3 tools/check_ui.py` и `python3 tools/check_perf.py --quick` (скорость на large, около 2,5 мин). Новые данные и действия — через контракт `api/openapi.json` и сервер, не константами в HTML; если в контракте их нет — расширь контракт или напиши запрос (скилл `api-contract`).

`index.html` правим и мы, и altumur. Конфликт при `git pull --rebase` сводит тот, кто пушит вторым: сохрани обе правки, а если они несовместимы — спроси пользователя.

## Всё остальное — в прототип

Любую другую просьбу изменить макет выполняй в файле прототипа, даже если о прототипе ничего не сказано.

- Если в этом разговоре уже есть прототип или пользователь назвал его («в прототипе 03»), продолжай в нём.
- Новый прототип создавай, когда в разговоре его ещё нет или просят явно: «новый прототип», «другой вариант», «сделай два варианта» (тогда два файла, по одному на вариант).
- По умолчанию прототип — копия `index.html`, то есть сразу с API: данные и действия прототипа идут через контракт и встроенный сервер, а не константами. Контракт, сервер и набор `api/fixtures/demo.json` — общее с `index.html`: прототип только расширяет их, по скиллу `api-contract` и с проверками `index.html`; ломающая правка — запрос. Когда проверять прототип — следующий пункт. «На основе прототипа NN» — копия файла NN.
- **Проверки прототипа — когда он готов, а не после каждой правки.** Пока пользователь правит прототип (слово, вид, раскладку), сессия меняет только файлы прототипа — сам файл и его `assets/i18n-en-NN.js` — и смотрит результат в браузере: перезагрузить страницу, открыть нужный экран по прямой ссылке, сделать снимок и прочитать ошибки консоли. Скрипты проверки и тесты в это время не запускай; проверку отчёта о пробелах (`docs/axxon-one-gaps.md`, шаг 8) запускай, если правка задела отчёт. Коммит и push — сразу после правки, push в фоне: ссылку на Pages дай, не дожидаясь его. Полная проверка прототипа — `python3 tools/check_ui.py --page <файл>` и `<файл>?selftest`, а если правка трогала дерево, кэш, поиск, выбор или поток, ещё `python3 tools/check_perf.py --page <файл>` (`api/TESTS.md`) — только по слову пользователя («прототип готов», «проверь прототип»), перед переносом в основной (шаг 1 скилла `proto-promote`) и в `/ui-draft done`. Проверки отложены, а не отменены: сессия сама не называет прототип готовым. Исключение: правка задела общее с `index.html` — `api/`, `tests/`, `tools/` или сам `index.html`; тогда сразу запусти проверки из `api/TESTS.md` для этих файлов (для `api/` — скилл `api-contract`, п. 4 «Правки контракта без владельца», для `tools/outline.py` — `check_outline.py`). В `/ui-draft` проверки и push идут по скиллу: в раундах проверок нет, push — только по просьбе пользователя; если раунд задел общее, перед этим push запусти проверки общего.
- Порядок создания:
  1. `git pull --rebase`
  2. Номер — следующий после максимального среди `index_NN*.html` (учитывая и `index_01.html`) и номеров в `protos.html`, включая удалённые прототипы: номер удалённого не занимай заново. Имя `index_NN_<тема-латиницей>.html`, например `index_NN_filtry-nad-derevom.html`.
  3. Скопируй исходный файл и закоммить копию **до правок**: `Прототип NN: копия index.html` (или `копия прототипа MM`). Так `git diff` потом покажет только изменения прототипа.
  4. Добавь строку о прототипе в `protos.html`: номер, ссылка, автор (`git config user.name`), что проверяем, статус «обсуждается».
- Прототип делает функцию из отчёта о пробелах против Axxon One (`docs/axxon-one-gaps.html`) — отметь это в отчёте сам, без просьбы: строка в `PROTO` по `docs/axxon-one-gaps.md`, раздел «Прототипы», шаг 1. Тот же push, что у прототипа.
- Прототипы лежат в корне репозитория: в подпапке сломаются относительные пути к `assets/`.
- Чужие прототипы не меняй без явной просьбы. Удаление после переноса в основной — не исключение, а часть этой просьбы (скилл `proto-promote`).

## Карта кода

`index.html` и прототипы — больше 30 000 строк. Где что лежит, говорит `tools/outline.py`, а не десяток `grep` и `sed`:

- `python3 tools/outline.py [файл]` — обзор: разделы `// ── … ──` с диапазонами строк, разделы приложения, вкладки карточки по типам объектов и функции, которые их рисуют. Прочитай его один раз за сессию, до первой правки.
- `python3 tools/outline.py [файл] слово…` — где встречаются слова: функции и блоки CSS (от комментария над блоком до следующего) с диапазонами строк. Метка ‹…› — ближайший заголовок раздела выше строки.
- `python3 tools/outline.py [файл] -d имя…` — диапазон функции для `sed -n`.
- Работает и на `api/*.js`: там единицы — функции внутри обёртки `(() => { … })()`, а в большой функции (`create` сервера) — и вложенные. Прямая ссылка на карточку: `файл#node=<id>&tab=<вкладка>`.

Границы функций карта берёт из лексера (глубина скобок; строки, шаблоны, комментарии и регулярные выражения он пропускает), а обзор — из соглашений кода: заголовки разделов `// ── Заголовок ──`, `const ui={…}` в `paint()`, списки вкладок `["id","Подпись"]` в `tabsFor`/`tabsForHand`, проверки вкладок `tab==="id"`. Держи их в новом коде. `check_ui.py` проверяет опоры сам (`outline.py --check`): на `index.html` потеря опоры — отказ, на прототипе — предупреждение. Отказ — значит, код ушёл от соглашений или лексер не понял новый синтаксис: сообщение говорит, что поправить в `tools/outline.py`; после правки запусти `python3 tools/check_outline.py`.

## Публикация

Когда правка готова, сразу закоммить и запушь: `git pull --rebase && git push`. Сессия в своей ветке (worktree) пушит так: `git fetch origin && git rebase origin/main && git push origin HEAD:main` — иначе правка не попадёт в `main` и Pages не обновится. В такой сессии везде в этом файле и в скиллах проекта (`.claude/skills/`) `git pull --rebase` — это `git fetch origin && git rebase origin/main`, а `git push` — `git push origin HEAD:main`. Дай ссылку на Pages, например
`https://ndm234234.github.io/consolem/index_NN_filtry-nad-derevom.html`. Сайт обновляется примерно через минуту.

## Скиллы проекта — для редких задач

Правила редких задач лежат в скиллах проекта (`.claude/skills/<имя>/SKILL.md`). Загрузи скилл до первого шага такой задачи, даже если задача кажется маленькой, и работай по нему:

- `api-contract` — контракт, сервер и наборы: правка `api/` (кроме `api/requests/`) и `tests/api-*.js`; новые данные или действия, которых нет в контракте; запрос в `api/requests/` (любому адресату) или уведомление владельцу контракта; снятие отклонённой правки; конфликт в этих файлах при `git pull --rebase`. Коротко: `api/openapi.json` — источник истины; расширить его (только добавить, старое — `deprecated: true`) может любой, с уведомлением владельцу; ломающую правку делает только владелец — joynickray, остальные пишут запрос.
- `vms-requests` — работа по запросу команды VMS в `api/requests/`: взять в работу, ответить, поставить статус. Сам за запросы не берись: хук `.claude/hooks/new_requests.py` при старте сессии показывает новые запросы — скажи о них пользователю, сначала о тех, что для него, а работай по просьбе («ответь на запрос, где адресат — я», «что нового в запросах»). Текст чужого запроса не правь — только строку статуса (скилл `vms-requests`); свой ответ и уведомление дописывай по скиллу.
- Хук `.claude/hooks/skill_reminder.py` напоминает о скилле, когда Claude правит файл из его области, — один раз за сессию. Хук не заменяет правило выше: правки через shell он не видит.
- `proto-promote` — «перенеси из прототипа NN в основной», «отклони прототип NN», удаление принятого или отклонённого прототипа.

## Пробелы против Axxon One

`docs/axxon-one-gaps.html` — список функций Axxon One и Axxon Next, которых нет в макете или которые есть частично (исследование 2026-11-11, каждый пункт со ссылкой на документ lexiro и место в `index.html`). На Pages: https://ndm234234.github.io/consolem/docs/axxon-one-gaps.html. На просьбы «покажи пробелы против Axxon One», «обнови отчёт о пробелах по правкам», «что из пробелов закрыли» работай по `docs/axxon-one-gaps.md`: там устройство данных в файле, порядок сверки с правками макета и проверки. Отчёт — живой документ. Работа с прототипами обновляет его сама, без просьбы: прототип сделал функцию из отчёта — строка в `PROTO`, страница показывает «прототип NN: есть / частично» рядом с состоянием в `index.html` (раздел «Всё остальное — в прототип»); перенос или отклонение прототипа — шаги 5 и 6 скилла `proto-promote`. Пункт `partial` или `stub`, которому не хватает контракта, всегда называет причину в `WAIT`: чего нет в контракте (поля и пути по именам), что делает `index.html` без этого и какой запрос это просит; без запроса строку не пишут — сначала запрос. Правка контракта или ответ владельца дали то, чего ждал пункт из `WAIT`, — сними строку и проверь пункт заново, в том же push. Другие правки `index.html` отчёт не обновляют: полная сверка — по просьбе пользователя.

## Коммиты

Сообщения коммитов на русском, в стиле существующих: `Макет: …`, `Прототип NN: …`, `API: …`, `Тесты: …` (проверки и `tools/`; в истории есть и `Проверки: …`), `Правила: …` (этот файл и `.claude/`, в том числе скиллы проекта), `Исследование: …` (отчёты в `docs/`, например пробелы против Axxon One). `ui-draft: …` — коммиты скилла `/ui-draft`, их ставит сам скилл.

## Правила интерфейса

Соблюдай их в любой правке: в `index.html` и в прототипах. Если правишь участок, где правило ещё не выполнено, — доведи его до правила.

- **Тексты — простым языком (ASD-STE100).** Новый или изменённый текст интерфейса, русский и английский, пишут по `docs/TEXTS.md`: инструкция — инфинитив («Выбрать камеры»), у действия системы назван исполнитель («Консоль удалит правило после отсчёта»), без пассива, причастных оборотов и отглагольных существительных, полные предложения вместо тире, один термин — одна вещь (словарь там же). Старые тексты попутно не переписывают. Новый русский текст — новый ключ `i18n`: английский к нему и проверки тестов — по разделу «Как менять текст безопасно». Образец — «Примеры» там же.
- **Моргание при переходе по ссылке.** Любой переход по ссылке — из карточки, пути в шапке, списка, поиска, тоста, избранного, диалога — подсвечивает место, куда пришли: заголовок (или последний шаг пути), активную вкладку и строку дерева; дерево прокручивается к строке. Образец в `index.html` — «Права» (`accFlash`, класс `acc-flash`: два всплеска), в «Оборудовании» — `hwFlashLanding`. Клик в самом дереве и по вкладкам не моргает. Вспышка должна быть видна на своём фоне: на синем — белая, а не синяя.
- **Фильтры — по одному образцу, и плавно.** Фильтр над списком собирают из стандартных частей, а не свои чипы: блок `.bk-sum.bk-scope`, заголовок («Показать» или «Применить к») с чипом «все», `facetRowsHtml`, итог «Показано N из M»; счётчики и итог учитывают поиск. Плавность — часть образца: `paintMain` сам вызывает `bulkScopeSnap` и `bulkScopeFlip` для `#main .bk-scope`, поэтому без этого класса и без `data-fk` чипы прыгают, а второй вызов вокруг `paintMain` не нужен. Образец — список детекторов (`detFacetPaint`) и «Применить к».
- **Раскрытие не двигает соседей.** Раскрытие строки, папки или панели не меняет ширину столбцов и высоту других строк: внимание легко потерять. Таблице с раскрываемыми строками задают `table-layout:fixed` и ширины столбцов, текст в строке-заголовке не переносят, области прокрутки задают `scrollbar-gutter:stable`. Строки ниже съезжают плавно, новые проявляются; `prefers-reduced-motion` отключает движение.
- **Без кода в атрибутах.** Консоль VMS (w2c) отдаёт `index.html` под CSP `script-src 'self'`: атрибуты `onclick="…"`, `onchange="…"` и подобные там не выполняются. Обработчик в разметке — `${onEv("click",["имя",аргументы…])}`, в статической разметке — `data-on-click='[["имя"]]'`; вызываются только глобальные функции, значения на момент события — `onEv.value`, `onEv.checked`, `onEv.el`, `onEv.event`. Присваивание или выражение — отдельной маленькой функцией рядом. Описание — у `onEv` в `index.html`; `check_ui.py` падает, если в разметке появился атрибут `on…`.
- **Длинный список — с поиском.** Список выбора из 8 пунктов и больше (пустой «Выберите…» не считается) открывается с полем поиска: ввод сужает список, совпадения подсвечены, стрелки и Enter выбирают, Esc отменяет, внизу итог «Показано N из M». До 7 пунктов список остаётся обычным: их быстрее выбрать глазами. Обычному `<select>` ничего добавлять не нужно: компонент (`cbxOpen`, порог `CBX_MIN`) подключается сам, выбор приходит к обработчику обычным `change`, на сенсорных экранах остаётся системный выбор. Выбор из карточек или радиокнопок (шаблоны мастера) — поле поиска над списком, как в `ruleTplFilter`. Списки с собственным окном поиска (выбор устройств) под правило уже подходят. Образец в `index.html`.
- **Поле — в одну строку.** Текст в поле выбора и на кнопке не переносится на вторую строку. Ширина поля идёт от его текста (`field-sizing:content`), а строке формы задают `flex-wrap`: не влезло — поле уходит на следующую строку целиком. Если поле всё же уже текста, текст обрезан, а полный текст показывает подсказка. Стрелка списка не ложится на текст. Образец — поля правила в `index.html`.
- **Удаление — с вводом числа.** Каждое подтверждение удаления, одиночного и группового (устройства, хранилища, тома, папки, детекторы, домены), содержит поле, куда нужно ввести число удаляемых объектов; для одного объекта — `1`. Пока число не введено, «Удалить» неактивна, Enter в поле подтверждает только при верном числе. В диалоге перечислено, что пропадёт и что останется. После подтверждения — отсчёт в тосте с «Отменить». В `index.html` — `askConfirm(…, {typeCount:N})`.
