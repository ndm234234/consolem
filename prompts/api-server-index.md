# Задача: перевести основной макет на API — по образцу прототипа 10

## Зачем это нужно

Прототип 10 (`index_10_api-server.html`) показал, как макет конфигуратора работает через API: контракт OpenAPI, встроенный тестовый сервер на эталонных данных, тесты и памятки для бэкенда и фронтенда. Но сделан он на основе прототипа 09 (`index_09_one-psim.html`), а согласованный вариант макета — `index.html`. Пока API-версия есть только у 09, команды получают задание по варианту, который не основной.

Нужен такой же рабочий прототип с встроенным сервером, но поверх `index.html`. Тогда бэкенд и фронтенд получат задание по согласованному макету, а прототип 10 останется образцом того, как это делается.

## Что уже есть и что из этого берётся

Ты работаешь в репозитории `consolem` (https://github.com/ndm234234/consolem, ветка `main`, Pages: https://ndm234234.github.io/consolem/). Почти всё, кроме слоя интерфейса, от макета не зависит и переиспользуется:

|---|---|---|
| Контракт OpenAPI 3.1 | `api/openapi.json` | Источник истины. Расширять только если в `index.html` есть то, чего нет в 09 (см. шаг 1) |

**Что делается заново** — слой интерфейса поверх `index.html`:
- кэш, который строится из ответов API;
- перевод ответов API в структуры, по которым рисует макет;
- замена каждого места, где макет меняет данные напрямую, на запрос;
- запуск страницы через `window.appReady`.

В прототипе 10 этот слой уже сделан для 09 — это и есть образец.

## Шаг 1. Сравни `index.html` с прототипом 09 — стоп, отчёт

Прототип 09 когда-то сделан из `index.html` («логика как в index.html», визуальное семейство ONE PSIM). С тех пор оба могли измениться. Выясни, что отличается, и разложи по трём видам:

1. **Только вид** — разметка, классы, стили, иконки, контролы дизайн-системы. Слой API это не задевает; разница лишь в том, куда вставлять код.
2. **Логика интерфейса** — функции, которых нет в 09 или которые устроены иначе: новые экраны, кнопки, диалоги, групповые действия, места, где меняются данные. Каждое такое место нужно перевести на API заново, а если операции для него в контракте нет — сначала добавить её в контракт.
3. **Данные** — константы-наборы: серверы, домены, устройства, хранилища, правила, права, опции, журнал, поиск в сети. Если они отличаются, эталонный набор `api/fixtures/demo.json` не совпадёт с тем, что показывает `index.html`.

Как сравнивать:

Правила, которые нарушать нельзя (они проверяются):
