# Сравнение двух прототипов «Конфигуратора»

- **A — прототип из этого репозитория** (`index.html`, коммит `d5c840b`).
- **B — демо** https://agkitv.github.io/nvr-configurator-demo/ (состояние на 15.10.2026).

Оба выросли из одного исходника (`index_before_changes.html`): общий каркас «рельс разделов → дерево → карточка объекта → подвал Сохранить/Отменить», общий словарь и демо-данные. Поэтому сравнение не «старый против нового», а **две альтернативные ветки редизайна одного продукта**. Там, где формат просит «что улучшено / что ухудшено», B рассматривается как альтернатива A.

## Как проверялось

Оба прототипа открыты в Chrome и пройдены одинаковыми сценариями:

| Сценарий | Что смотрели |
|---|---|
| Первый экран, 1600×1000 | плотность, иерархия, число элементов управления |
| Глобальный поиск: одинаковые запросы разных типов | охват, подача результатов, связь с деревом |
| Фильтр дерева по типу «Микрофон» | можно ли вывести только один тип устройств |
| Поля поиска в каждом разделе | сколько их, как ведут себя одинаковые запросы |
| Поиск настройки внутри карточки камеры | находит ли поле на другой вкладке, переходит ли к нему |
| Длинные списки: сервер на 328 устройств, архив на 286 камер | постраничный показ, поиск, фильтры |
| Стрелки клавиатуры в дереве | можно ли идти по дереву без мыши |
| Сверка с общим исходником и историей коммитов | какие преимущества A были в исходнике и сохранились ли они в B |
| Карточка сервера и домена | состав, главное действие |
| Меню «⋯» строки дерева и правый клик | состав, опасные действия |
| Правка имени → уход на другой объект | защита от потери данных |
| Вкладка «Серверы» домена | работа с длинными списками |
| Добавление устройства: найденные и вручную | число шагов, проверки |
| Ширина 1024 и 390 px | адаптивность |
| Автоматический замер | контраст текста, размеры шрифтов и кликабельных зон |

Где поведение было неочевидным, проверялся исходный код. Ограничения: реальных пользователей не было, время выполнения задач не замерялось, клики посчитаны по сценарию. Оценки — экспертные.

**Что оценивается.** Насколько прототип закрывает задачи конфигурирования: найти объект, настроить его, работать с сотнями и тысячами элементов, не ошибиться. Чисто интерфейсная шлифовка — перетаскивание, анимации панелей, навигационные надстройки вроде истории «Назад/Вперёд» — в оценку не входит. Её разумно делать на последнем этапе, когда прототип полностью закрывает потребности конфигурирования.

Начальное состояние демо-данных в оценку тоже не входит. Например, в A на старте заранее раскрыты сервер и архив, а в B — нет. Это одна строка данных, а не решение дизайна.

### Принятые допущения о контексте

Масштаб подтверждён заказчиком, остальное — допущения. Если они неверны, оценки по критериям 1, 2 и 5 сдвинутся.

- **Пользователи** — инженеры-интеграторы и администраторы систем видеонаблюдения, 25–50 лет, технически грамотные.
- **Масштаб** — тысячи камер на домен. Поэтому навигация по большому числу элементов — ключевой критерий.
- **Частота** — интенсивно при пусконаладке, затем эпизодически при изменениях.
- **Основные задачи** — найти объект, добавить и привязать устройства, настроить архивы и правила, проверить состояние.
- **Платформа** — десктопный веб; планшет и телефон вторичны.

## 2. Сильные и слабые стороны

### A — прототип из репозитория

**Сильные стороны**
- **Видимость системы.** Подписанный рельс, все способы добавления на виду, пояснения в карточках. Новичок не ищет функции.
- **Единый поиск.** Одно поле на все 5 разделов. Оно фильтрует и дерево оборудования, и списки правил, ролей, журнала, а заодно показывает, что найдено за пределами текущего раздела. Находит правила, роли, учётные записи, страницы опций, понимает неверную раскладку клавиатуры.
- **Навигация по большому числу элементов.** В каждом списке карточки есть поиск и страницы 10–200, номер страницы помнится по объекту, счётчик склоняет единицы («из 12 серверов»). По дереву можно идти стрелками. IP копируется в один клик. Это главное преимущество A.
- **Полный набор действий.** Меню ⋯ домена и сервера содержит всё, что заводит их карточка.
- **Добавление найденных в контексте.** Список открывается во вкладке «Устройства» с фильтрами «Здесь / Свободные / В другом месте / Нет в системе».
- **Сетка и выравнивание.** Отступы кратны 8, колонки дерева держат ровный правый край.
- **Состояние сохранения читается.** Приглушённая кнопка, текст в подвале, красное «Удалить домен».
- **Телефон.** На узком экране остаётся одна панель, а не две сжатые.

**Слабые стороны**
- **Тройное дублирование действий.** «＋ Сервер», «＋ Сетевой архив» и три способа добавить устройства есть в шапке, в карточке «Действия» и в меню ⋯ домена. Сами функции нужны, лишние копии — нет.
- **Все кнопки шапки одного веса.** Глазу не за что зацепиться.
- **Нет поиска по полям карточки.** Запросы «разрешение», «кодек», «предзапись» ничего не находят: поиск знает вкладки, но не поля. А поскольку то же поле фильтрует дерево, такой запрос оставляет дерево пустым.
- **Фильтр по типу не работает в группировке «По серверам».** Подробности в разделе 7.
- **Мелкие кнопки строки.** ☆ и ⋯ появляются только на выбранной или наведённой строке, а сами цели 16×12 px (закон Фиттса). На сенсорном экране навести нельзя.
- **Ширина 1024 px.** Ширина дерева не адаптируется, имена режутся до двух букв.

### B — демо

**Сильные стороны**
- **Поиск настройки в карточке объекта.** Ctrl+F закрепляет поле поиска за открытым объектом. Запрос «разреш» находит поле «Разрешение» на вкладке «Видео», а Enter переключает вкладку и выделяет поле. Это главная реальная польза B.
- **Таблица камер сервера.** Фильтр в каждой колонке и выгрузка в CSV.
- **Тихая шапка карточки.** Одна кнопка, ясная фокусная точка.
- **Поиск по детекторам и настройкам опций.** Находит детекторы и отдельные настройки вроде «Лицензии камер».
- **Сквозной список детекторов.** В разделе «Детекторы» видны детекторы всех камер.
- **Таблица камер в карточке архива.** Колонки «Камера / Сервер / Режим» читаются быстрее карточек.
- **Стили фокуса с клавиатуры.** Их в 3 раза больше, чем в A.

**Слабые стороны**
- **Урезанный набор действий.** В меню домена только «Добавить сервер»: папку, сетевой архив и устройства с уровня домена не добавить, домен не удалить.
- **Иконки без подписей.** 7 значков, смысл узнаётся только наведением. Плохо для новичков и эпизодических пользователей.
- **Восемь полей поиска.** Общее поле в шапке и своё поле в каждом из 7 разделов. Одинаковый запрос в них ведёт себя по-разному. Подробности в разделе 7.
- **Ложная активность «Сохранить».** Кнопка неактивна, но выглядит активной.
- **Опасное действие не выделено.** «Удалить все устройства» соседствует с «Переименовать».
- **Слабая навигация по большому числу элементов.** Постраничный показ есть только в каталоге состава логической группы. Архив на 286 камер выводится одним списком без поиска, раскрытый сервер — одним длинным столбцом. Стрелки клавиатуры в дереве не работают.
- **Телефон.** Вёрстка ломается, появляется горизонтальная прокрутка.
- **Мелкие огрехи.** Кнопки внизу автоматизации выходят за край панели. Нагрузка сервера в шапке окна меняется при смене выбора, и неочевидно, к чему она относится.

## 4. Итоговый вывод

**A лучше: 46 против 40.** Главное преимущество A — быстрая и удобная навигация по большому числу элементов, в B её нет. Главная реальная польза B — поиск настройки внутри карточки объекта, в A его нет. Большая часть преимуществ A была в общем исходнике, но в B не сохранилась: B ответвился от исходника, часть его возможностей убрал, а улучшения A перенёс лишь фрагментами. Подробности в разделе 8. Остальные решения B, которые на первый взгляд выглядят преимуществами, при проверке в основном не подтверждаются. Подробный разбор — в разделе 7.

- **Тихая шапка** B получена во многом отсутствием функций. У A есть реальная проблема, но другая: тройное дублирование действий.
- **Охват поиска** у A не уже, а по большинству запросов шире.
- **Своё поле поиска в каждом разделе** не даёт новой возможности: в A то же делает одно поле, а вывести только один тип устройств можно фильтром.
- **Поток добавления устройств** у прототипов общий, включая проверку конфликта IP. В A ручное добавление на клик короче.
- **Отдельные разделы** «Архивы» и «Детекторы» дают второй путь к тем же объектам, а не новую возможность.

**Что стоит взять из B.** В первую очередь поиск настройки в карточке объекта. Дальше по необходимости: фильтры по колонкам и CSV в таблицах устройств, поиск по детекторам и настройкам опций, сквозной список детекторов, стили фокуса с клавиатуры.

**A лучше в трёх сценариях:**
- **Первое знакомство и редкое использование.** Подписи и видимые действия снижают порог входа.
- **Работа с сотнями и тысячами элементов.** Страницы, поиск в каждом списке, стрелки в дереве и копирование IP есть только в A.
- **Узкий экран.** A остаётся рабочим, B ломается.

Ни один вариант не готов как финальный. За основу стоит взять A: добавить поиск настройки в карточке, убрать дублирование действий и починить фильтр по типу.

## 5. Рекомендации по доработке

1. **Добавить в A поиск настройки в карточке объекта — в то же единое поле.** Отдельный режим не нужен. Когда запрос совпадает с подписями полей открытой карточки, в выдаче появляется группа «В карточке» рядом с «В дереве» и «Не в дереве». Выбор результата переключает вкладку и выделяет поле, как в B. Дерево при этом не должно оставаться пустым без объяснения. Стоит сразу добавить синонимы подписей: «fps» для «к/с», «битрейт» для «скорость потока».
2. **Убрать дублирование действий, не убирая сами действия.** Полный набор остаётся в меню ⋯. В шапке — частые задачи: три способа добавить устройства и «＋ Добавить сервер». Из карточки «Действия» убрать всё, что повторяет шапку, оставить уникальное: «Добавить серверы по IP», «＋ Папка», «＋ Домен», «Удалить домен».
3. **Рельс и разделы оставить как в A.** Пять подписанных разделов, детекторы и архивы — внутри своих объектов. Если нужен обзор всех детекторов, лучше дать его фильтром по типу в дереве, а не отдельным разделом.
4. **Защита от потери данных и опасных действий.**
   - При уходе с изменённой карточки спрашивать «Сохранить / Не сохранять / Остаться» или хранить черновик по объекту.
   - Неактивное «Сохранить» всегда приглушать.
   - Разрушительные пункты меню отделять, красить и подтверждать с числом затрагиваемых объектов; после выполнения показывать уведомление с отменой.
5. **Доступность до минимума WCAG 2.2.**
   - Кликабельные зоны ☆ и ⋯ не меньше 24×24 px. Они появляются только при наведении, поэтому для сенсорного экрана нужен другой способ, например долгое нажатие.
   - IP-метки не мельче 11 px.
   - Контраст «Сохранить» не ниже 4.5:1: темнее синий или тёмный текст.
   - Дерево с минимальной шириной и переходом в однопанельный режим ниже ~1100 px.
6. **Единый поиск оставить и доработать.**
   - Починить фильтр по типу в группировке «По серверам» и скрывать пустые папки при активном фильтре.
   - В выдаче сворачивать учётные записи под строкой роли: сейчас по запросу «охрана» 14 записей вытесняют правило вниз.
   - Фильтры по колонкам и выгрузку CSV в таблицах устройств взять из B.
   - Детекторы и отдельные настройки опций добавлять в выдачу, только если они нужны пользователям, и группировать по типу. Иначе одинаковые «Детекторы движения» сотен камер забьют выдачу.
7. **Шлифовку отложить на последний этап.** Перетаскивание, анимации панелей, история переходов и подобные надстройки делать после того, как прототип закроет все задачи конфигурирования.

## 6. Резюме от лица продакт-менеджера

Для бизнеса важнее всего **скорость пусконаладки и отсутствие ошибок конфигурации.** Ошибка в настройке видеонаблюдения — это пропущенная запись, выезд инженера и претензия заказчика. Поэтому приоритеты такие:

1. **Устойчивость к ошибкам** — прямые затраты на поддержку. Здесь оба варианта недотягивают, и это первое, что надо закрыть.
2. **Эффективность на больших объектах** — выручка идёт от крупных инсталляций. Здесь решают навигация по большому числу элементов, где сильнее A, и быстрый доступ к нужной настройке, где сильнее B.
3. **Обучаемость** — влияет на стоимость внедрения у партнёров и нагрузку на обучение. Здесь выигрывает A.

Рекомендация: брать за основу A, добавить в него поиск настройки в карточке из B, убрать дублирование действий и починить фильтр по типу. До пилота закрыть рекомендации 4 и 5. Перетаскивание, анимации и прочую шлифовку отложить на последний этап. Для проверки провести юзабилити-тест на 5–6 интеграторах с тремя задачами: найти камеру по части имени, добавить 10 устройств на сервер, создать правило. Метрики: время выполнения, число ошибок, доля успешных выполнений без подсказки.

## 7. Разбор ключевых решений по пунктам

### 7.1. Своё поле поиска в каждом разделе

**Обоснование автора B.** Глобальный поиск не поможет, если нужно вывести только микрофоны, а фильтры отдельно от строки поиска — неочевидный ход. Поэтому в B общее поле в шапке и своё поле в левой панели каждого раздела.

**Сколько полей поиска на экране.**

| Раздел | A | B |
|---|---|---|
| Оборудование | 1 — в шапке | 2 — «Поиск по системе…» и «Фильтр по имени, IP, ID…» |
| Архивы | раздела нет, архивы в «Оборудовании» | 2 — «Поиск по системе…» и «Поиск…» |
| Детекторы | раздела нет, детекторы в карточке камеры | 2 |
| Автоматизация | 1 — то же поле в шапке | 2 |
| Права / Пользователи | 1 — то же поле в шапке | 2 |
| Опции | 1 — то же поле в шапке | 2 |
| Журнал | 1 — то же поле в шапке | 2 |
| **Всего разных полей** | **1** | **8** |

**Одинаковый запрос «сирена» в разделе «Автоматизация».**

| Куда ввести | A | B |
|---|---|---|
| Поле в шапке | список правил сужается до «Сирена по двери» с подсветкой | список правил не меняется, открывается выпадающий список переходов |
| Поле раздела | — | список сужается до «Сирена по двери» |
| То же в английской раскладке, «cbhtyf» | находит | поле раздела ничего не находит |

Пользователь B должен в каждом разделе заново решать, в какое из двух полей печатать, а результат зависит от выбора. Подписи полей тоже разные: «Фильтр по имени, IP, ID…» в «Оборудовании» и «Поиск…» в остальных разделах.

**Проверка сценария с микрофонами.** Он закрыт в A одним полем, двумя способами.
- **Запрос «микрофон» в едином поиске.** Дерево сразу фильтруется, выдача показывает «В дереве: 3» и сами микрофоны с путём. Глобальный поиск работает.
- **Фильтр по типу.** Кнопка воронки стоит в той же колонке прямо под полем поиска и называется «Фильтры поиска». Первая секция её панели — «Искать в», то есть это настройки той же строки поиска, а не отдельный инструмент. В секции «Фильтр по типу» есть «Микрофон» со счётчиком 3, количество видно до выбора.

**Одно поле на всё — устоявшийся образец.** Адресная строка Chrome одним полем ищет по истории, закладкам, открытым вкладкам и в интернете. Пользователь не решает заранее, где искать: выдача сама показывает, откуда каждый результат. Так же устроены Ctrl+P в VS Code и Spotlight в macOS. В A та же модель: одно поле, а выдача делится на «В дереве» и «Не в дереве».

Поля разделов в B новой возможности не дают: только микрофоны там выводит тот же фильтр по типу, а списки разделов в A фильтрует общее поле. Цена — восемь полей вместо одного, неясность, куда печатать, и два разных результата по одному запросу. Переключатель «Показать списком» в B тоже не нужен: в A эту роль выполняет выдача единого поля, где найденное идёт плоским списком с типом и путём.

**Дефект A, который ломает этот сценарий на экране по умолчанию.**

| Группировка дерева | Что видно после выбора типа «Микрофон» |
|---|---|
| «По серверам», по умолчанию | подсказка «Найдено: 3», но в дереве 240 строк: камеры, микрофонов нет |
| «По папкам» | три микрофона, но вместе с ними остаются пустые папки, всего 79 строк |

Причина: в группировке «По серверам» ветка «архив → камеры» отбирает объекты только по текстовому запросу. Фильтры по типу и статусу там не применяются. Это функции построения строк архива, регистратора и камеры в `index.html`, около строк 4193–4280. Возможно, именно этот сбой автор B принял за ограничение подхода с одним полем.

**Вывод.** Одного поля на все разделы с фильтрами под ним достаточно. Нужно починить фильтр в группировке «По серверам» и скрывать пустые папки.

### 7.2. Тихая шапка карточки

**Что видно.** В шапке домена A — 5 кнопок «＋…», плюс ☆ и ⛶, ниже карточка «Действия» ещё с 6 кнопками. В B — одна кнопка «＋ Добавить сервер».

**Проверка.**
- **В B тишина получена отсутствием функций.** В меню ⋯ домена B есть только «Добавить сервер», переименование, избранное и вкладки. Создать папку, сетевой архив, добавить устройства или удалить домен с уровня домена нельзя.
- **В A функций больше, и они нужны.** Меню ⋯ домена A содержит всё, что заводит карточка: три способа добавить устройства, сервер, серверы по IP, папку, сетевой архив, удаление и создание домена.
- **Проблема A — не количество, а повторы.** «＋ Сервер», «＋ Сетевой архив» и способы добавления устройств есть одновременно в шапке, в карточке «Действия» и в меню ⋯.

**Вывод.** Копировать шапку B не нужно. Нужно убрать повторы в A, сохранив набор функций.

### 7.3. Охват глобального поиска

Одинаковые запросы в обоих прототипах:

| Запрос | A | B |
|---|---|---|
| «охрана» | роль, 14 учётных записей, правило «Охрана входа ночью», объекты в дереве | роль, правило |
| «оператор» | роль и 12 учётных записей | роль |
| «ночью» | правило | правило |
| «лиценз» | страница опций и вкладка «Лицензии» домена | страница опций и две настройки: «Лицензии камер», «Лицензии ACFA» |

- **A по большинству запросов шире.** Он находит учётные записи, а не только роли, учитывает неверную раскладку и сразу фильтрует дерево.
- **B шире в двух местах.** Он находит детекторы и отдельные настройки и предлагает поиск внутри карточки по Ctrl+F.
- **Минус выдачи A.** По запросу «охрана» 14 учётных записей идут списком и вытесняют правило вниз.

### 7.4. Поток добавления устройств

**Что видно.** В B одна кнопка «＋ Добавить устройство» открывает окно: сначала найденные в сети, внизу «Добавить вручную» и «Добавить из файла». При совпадении IP и порта с другим MAC появляется предупреждение.

**Проверка.**
- **Компонент у прототипов общий.** Строка устройства, поля и текст предупреждения о конфликте IP в коде A и B совпадают.
- **В A «Найденные» открываются прямо во вкладке «Устройства».** Есть фильтры «Все / Здесь / Свободные / В другом месте / Нет в системе» и общие для всех строк архив и режим записи. Карточку не закрывает окно.
- **Ручное добавление в A на клик короче.** В A — одна кнопка «＋ Вручную». В B — кнопка, затем «Добавить вручную» внизу окна.

**Вывод.** Преимуществом B это не является.

### 7.5. Отдельные разделы «Архивы» и «Детекторы»

**Что видно.** В рельсе B 7 разделов: к «Оборудованию» добавлены «Архивы» и «Детекторы». В A 5 разделов: архивы живут в дереве под сервером и списком в карточке домена, детекторы — во вкладке карточки камеры.

**Проверка.**
- **Это второй путь к тем же объектам.** Детектор в B открывается и через камеру, и через раздел «Детекторы» с деревом «сервер → камера → детектор». Чтобы создать детектор там, всё равно надо выбрать камеру.
- **Больше пунктов в рельсе без подписей.** По закону Хика выбор раздела дольше, а различить иконки «Архивы» и «Детекторы» без наведения трудно.
- **Реальная польза одна — сквозной список детекторов.** Например, найти все «Оставленные предметы» на объекте. Эту задачу закрыл бы фильтр по типу в дереве A, если включить туда детекторы.

**Вывод.** Отдельные разделы скорее минус. Взять стоит только идею сквозного списка детекторов — через фильтр, а не через раздел.

### 7.6. Поиск настройки в карточке объекта — подтверждается

**Как работает в B.** На открытой карточке Ctrl+F или пункт меню «Найти в карточке объекта…» закрепляет общее поле поиска за объектом: в поле появляется метка с его именем. Выдача состоит из полей карточки с указанием вкладки.

| «запис» | «Предзапись, с», вкладка «Архив» | ничего |
| «fps» | ничего: поле подписано «к/с» | ничего |
| «pfgbc», то есть «запис» в английской раскладке | ничего | ничего |

**Вывод.** Это реальная польза B: в карточке с несколькими вкладками нужное поле находится без перебора вкладок. В A такого нет: поиск знает вкладки, но не поля. Слабые места B — поиск только по точной подписи, без синонимов и без учёта раскладки. Переносить в A стоит в единое поле, отдельной группой выдачи. Это рекомендация 1.

## 8. Преемственность: сохранились ли в B преимущества A

**Как проверялось.** Код B сравнивался построчно с общим исходником и с каждой версией A из истории коммитов. С общим исходником у B совпадает больше строк, чем с любой версией A, поэтому B ответвился именно от исходника. Из поздних изменений A в B перенесены отдельные фрагменты: код постраничного переключателя, скрытие рельса разделов, панель избранного, синхронизация поля поиска. Наличие каждой возможности проверено в коде и в браузере.

**Итог: преемственности нет.** Из 15 преимуществ A в B полностью не сохранилось ни одно. Девять были в общем исходнике и в B утрачены. Ещё шесть добавлены в A после разделения, и в B их нет или они перенесены частично.

### Было в общем исходнике, в B утрачено

| Преимущество A | В исходнике | В B |
|---|---|---|
| Подписи разделов в рельсе | есть | убраны, остались иконки |
| Одна панель на узком экране | есть | утрачено: обе панели сжимаются, горизонтальная прокрутка |
| Учёт неверной раскладки в поиске | есть | убран |
| Стрелки клавиатуры в дереве | есть | убраны |
| Поясняющие строки о модели данных в карточках, например «Сервер появляется у камеры только через архив» | есть | убраны |
| Добавление найденных во вкладке «Устройства» со статусами «Здесь / Свободные / В другом месте / Нет в системе» и кнопкой «Писать сюда» | есть | заменено окном со списком найденных, статусов размещения нет |
| Подсказка «Сохраняется только выбранный объект» | есть | убрана |
| Выделение опасных действий красным, например «Удалить домен» | есть | убрано: «Удалить все устройства» стоит среди обычных пунктов |
| Действия домена: добавление устройств, папки, сетевого архива, удаление домена | есть | убраны, у домена остался «Добавить сервер» |

### Добавлено в A после разделения, в B не перенесено

| Преимущество A | В B |
|---|---|
| Одно поле поиска на всё окно с делением «В дереве / Не в дереве» | нет: два поля исходника сохранены, и добавлено своё поле в каждый раздел |
| Постраничный показ во всех списках | частично: код переключателя перенесён, но применён только в каталоге состава логической группы |
| Поиск в каждом списке карточки | нет |
| Копирование IP в один клик | нет |
| Приглушённая неактивная «Сохранить» | нет: в исходнике кнопка не приглушалась, в B так и осталось |
| Полное меню ⋯ домена и сервера | нет |

**Что это значит.** B — не развитие A, а параллельная ветка от более старой точки, которая по пути потеряла заметную часть уже сделанного. Преимущества A в B не унаследованы и не перенесены. Обратное тоже верно: поиск настройки в карточке, фильтры по колонкам и выгрузка CSV есть только в B. Поэтому сливать ветки выгоднее в A: переносить в A три находки B проще, чем возвращать в B пятнадцать возможностей A.

## Вопросы, которые уточнят оценку

- **Кто основной пользователь:** штатный администратор объекта или выездной интегратор партнёра? От этого зависит вес обучаемости против скорости.
- **Нужен ли планшет или телефон** для работы на объекте? Если да, вёрстка B требует переделки, а в A — крупные кнопки строк.
- **Нужен ли поиск по детекторам и отдельным настройкам?** Если да, их стоит добавить в единый поиск A с группировкой по типу.
