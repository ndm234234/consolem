# Групповые операции в разделе «Оборудование»: идеи

Статус: черновик для обсуждения, ничего в макете не менялось. Цель — дополнить раздел
«Оборудование» групповыми операциями, не ломая его нынешнюю структуру: рельс разделов →
срезы и фильтры над деревом → дерево → карточка объекта справа с вкладками.

Источники: практики корпоративных VMS и других enterprise-консолей (раздел 2),
спецификация и код `web-configurator-next` (раздел 3), прототип `BMS/prototypes/sip-setup`
(раздел 4), текущий `index.html` (раздел 1).

## 2. Практики VMS и enterprise-консолей

Подробный разбор с источниками — `web-configurator-next/spec/research-market.md`
(фаза 2) и отчёт по внешним источникам в разделе 7. Здесь — только то, что переносится.

Метки: `[ДОК]` — подтверждено страницей документации (ссылка в разделе 7);
`[ВЫЖИМКА]` — по выдаче поиска, страницу целиком не читали; без метки — общее знание о продукте.

### 2.1. Axxon One сегодня (толстый клиент)

`[ДОК]` Массовое применение настроек уже есть, и модель у него «от одной камеры»:
настраиваешь одну камеру → кнопка выбора камер → список **только той же модели и
прошивки** → отметить галочками (Shift — диапазон) → «Применить»; число камер показано
в скобках. Для детекторов то же самое для детекторов одного типа, но зоны детекции и
игнорирования массово не меняются. Это важно для consolem: пользователи Axxon One
привыкли к пути «настроил одну — применил к похожим», а не к «выбрал много — правлю
форму выборки». Оба пути стоит оставить (см. 5.2 и 5.6).

### 2.2. Другие VMS

- **Milestone XProtect Management Client.** `[ДОК]` Группы устройств: только один тип
  устройств в группе, рекомендация до 400 устройств «чтобы видеть и править все
  свойства»; общие свойства задаются на группу «за один раз», но хранятся на каждом
  устройстве; устройство может быть в нескольких группах; удаление группы не удаляет
  устройства. `[ДОК]` Мастер «Change Hardware Password»: единый пароль или
  автогенерация своего на каждое устройство; страница результатов по каждому
  устройству, у неудачных — «Failed» с причиной от устройства, «Print report»,
  «Retry» перезапускает мастер только с неудачными. `[ВЫЖИМКА]` Смешанные значения в
  форме группы документация не описывает; сторонние надстройки (Boring Toolbox) живут
  именно на правке «разнородного железа».
- **Genetec Security Center.** `[ДОК, только введение]` *Copy configuration tool*
  «упрощает настройку многих похожих сущностей»: настройки одной сущности копируются в
  другие того же типа; какие именно группы настроек — на отдельной странице, не прочитана.
  Unit enrollment: обнаружение, «добавить все новые», учётные данные заранее.
- **Axis Device Manager.** `[ДОК]` Мультивыбор в списке устройств + контекстное меню:
  обновить прошивку (параллельно или последовательно, флаг «отменить остальные, если
  одно упало», подтверждение «устройства станут недоступны»), ввести учётные данные
  (одни на всю выборку или CSV с парами по MAC/IP), «Set configuration», настройка SIP
  с выбором на каждое поле **«оставить значение устройства» или «задать одно всем»**,
  сертификаты, точки восстановления. Мастера заканчиваются экраном «Review» со списком
  устройств; результаты и ошибки — в панели Tasks. Групп и тегов на этой странице нет
  (они в Device Manager Extend `[ВЫЖИМКА]`).
- **Nx Witness.** `[ВЫЖИМКА]` В справке есть раздел «Setting Same Parameters for
  Multiple Cameras»: выделить несколько камер → Camera Settings → общие вкладки; одни
  учётные данные ставятся на несколько камер сразу. Страница про показ смешанных
  значений не открылась.
- **Eocortex.** `[ДОК]` Два режима группового выбора в дереве: без галочек (Ctrl/Shift,
  Ctrl+A, Shift+стрелки) и с галочками (F4 или «Показать чекбоксы»; галочка на папке =
  всё содержимое); выделение сохраняется при переключении режима и сворачивании папок.
  Действия над выборкой: переместить в папку (Ctrl+M), включить/выключить (Ctrl+Q),
  удалить, копировать/вырезать/вставить. «Создать группу камер» из одной: до 999 копий
  с настройками источника и инкрементом IP. Экспорт/импорт конфигурации камер файлом,
  таблица камер с выгрузкой в CSV/Excel.
- **Verkada Command.** `[ДОК, research-market]` Правка массовая только для однородной
  выборки (один тип устройств; при смешанном выборе кнопка скрыта); удаление — ввод
  кода подтверждения.
- **HikCentral.** `[ДОК, research-market]` Пакетный импорт из Excel, добавление найденных
  с общими учётными данными, пакетная смена пароля после добавления. Отдельный Batch
  Configuration Tool снимается с поддержки в 2026 — массовые операции уходят в основной
  продукт `[ВЫЖИМКА]`.

### 2.3. Другие enterprise-консоли и дизайн-системы

- **Carbon (IBM).** `[ДОК]` Панель пакетных действий появляется над таблицей при выборе
  первой строки, высота = высоте строки, «Cancel» справа; в режиме пакетных действий
  строчные действия и меню строк отключаются; чекбокс заголовка — тристейт.
- **PatternFly (Red Hat).** `[ДОК]` «Bulk selector» первым элементом тулбара: «Select
  none / Select page / Select all» плюс необязательные пункты по условию («все с
  ошибкой»); счётчик считает выбранное по всем страницам; выбор **сохраняется после
  выполнения действия**, пока пользователь сам его не изменит.
- **Cloudscape (AWS).** `[ДОК, research-market]` Групповые действия — в заголовке таблицы,
  подтверждение с числом выбранных, отдельные строки не блокировать.
- **Material.** `[ВЫЖИМКА]` Верхняя панель превращается в contextual action bar: цвет
  меняется, слева «закрыть», заголовок — число выбранных, действия — только над
  выборкой; закрывается после действия или вручную.
- **Jira, bulk change.** `[ДОК]` Поиск → Tools → Bulk change → выбор операции (edit,
  move, transition, delete…) → поля → страница подтверждения → Confirm; лимит 1000
  объектов; переходы — только группами с одинаковым workflow.
- **Intune.** `[ВЫЖИМКА]` «Bulk device actions»: мастер Basics (ОС, действие) → Devices
  (до 100) → Review + create; набор действий ограничен (restart, sync, rename, delete…).
- **UniFi.** `[ВЫЖИМКА]` Radio Manager: фильтр по устройствам и диапазону → Bulk Edit
  радионастроек на нескольких точках; заменил «Global AP Settings».
- **Meraki.** `[ДОК, research-market]` Шаблоны с живой связью «правка шаблона → все
  сети»; спецификация configurator-next от этого отказалась.

### 2.4. Сквозные паттерны, которые берём

1. Выбор видим: галочки, счётчик, «выбрать все по фильтру (N)», выбор переживает поиск и страницы и сохраняется после действия (PatternFly).
2. Действия над выбранным — в одном месте, появляются при выборе, недоступные — серые с причиной; строчные действия в этот момент отключены (Carbon).
3. Правка нескольких объектов — те же вкладки и поля, что у одного; «— не менять —» по умолчанию, «— разные —» при расхождении (Axis: «оставить значение устройства / задать одно всем»).
4. Однородность: общие поля — для любых устройств среза, поля драйвера/видео — для одной модели (Axxon One: модель и прошивка; Milestone: один тип в группе; Verkada).
5. Предпросмотр: сколько объектов и какие поля изменятся — до записи (Jira, Axis «Review», configurator-next «план»).
6. Выполнение как очередь: прогресс, пауза, отчёт по каждому объекту, «повторить неудачные» (Milestone «Retry» только с неудачными, «Print report»).
7. Опасное — с подтверждением, пропорциональным масштабу (число → ввод числа), обратимое — с «Отменить».
8. Два пути к одному результату: «применить к похожим» от одной камеры (Axxon One, Genetec, Eocortex) и форма выборки (Milestone, Nx, configurator-next).

## 3. Что сделано в web-configurator-next

Спецификация `spec/screens.md` (S0.4, S1.4, S1.5, S2.8), `spec/requirements.md`
(REQ-BULK-01…07, REQ-DEV-21), код `app/src/widgets/bulk-edit`, `app/src/widgets/device-table`.

- **Таблица устройств (S0.4).** Чекбоксы, Shift-диапазон, «Выбрать все по фильтру (412)»
  с предупреждением «Действие применится ко всем». Панель над таблицей: «Выбрано: N ·
  Изменить выбранные · В группу… · Включить · Выключить · Удалить… · Снять выбор».
  Чекбоксы недоступного сервера заблокированы. Ctrl+A — выбрать загруженные, Delete —
  «Удалить…» с подтверждением.
- **Массовая правка (S2.8, реализовано).** Только однородная выборка: общие свойства
  (имя-правило, группа, архив, режим записи) — любым камерам; свойства драйвера и потоков —
  одной модели. При двух моделях: «Выбрано 2 модели. Поля драйвера доступны, если выбрать
  камеры одной модели. Показать общие поля?». Каждое поле «— не менять —»; при разных
  значениях «— разные —» и диапазон «(5…25)»; проверка по пересечению допустимых
  диапазонов и списков; пароль «задан / заменить»; Del в поле возвращает «— не менять —».
  Камеры недоступного сервера и без полного доступа исключены и названы.
- **План и очередь (S1.4).** Любое «Применить» сначала показывает план: шаги, пачки по 10,
  сервер, побочные эффекты, время. Один шаг без побочных эффектов — свёрнутая строка прямо
  в карточке («Изменится: 2 камеры добавятся в группу „Склад“ · Применить»). Очередь:
  «Применяется 12 из 34», пауза, отмена оставшегося, объекты в очереди помечены
  «изменяется».
- **Отчёт по объектам (S1.5).** Строка на объект: применено / не применено (причина) /
  сервер изменил значение; «Повторить неудачные (N)», «Сохранить отчёт (CSV)»,
  «Открыть камеры» (таблица, отфильтрованная по отчёту).
- **Группы (S2.9).** «В группу…» из выборки; объект в нескольких группах — то же, что папки
  в consolem.
- **Удаление нескольких (S1.8).** Диалог считает последствия (архивы, детекторы, правила),
  подтверждение.

Из SPEC.md прямо сказано: из consolem в новый конфигуратор взяты срезы, папки с
множественным членством, карточка, Ctrl+K, три способа добавления, шаблон имени и
массовая правка с «не менять». Обратный перенос логичен: таблица с выбором, карточка
выборки, план → очередь → отчёт.

## 4. Что показывает прототип BMS `sip-setup`

Файлы: `index.html` (базовый), `index_10.html`, `index_11.html`, `tests/checklist*.md`.

- **Галочки в дереве с тристейт-родителями.** Отметить узел = отметить всё видимое
  поддерево; родитель показывает «частично». Мастер-чекбокс «Выбрать всё / Снять
  выделение» работает по видимым строкам (с учётом поиска), счётчик «Выбрано: N» —
  общий. Кнопка удаления появляется только при выборе.
- **Верхний узел побеждает.** Если выбраны и узел, и его потомок, в операцию идёт только
  верхний — потомок уедет с поддеревом.
- **Отложенная фиксация вместо undo** для необратимого (ушло во внешнюю систему): узел
  получает чип «удаляется · 12», тост с «Отменить», отсчёт замирает при наведении на
  уведомление; для массового удаления окно длиннее. В `index_11` большое удаление требует
  ввести число затрагиваемых учётных записей.
- **Undo для обратимого**: привязки, переименования — тост «Отменить».
- **Таблица-реестр (`index_11`).** «Выбрано: N», ссылка «Выбрать все 248 по фильтру»
  появляется, когда отмечена вся страница; действия «Заблокировать / Разблокировать»;
  выбор переживает фильтр и страницы.
- **Пикеры привязки**: «Выбрать всё», фильтр «Все / Привязанные / Не привязанные»,
  счётчик; снятие галочки = отвязать.
- **Сводная таблица «парк оборудования»** с чипами по статусу (онлайн / офлайн / без
  привязок) и поиском.

## 5. Предложения для consolem: как вписать

Принцип: не добавлять новых зон на странице. Всё ложится в четыре уже существующих
места — строка фильтров над деревом, само дерево, заголовок карточки и тело карточки.

### 5.1. Дерево: режим выбора

- **Галочки появляются по требованию.** Кнопка «Выбрать» в строке фильтров (рядом с
  «Все статусы») или первый Ctrl/Shift-клик включают режим: у строк текущего среза
  появляются чекбоксы в колонке иконок, Esc выключает. Раскладка не меняется — чекбокс
  занимает место иконки типа.
- **Тристейт на контейнерах.** Галочка на сервере, регистраторе, папке отмечает все его
  устройства текущего среза, видимые при текущем поиске и фильтре статусов (BMS).
  Сервер сам в выборку не попадает (сохраняем `canMultiPick`).
- **Строка «Выбрано: 12 · Выбрать все 214 по фильтру · Снять»** — появляется под строкой
  фильтров только при выборе, как уже появляется заметка «скрыто фильтром».
- **Клавиатура.** Ctrl+A — все видимые своего среза, Space — отметить, Delete есть.
- Срез остаётся границей выборки: камеры и ОПС вместе не выбираются — это и есть
  гарантия однородности для общих полей.

### 5.2. Карточка справа: «карточка выборки» при N ≥ 2

Сейчас при мультивыборе справа карточка последнего объекта. Предлагается при N ≥ 2
показывать карточку выборки **той же формы**, что карточка устройства:

- **Крошки и заголовок**: «Домен 1 / Выборка», заголовок «12 камер · 3 сервера · 2 модели».
  Под заголовком — состав чипами (по серверам, по моделям) с крестиками «убрать из
  выборки», разворачиваемый список.
- **Кнопки в заголовке** — там, где сейчас «Добавить устройство» и звезда: «Включить»,
  «Выключить», «В папку…», «Архив и запись…», «Ещё ▾» (Учётные данные…, Переименовать по
  шаблону…, Переместить на сервер…, Скопировать настройки с…, Экспорт CSV, Удалить…).
  Те же пункты дублируются в контекстном меню дерева (сейчас там три пункта).
- **Вкладки** те же: «Подключение», «Видео», «Архив», «Детекторы». В каждой — те же поля,
  но каждое поле в состоянии «— не менять —» / «— разные — (5…25)» / значение.
  Поля-идентификаторы (имя, короткое имя, ID, IP, MAC) массово не правятся: вместо
  «Имя» — «Переименовать по шаблону» (шаблоны уже есть в мастере:
  `BULK_NAME_TEMPLATES`).
- **Однородность.** Общие поля (включено, папки, архив, режим записи, предзапись, учётные
  данные) активны всегда; поля «Видео» (кодек, разрешение, к/с, битрейт) и детекторы —
  только если одна модель; иначе серые с текстом «Выбрано 2 модели. Поля доступны, если
  выбрать камеры одной модели» и ссылкой «оставить только Hikvision DS-2CD2143G2 (8)».
- **Подвал карточки** вместо обычного «Сохранить»: «Изменится 3 параметра у 12 камер ·
  Показать план» (как в configurator-next) или «Применить» для одного простого поля.

### 5.3. Таблица папки / сервера

- Колонка чекбоксов, мастер-чекбокс «все на странице», ссылка «Выбрать все N по фильтру»,
  когда отмечена вся страница (BMS, configurator-next).
- Выбор в таблице и в дереве — одно множество (`treeSel`): отметил в таблице — подсветилось
  в дереве, и наоборот. Панель действий та же — в заголовке карточки.
- Правка по месту в таблице (режим записи, папка) как лёгкие действия — опционально.

### 5.4. Применение: план → очередь → отчёт

- **План** в модальном окне: таблица шагов (что, сколько объектов, сервер), предупреждения
  (лицензия, камеры недоступного сервера исключены). Для одного простого изменения —
  свёрнутая строка в карточке без окна.
- **Очередь**: окно сворачивается в строку состояния внизу карточки «Применяется 12 из
  34 · Привязка к архиву» с паузой и отменой оставшегося; объекты в очереди помечены в
  дереве.
- **Отчёт**: строка на объект (применено / не применено, причина / сервер изменил
  значение), фильтр по результату, «Повторить неудачные (N)», «Открыть в дереве»
  (подсветить объекты отчёта), «Сохранить CSV».
- В макете это имитация: задержка на объект, 1–2 случайных отказа, чтобы отчёт было видно.

### 5.5. Подтверждения и отмена

- **Удаление N объектов**: окно считает последствия (камер, с архивом, детекторов, папок),
  при N ≥ 10 — ввести число для подтверждения (Verkada, BMS). Альтернатива — отложенная
  фиксация с чипом «удаляется · 12» в дереве и «Отменить» в тосте (BMS); обсудить, что
  ближе эксплуатации.
- **Обратимые действия** (включить/выключить, папки, избранное, режим записи): без окна,
  тост с «Отменить» на 8–10 с.

### 5.6. «Скопировать настройки с устройства»

В карточке одного устройства — кнопка «Применить к другим…»: пикер с фильтром «та же
модель / тот же сервер / папка» (как пикеры BMS: поиск, «Выбрать всё», счётчик), затем
выбор групп параметров (видео, архив, детекторы, учётные данные) → план. Это путь
Genetec *Copy configuration* и нынешнего Axxon One (раздел 2.1): он покрывает самый
частый случай «настроил одну — повтори на остальных» без шаблонов и знаком
пользователям. Отличие от Axxon One: пикер не ограничен той же моделью и прошивкой —
общие поля (архив, запись, папки, учётные данные) копируются на любые камеры среза, поля
драйвера и видео — только на ту же модель, остальные в пикере серые с причиной.

### 5.7. Выборки по правилу и шаблоны (позже)

- **Закладка как динамическая выборка.** Закладки уже хранят срез, фильтр и папку.
  Добавить «Выбрать всё по закладке» → дальше обычная панель действий. Это дешёвый аналог
  динамических групп Intune / тегов Axis.
- **Шаблоны настроек**: «Сохранить как шаблон» из карточки устройства или выборки,
  «Применить шаблон…» из панели действий. Без живой связи: шаблон — заготовка, применяется
  по команде (вывод research-market, паттерны 6 и 24).
- **CSV**: экспорт выбранных, импорт изменений с проверкой до записи (HikCentral); в
  consolem уже есть «Добавить из файла» — расширить до «изменить из файла».

### 5.8. Что не делать

- Плавающую панель действий внизу экрана — она чужая для нынешней раскладки; действия
  живут в заголовке карточки и в контекстном меню.
- Смешанные выборки через срезы (камеры + СКУД) — нет общих полей, кроме «включено» и
  папок; если понадобится — отдельный вопрос.
- Правку имени, IP, ID массово — только через шаблон имени и импорт.

## 6. Порядок проверки прототипами

| Волна | Что рисуем | Что проверяем |
|---|---|---|
| 1 | Галочки в дереве по требованию, строка «Выбрано», карточка выборки с общими полями («— не менять —»), действия Включить / Выключить / В папку / Архив и запись / Удалить, план-строка и имитация отчёта | Понятно ли, что выбрано и что изменится; не мешают ли галочки обычной работе |
| 2 | Однородная правка «Видео» и детекторов для одной модели, «— разные — (5…25)», «Скопировать настройки с…», чекбоксы в таблице папки | Хватает ли правила «одна модель»; нужен ли пикер «оставить только модель X» |
| 3 | Закладка как выборка, шаблоны, импорт изменений из CSV, отложенное удаление с таймером | Нужны ли шаблоны при наличии «скопировать с…» |

Открытые вопросы:
1. Удаление: окно с вводом числа или отложенная фиксация с «Отменить»?
2. Нужна ли «карточка выборки» для серверов (перезапуск, обновление, исключение из домена) —
   сейчас серверы не выделяются.
3. Где показывать очередь, если пользователь ушёл в другой раздел: строка состояния у
   рельса или только в карточке?
4. Правка по месту в таблице — делать ли в макете.
