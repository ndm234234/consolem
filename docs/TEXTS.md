# Как писать тексты интерфейса

Тексты интерфейса понятны оператору с первого чтения. Стиль — правила ASD-STE100 (Simplified Technical English): для английского — как в стандарте, для русского — те же правила, перенесённые на русский язык.

**Где действует.** Любой новый или изменённый текст — в `index.html` и в прототипах: подсказки, описания, диалоги, уведомления, пустые состояния, ошибки, кнопки, подтверждения. Старые тексты не переписывают попутно: их приводит к стилю отдельная работа. Тексты от сервера (`api/kinds.js`, `api/fixtures/demo.json`, сообщения `api/server.js`) — часть контракта: менять их — через запрос (CLAUDE.md, «Контракт API»).

**Образец** — раздел «Примеры» ниже. Правило не ссылается на файлы прототипов: прототип удаляют после переноса в `index.html`.

## Русский

1. **Инструкция — инфинитив**, и в подсказке, и на кнопке: «Выбрать камеры», «Сохранить», «Чтобы отменить, нажать «Отменить» в уведомлении». Не «Выберите», не «Выбор камер».
2. **Действие системы — с исполнителем.** Назвать, кто делает: «Консоль проверяет режимы сверху вниз», «Сервер записывает событие в журнал», «Браузер не дал доступ к микрофону». Не «режимы проверяются», не «событие будет записано».
3. **Глагол, а не его замена.** Без страдательного залога («создана», «будет потерян» → «создали», «если вы потеряете»), без возвратного страдательного («не добавляется» → «Клиент не добавляет»), без причастных и деепричастных оборотов, без отглагольных существительных («выполнить проверку» → «проверить»; «Повтор через 5 с» → «Консоль повторит запрос через 5 с»). Не «является», не «осуществляется».
4. **Полные предложения.** Тире и двоеточие не заменяют глагол и не соединяют две мысли: «Ключ не подходит — лицензии не действуют» → «Ключ не подходит, поэтому лицензии не действуют». Тире остаётся только в подписях, названиях шаблонов и ячейках таблиц («Движение — запись»).
5. **Одна мысль — одно предложение.** Инструкция — не больше 20 слов, описание — не больше 25. В абзаце — не больше 6 предложений.
6. **Простые слова, одно значение.** Без идиом, метафор и жаргона («держатель», «дверь», «тишина» → прямые слова). Не больше 3 слов в цепочке существительных, без цепочек родительного падежа («настройка параметров запуска сервера»).
7. **Не менять:** названия объектов, разделов, режимов и кнопок в «» — их не склоняют: «режим «Ночь» важнее режима «Выходной»», а не «вместо «Выходного»». Не менять имена полей API, коды, числа, разметку и логику.
8. **Смысл — как был.** Переписанный текст говорит то же, что старый: не терять условий («должна идти, но не идёт»), не превращать совет в требование («лучше» ≠ «должны»), не сужать круг лиц. Факт о том, кто что делает, проверять по коду.

## Английский

Английские тексты (`assets/i18n-en*.js`) — по ASD-STE100:
- инструкция — повелительное наклонение, начинается с глагола: «Select cameras», «Enter a domain name»;
- действительный залог, исполнитель назван: «The server writes the event to the journal», не «The event is written»;
- одна мысль — одно предложение; инструкция ≤ 20 слов, описание ≤ 25;
- простые слова с одним значением, термины — по словарю ниже;
- кавычки — “…”, не «…».

## Словарь

Один термин — одна вещь. Синонимы для разнообразия не используют.

| Термин | Что значит | Не писать |
|---|---|---|
| консоль / the console | это приложение, где настраивают систему | конфигуратор, интерфейс, система (как исполнитель) |
| клиент оператора / the operator client | приложение оператора для живого видео и архива | консоль просмотра |
| сервер / the server | сервер VMS, который выполняет действие | система |
| уведомление / notification | всплывающее сообщение внизу экрана | тост |
| состояние «Только журнал» / the “Log only” state | правило только пишет в журнал | наблюдение, проверка, режим (для правила) |
| режим / mode | то, что выключает правила на время: «Обслуживание», «Рабочее время». Действует один режим или «Обычная работа» | режим объекта, состояние |
| обычная работа / normal operation | состояние, когда не действует ни один режим: все правила работают по своим условиям | режим по умолчанию |
| приглушить правило / mute the rule | правило не запускает действия до заданного времени | тишина, выключить один раз |
| окно обслуживания / maintenance window | устаревшее: интервал, когда правила не действуют. Теперь это режим | окно (без уточнения) |
| период / period | отрезок на шкале времени | окно времени |
| учётка потока / stream account | учётка, по которой внешний клиент подключается к потоку | — |
| пользователь / user | человек с учётной записью | человек |
| выбрать / select | выбрать из списка | выделить |
| отметить / mark | поставить флажок у строки | — |

## Типовые фразы

| Случай | Текст |
|---|---|
| Удаление с отсчётом | «Консоль удалит <объект> после отсчёта. Чтобы отменить, нажать «Отменить» в уведомлении» |
| Объект уже в отсчёте удаления | то же: «Консоль удалит <объект> после отсчёта» (не «уже удаляет») |
| Правка в черновике | «Консоль добавит изменение в черновик» |
| Черновик сброшен | «Консоль не сохранит <что>» |
| Нет связи | «Нет связи с <чем>. Консоль показывает последние известные значения на <время>» |
| Изменить нельзя сейчас | «Изменить их можно, когда связь вернётся» |
| Отказ с причиной | «<Факт>, поэтому <следствие>»: «У домена нет ключа, поэтому его камеры не работают» |
| Пусто в поле | «Если поле пустое, <что происходит>» (не «Пусто — …») |
| Пустой список с фильтром | «Нет <объектов>, которые подходят под фильтр» |
| Подтверждение удаления | «Чтобы подтвердить, ввести число <объектов>» |

## Как менять текст безопасно

1. **Код сравнивает текст?** Перед правкой найти строку в коде: `===`, `.includes`, `.test`, `match`, ключи объектов. Если код сравнивает или ищет текст, сохранить искомую часть или перейти на код ошибки.
2. **Английский.** `i18n(s)` ищет перевод по русскому тексту. Новый русский текст — новый ключ: если у старого текста был английский, добавить ключ с английским. В `index.html` — в `assets/i18n-en.js`; в прототипе — в его собственный файл `assets/i18n-en-NN.js`, подключённый после `assets/i18n-en.js` (общий файл прототип не меняет). Ключ должен совпадать со строкой в странице буква в букву.
3. **Тесты.** Сценарии `tests/ui-*.js` общие для `index.html` и прототипов. Если проверка ищет старый текст, а прототип его изменил, проверка принимает оба: `/старый текст|новый текст/`; проверка на равенство остаётся с якорями `^…$`. Альтернатива не должна совпадать с другими сообщениями на том же экране. Старый вариант убирают, когда старого текста нет ни в `index.html`, ни в живых прототипах: их проверяют те же сценарии.
4. **Проверки.** В `index.html` и в `tests/` — сразу, как для любой правки: `python3 tools/check_ui.py` (см. `api/TESTS.md`). В прототипе — когда он готов: `--page <прототип>` и `?selftest` (`CLAUDE.md`, пункт «Проверки прототипа»).
