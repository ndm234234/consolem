# Перенос прототипа в основной

Правила из `CLAUDE.md` проекта вынесены сюда, потому что нужны только при переносе или отклонении прототипа. Правила `index.html`, прототипов, публикации и интерфейса — в `CLAUDE.md`.

По просьбе «перенеси из прототипа NN в основной …»:
0. Возьми замок `index.html`: `git fetch origin`, затем `python3 tools/index_lock.py take прототип NN` (`CLAUDE.md`, «Одна сессия за раз»). Замок занят — не переноси: скажи пользователю, кто держит замок, и жди. Скрипт назвал рабочие каталоги с правками `index.html` без push — скажи о них пользователю до переноса: там может идти другой перенос.
1. Посмотри изменения: `git log -- <файл>` и `git diff <коммит-копии> HEAD -- <файл>`. Если после последней правки прототипа полной проверки не было, сначала проверь его (`CLAUDE.md`, пункт «Проверки прототипа» в разделе «Всё остальное — в прототип»).
2. Перенеси в `index.html` только то, что попросили, поверх текущего `index.html` из `origin/main` (он мог уйти вперёд). Переноси правкой, а не копией файла: возьми изменения прототипа (`git diff <коммит-копии> HEAD -- <файл>`) и внеси их в `index.html`, например `git diff … | sed 's#<файл>#index.html#g' | git apply --3way`. Перед этим закоммить или убери другие правки `index.html`: `git apply --3way` работает только с чистым файлом и кладёт итог в индекс git. Строки, нужные только прототипу, не переноси: `assets/i18n-en-NN.js` (его строки — в `assets/i18n-en.js`), заголовок страницы. Прототип переименован после копии — `git diff -M` и замени в `sed` оба имени (точки в имени экранируй). Копия файла прототипа сотрёт то, что попало в `index.html` после копии. Копия допустима только при переносе целиком и только если `index.html` в `origin/main` совпадает с исходной копией: `git diff --quiet <коммит-копии>:<файл в коммите копии> origin/main:index.html`. Правила интерфейса соблюдай на перенесённых участках, остальное не трогай.
3. Проверки из `api/TESTS.md` (см. `CLAUDE.md`, раздел «index.html — только согласованное»). Коммит: `Макет: из прототипа NN — <что>`, плюс запись в `CHANGES.md`. Перед push — `git fetch origin && git rebase origin/main` (в основной копии — `git pull --rebase`). Rebase принёс чужую правку `index.html` — сведи конфликт, сохрани обе правки (несовместимы — спроси пользователя) и запусти проверки `index.html` ещё раз до push. После push сними замок: `python3 tools/index_lock.py release`.
4. В `protos.html` поставь прототипу статус «принят» (или «частично принят»).
5. Обнови отчёт о пробелах против Axxon One (`docs/axxon-one-gaps.html`) сам, без просьбы: пункты с этим прототипом в `PROTO` переведи в `DONE` или в `partial` — `docs/axxon-one-gaps.md`, раздел «Прототипы», шаг 2. У прототипа нет строк в `PROTO` — отчёт всё равно проверь: найди пункты `G`, которые задел перенос (`grep` по словам перенесённой функции в `title`, `missing` и `evidence`), и исправь их по тому же шагу 2 (там же, последний пункт шага). Пункт не закрыт из-за контракта — строка в `WAIT`: чего нет в контракте и какой запрос это просит (там же, раздел «Пункт ждёт контракта»). Отклонённый прототип — шаг 3 там же. Коммит: `Исследование: пробелы против Axxon One — перенос прототипа NN`.
6. Принятое удали — после переноса оно мусор: два файла с одним и тем же расходятся, и непонятно, какой смотреть.
   - Прототип принят целиком — удали файл (`git rm`), в том числе чужой: просьба перенести и есть явная просьба. Строку в `protos.html` оставь: имя файла без ссылки с пометкой «(удалён)», статус «принят: …», как у прототипа 37. Отдельный коммит: `Прототип NN: удалён — перенесён в index.html`.
   - Принят частично — файл оставь: в нём ещё есть то, что не решено. В статусе перечисли, что перенесено. Когда остальное перенесут или отклонят — удали, как выше.
   - По просьбе «отклони прототип NN» — статус «отклонён: почему», файл удали (`git rm`), коммит `Прототип NN: удалён — отклонён`. Строки прототипа в `PROTO` отчёта `docs/axxon-one-gaps.html` убери (шаг 5). Его добавления в контракт сними, как отклонённую владельцем правку (скилл `api-contract`), если на них не держится `index.html`; в уведомлении о них допиши, что добавленное снято, — закроет владелец.
   - Ссылки на удалённый файл в живых документах (`*.md`, `protos.html`, другие прототипы) замени на имя с пометкой «(удалён)»; `CHANGES.md` и всё в `api/requests/` (запросы, уведомления, ответы) — история, их не трогай. Файл остаётся в git: `git log --all -- <файл>`, затем `git show <коммит>:<файл>`.
