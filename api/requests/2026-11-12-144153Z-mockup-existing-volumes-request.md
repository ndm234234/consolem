# Запрос от команды mockup: хранилище на существующих томах, без форматирования

2026-11-12 · коммит контракта `f080e13` (0.12.0) · от команды mockup, для владельца контракта

Кому: владелец контракта

**Статус: новый**

## Зачем

Пробел B4 против Axxon One (`docs/axxon-one-gaps.html`): администратор создаёт хранилище из томов, на которых уже есть записи, — раздел SolidStore, файл `.afs` или папка объектного хранилища, — и сервер не стирает эти записи. Источник — документация Axxon One 3.0, «Creating an archive based on existing archive volumes» (lexiro doc 292095): выбрать диски или сетевые хранилища с томами, для тома-файла выбрать файл, снять флажок **Format**; новое хранилище может собрать тома разных старых хранилищ; записи видны, только если имя сервера и ID камер те же, что при записи.

Сейчас в контракте 0.12.0:
- у вида `volume` нет поля, которое говорит «на томе есть записи, подключить как есть». Сервер стенда ставит новому разделу (`mode: "part"`) `state: "unfmt"` (`api/profiles.js`), а раздел с записями SolidStore форматировать не нужно;
- нет способа узнать, какие тома с записями лежат на дисках сервера (`disks` сервера даёт только диск, объём и признак системного) и в папке NAS;
- у тома нет периода записей и прежнего хранилища: администратору нечем отличить нужный том.

Прототип 58 (`index_58_toma-s-zapisyami.html`) показывает это на заглушке: шаг «Первый том» мастера «Новое хранилище» и окно «＋ Том» дают выбор «Новый том» / «Том с записями», список найденных томов строит браузер, признак «с записями» живёт в памяти страницы и на сервер не уходит.

## Пункты

1. **Поле тома «подключить с записями».** Необязательное поле в `UnitCreate` тома (вид `volume`), например `attachExisting: true`: сервер подключает раздел, файл `.afs` или папку как есть, без форматирования, и записи остаются. Умолчание — `false`, прежнее поведение. Том, подключённый так, получает `state: "ready"` (или `open`, пока сервер читает индекс), а не `unfmt`. Если по адресу нет тома с записями — `422` с понятным `code` (например `volume.notFound`), если тип тома не подходит хранилищу (папка объектного у блочного, файл `.afs` у объектного) — `422` (`volume.storageMismatch`).
2. **Найденные тома.** Команда вида хранилища (как `check`, через `POST /kinds/{kind}/actions/…`, хранилища ещё нет) или команда сервера: список томов с записями на дисках сервера — для локального — и в папке NAS по пути и учётной записи — для сетевого. У каждого тома: адрес (`disk`, `mode`, `dir`, `file`), объём, тип хранения (`block` / `object`), период записей (`from`, `to`), имя прежнего хранилища, имя сервера, который записывал. Диски, которые уже заняты томами других хранилищ, в список не входят.
3. **Период записей у тома.** Только для чтения: `recordsFrom`, `recordsTo` у тома (для карточки тома и строки списка). Необязательно: прототип показывает период, который запомнил при подключении.
4. **Имя сервера записи.** В ответе пункта 2 — имя сервера, который писал том. Интерфейс предупреждает, если оно не совпадает с текущим: по документу Axxon One записи тогда не видны. Если сервер может сам сказать, видны ли записи (имя сервера и ID камер совпали), — лучше признак `recordsVisible`.
5. **Тесты:** `POST` тома с `attachExisting: true` по адресу найденного тома даёт том без `unfmt`; без поля — прежнее поведение; по адресу без тома — `422`.

## Что сломается у тех, кто работает по контракту

Ничего: все пункты — новые необязательные поля и новая команда, умолчания сохраняют прежнее поведение.
