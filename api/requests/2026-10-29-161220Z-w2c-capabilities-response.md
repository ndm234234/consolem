## П. 1. Объявление возможностей — сделано, `6c88e17`

- Поле `capabilities` — в `GET /reference`, а не в `GET /me`: это свойство системы, а не администратора. Схема `Capabilities`, три списка:
  - `operations` — `operationId` операций, которые система выполняет. `getMe`, `getReference`, `stream` обязательны, служебные `test-support` сюда не входят;
  - `deviceTypes` — виды устройств. У вас — `["camera", "det"]`;
  - `features` — необязательные настройки: `serverRoles`, `serverNetwork`, `archiveEncryption`. У вас — пусто.
- Неподдержанная операция — `404 NO_ROUTE`, и раньше разбора адреса и тела: по этому коду клиент понимает «не поддержано», а не «нет записи».
- Неподдержанный вид устройства или настройка — новый код `422 NOT_SUPPORTED` с `field`. В `POST /devices` он приходит строкой в `failed`.
- Объявленное работает по контракту целиком: «поддержано частично» выражается только тем, чего нет в списках.
- Ваш список «у нас пока нет» в объявлении выглядит так:

  | Чего нет | Как объявить |
  |---|---|
  | нескольких доменов | без `createDomain`, `deleteDomain` |
  | устройств, кроме камер и детекторов | `deviceTypes: ["camera", "det"]` |
  | лицензий | без `listLicenses` |
  | ролей и сетевых настроек серверов | без `serverRoles`, `serverNetwork` в `features` |
  | хранилищ из нескольких томов, шифрования | без `createVolume`, `deleteVolume`; без `archiveEncryption` |
  | поиска в сети | без `getDiscovery`, `startDiscovery`, `stopDiscovery` |

- Интерфейс прячет неподдержанное: пункты меню, кнопки, вкладки, поля, виды в мастере. Посмотреть можно здесь: `index_10_api-server.html?fixture=one-domain`.
- Тесты пропускают неподдержанное (строка `SKIP` с причиной) и считают покрытие по объявленному. Отдельная проверка следит, что каждая необъявленная операция отвечает `404 NO_ROUTE`.

## П. 4. Непрозрачная версия — да, `2fa42f3`

- `version` — строка. Клиент сравнивает её только на равенство и возвращает в `If-Match` как есть, порядка и «+1» у неё нет. Пустая или не та — как раньше, `428` и `412`.
- Что обязан сервер:
  1. Версия меняется при любом изменении того, что видно в записи, в том числе любой из частей, из которых запись собрана. Подойдёт склейка версий частей (`"a12.b7.c3"`).
  2. Версия никогда не возвращается к прежнему значению той же записи. Хеш одного содержимого этого не гарантирует.
  3. Версия не меняется без изменений: связь устройства и нагрузка её не трогают.
  4. Символы — печатные ASCII без пробела и кавычек.
- Встроенный сервер выдаёт версии из общего счётчика (`v1`, … `v3k`), поэтому ни интерфейс, ни тесты не могут опереться на «+1».
- Где смотреть: [BACKEND.md, «На что обратить внимание» → «Версии и 412»](../BACKEND.md#на-что-обратить-внимание).

## Чего пока нет

- **Самопроверка прототипа против вашего стенда.** `index_10_api-server.html?api=…&selftest` пока работает только на наборе `demo`: её сценарии написаны под весь контракт. Ваш критерий готовности сейчас — тесты API (пункты 1–3 «Когда готово» в [BACKEND.md](../BACKEND.md#когда-готово)).
- **В объявлении нет ограничений числа** (сколько томов, камер на сервер) и разных возможностей у разных объектов одной системы. Это задача о нескольких VMS за одним API ([`prompts/api-multi-vms.md`](../../prompts/api-multi-vms.md)). Если нужно раньше — пришлите отдельный запрос.
