## Что проверить

1. **Модель тура — по п. 4 ответа 174207Z.** Свойство камеры `tours` — массив туров:
   - `id` (строка 1–64, обязательна) — имя тура для команды правила `ptz.tour`;
   - `name` (строка 1–128, обязательна);
   - `steps` (обязателен, не меньше одной точки): `preset` — номер пресета, `dwellSec` — сколько стоять, 1–3600 с, `speed` — скорость переезда 1–100, нет поля — скорость камеры;
   - `order` — `seq` или `random`, нет поля — `seq`;
   - `pauseSec` — пауза между кругами, от 0, нет поля — 0;
   - `onManual` — `pause` или `stop`, нет поля — `pause`; `resumeSec` — от 5, нет поля — 15; `resumeFrom` — `same` или `first`, нет поля — `same`;
   - `idleStartSec` — от 10: тур запускается сам, когда камерой не управляют столько секунд.

   Ваш бэкенд хранит туры в камере (ONVIF PresetTour) или на сервере? Подходят ли пределы чисел?
2. **Пределы от камеры** — `tourMax` и `tourStepsMax`, только чтение, как `presetMax`. Нет поля — предела нет. Пределов времени и скорости отдельными полями нет: их задают `minimum` и `maximum` схемы. Ваш бэкенд знает пределы камеры (ONVIF `GetPresetTourOptions`)?
3. **Проверка сервера.** Хук `ptz.beforeSet` отклоняет `PATCH` с `tours`, если у двух туров один `id`, если `idleStartSec` есть у двух туров, если туров больше `tourMax` или точек больше `tourStepsMax`: `422 VALIDATION_FAILED`, `field: /properties/tours`, причина в `params.reason` (`duplicateId`, `idleTwice`, `tourMax`, `tourStepsMax`). Ошибки схемы идут по обычному правилу, путём до поля (`/properties/tours/0/steps/0/dwellSec`). Прежние запросы новых отказов не получают: поля раньше не было.
4. **Пресет точки сервер не проверяет.** Пресет могут удалить позже, а `PATCH` шлёт список целиком: проверка сломала бы правку других туров. Консоль показывает такую точку ошибкой «пресета больше нет». Вас это устраивает?
