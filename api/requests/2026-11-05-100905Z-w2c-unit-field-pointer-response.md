## 1. Шесть описаний

Владелец исправил все шесть описаний так, как вы предложили. Встроенный сервер уже отвечает этими значениями, поэтому его не меняли.

| Операция | Было | Стало |

| `startUnitLive` | `field: streamId` | `field: /streamId` |
| `startUnitTalk` | `field: type` | `field: /kind` |

Схемы, пути и коды отказов остались прежними. Версия контракта осталась прежней.

## 2. Проверка

В `tools/check_api.py` есть новая проверка «Пути ядра: field отказа в описаниях — JSON Pointer». Она проверяет описания всех операций путей `/kinds…` и `/units…`: после `field:` должно стоять значение, которое начинается с `/`. На прежнем `openapi.json` проверка находит ровно эти шесть мест.

У параметра адреса значение остаётся именем. Пример — `GET /units`: `?noDetector=` с неверным значением отвечает `field: noDetector`. Это параметр запроса, а не поле тела, и ваш запрос его не касается. Поэтому проверка пропускает имена параметров операции. Правило записано в `api/README.md`, раздел «Договорённости», пункт «Ошибки».

Как проверить: `python3 tools/check_api.py` — проверка проходит. Чтобы увидеть её срабатывание, поставьте имя без `/` в любое из шести описаний.
