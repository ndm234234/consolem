# Ответы команды w2c на вопросы по п. 1

Спасибо. Ниже ответы на вопросы 1–6, можно начинать работу по п. 1. На вопросы п. 2 ответим отдельно.

1. **Заголовок CSP.** Страница WebUI отдаётся ровно с таким заголовком, без дополнительных директив:

   ```
   Content-Security-Policy: script-src 'self' 'sha256-…'; object-src 'none'; base-uri 'none'
   ```

   `'sha256-…'` — хэши встроенных `<script>` страницы. Если в `index.html` встроенного кода нет, их нет, и заголовок
   — `script-src 'self'; object-src 'none'; base-uri 'none'`. Заголовок для этой страницы у нас закреплён: строже
   он не станет. Прогоняйте тесты сборки с ним.
2. **Стили и картинки.** Встроенные стили (`style="…"` и вставляемый `<style>`) и картинки `data:` разрешены: в
   заголовке нет `style-src`, `img-src` и `default-src`. Строгий вариант делать не нужно, значки в CSS можно оставить
   как есть.
3. **Адрес API.** Тот же адрес, что у страницы. Страница — `/backend/`, API — `/backend/api/…`, поток —
   `/backend/api/stream`. Ваш `<meta name="consolem-api" content="api">` принимаем, значение **относительное**
   (`api`), тогда файл одинаков для любой установки. По 401 просим перейти по такому же относительному
   `<meta name="consolem-login" content="../">`: вход у нас один, его показывает наша консоль.
4. **Входная страница.** Да: отдайте `index.html` в составе сборки. Мы отдаём его байт в байт, закреплённым по
   SHA-256, как остальные файлы. Своего в странице у нас нет: шапка и вход — у консоли на другой странице.
5. **Как открывается WebUI.** Отдельной страницей `/backend/`, без рамки и без `sandbox`.
6. **Формат списка.** `MANIFEST.json` `[{name, type, purpose, size, sha256}]`, SHA-256 в hex — так и нужно. Base64
   для `integrity` не нужен: файлы отдаём сами и сверяем при установке. Имена файлов — постоянные, без хэша в имени.

Картинки: верно, приложению они не нужны — `logo-configurator.png` и `one-sign.svg` не присылайте.

## Ответы по п. 2

1. **Один запрос не записывается наполовину.** Сейчас — нет: если вторая часть не прошла проверку версии, первая
   остаётся записанной. Мы это меняем: делаем **пакетную запись** в хранилище платформы. Все части устройства, которые
   меняет запрос, пишутся одной операцией, у каждой — проверка её версии; остальные части устройства проверяются на то,
   что они не изменились с прочитанного снимка. Не прошла любая проверка — не записывается ничего, ответ `412` с текущей
   записью. Так же для строки `failed` в `/devices/update` и шага `fail` в `/operations`: строка или шаг либо записаны
   целиком, либо не изменили ничего. Когда пакетная запись будет в стенде, напишем здесь же.
2. **Связанные поля.** Камера у нас собрана из записи `cam` (имя, адрес, учётка, `enabled`), записей `rec` (основная и
   резервные: `recordMode` — это состав записей, `archiveId`, `extraArchives`, `recordDetectorIds`) и детекторов `det`.
   Связанные поля `recordMode`, `archiveId`, `extraArchives`, `recordDetectorIds` лежат в нескольких записях `rec`. С
   пакетной записью это не важно: при записи проверяется **всё устройство**, и одновременная правка любой его части —
   `412`.

Поэтому ограничение из п. 2 нашего запроса снимается: одновременную правку другой части того же устройства мы тоже
ловим. Допущение «одновременная правка разных частей не ловится» в `BACKEND.md` записывать не нужно — `If-Match` у нас
означает версию всего устройства.
