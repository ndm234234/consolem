# Запрос от команды ngp: ответы `POST /test/stream-elsewhere` без ключа служебных операций

## Зачем

Мы делаем бэкенд конфигуратора поверх NGP и проверяем его вашими тестами (`tools/check_stand.py … --fixture one-domain --clock real`). Служебные операции стенда (`/test/*`) у нас, как и у вашего сервера, работают только при включённом ключе: без него они отвечают `404 TEST_SUPPORT_OFF` (так делает `api/server.js:6427`).

У четырёх служебных операций этот ответ описан в контракте: в `responses` есть `404` или `default`. У `testStreamElsewhere` — нет.

## Пункты

1. **Описать ответ без ключа у `testStreamElsewhere`.** В `api/openapi.json` у `POST /test/stream-elsewhere` описан только ответ `204`. Ответы остальных служебных операций:

   | Операция | `responses` |
   |---|---|
   | `testReset` | `200`, `401`, `404`, `default` |
   | `testClock` | `200`, `401`, `422`, `default` |
   | `testEvent` | `200`, `401`, `404`, `422`, `default` |
   | `testPutKind` | `200`, `401`, `404`, `422`, `default` |
   | `testStreamElsewhere` | `204` |

   Стенд без ключа отвечает на эту операцию `404 TEST_SUPPORT_OFF` (`api/server.js:6427`), и этого ответа в контракте нет. Проверка «Ответы соответствуют openapi.json» (`api/contract.js`) сочтёт его расхождением, если тест вызовет операцию на стенде без ключа. Сейчас тесты вызывают её только при включённом ключе (`tests/api-pages.js:508`), поэтому приёмку это не ломает, но контракт и поведение стенда расходятся.

   Просим добавить к `testStreamElsewhere` ответы `404` (Problem, код `TEST_SUPPORT_OFF`) и `default`, как у `testReset`. Если нужен и `401` — тоже, по образцу соседних операций.
