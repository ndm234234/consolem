# Запрос от команды w2c: API конфигуратора за нашей VMS

2026-10-29 · коммит контракта `9dc1688` · от команды w2c (бэкенд VMS)

Мы делаем бэкенд к API конфигуратора (`api/openapi.json`, коммит `9dc1688`) для нашей VMS. Контракт берём как
есть и сверяемся с каждой вашей правкой. Готовность хотим доказывать вашими тестами (`tests/api.html?api=<стенд>`,
`tools/check_stand.py`).

Чтобы тесты можно было прогнать против нашей системы, просим три вещи. Они пересекаются с вашей задачей о
нескольких VMS ([`prompts/api-multi-vms.md`](../../prompts/api-multi-vms.md)).

1. **Объявление возможностей.** Пусть система сообщает, какие разделы, виды объектов и операции она поддерживает:
   поле в `GET /reference` или в `GET /me`. Неподдержанная операция отвечает `404 NO_ROUTE`. Интерфейс прячет
   неподдержанное, тесты его пропускают, а проверка покрытия считает только объявленное. У нас пока нет:
   - нескольких доменов на одну установку;
   - устройств, кроме камер и детекторов (микрофоны, реле, датчики, СКУД, оповещатели);
   - лицензий;
   - ролей серверов и сетевых настроек сервера;
   - хранилищ из нескольких томов и шифрования;
   - поиска в сети на первом шаге.
2. **Набор данных под профиль.** Рядом с `fixtures/demo.json` нужен набор для профиля «один домен, камеры,
   детекторы, хранилища, правила, пользователи». `POST /test/reset` пусть принимает имя набора.
3. **Тесты на идущих часах.** Наша система работает на настоящих часах, остановить их мы не можем. Нужен режим
   тестов API без `POST /test/clock`: тест ждёт результат, пока он не наступит. Ваша самопроверка `?selftest` уже
   так работает (`freezeClock: false`).

И один вопрос по контракту:

4. **Версия записи.** `version` описан как целое, растущее на 1. У нас одно устройство собрано из нескольких
   записей, и честного «+1» для него нет. Можно ли считать версию непрозрачной: сравнивать только на равенство и
   передавать через `ETag`/`If-Match`, не полагаясь на порядок?
