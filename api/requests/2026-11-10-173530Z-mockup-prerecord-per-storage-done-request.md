# Запрос от команды mockup: предзапись у каждого хранилища камеры внесена в контракт 0.7.0 — проверить

## Что мы сделали

Пользователь команды mockup (Maxim Kabenin) указал: предзапись у каждого хранилища камеры своя. Так в Axxon One: `prerecord_sec` — свойство привязки камеры к архиву, а не камеры (Axxon One 3.0, «Configuration of recording to an archive for a camera», п. 6; поле «Prerecord, s» в строке камеры на вкладке архива). Исходного запроса нет: это правка без запроса, по разделу «Правка контракта без владельца».

Коммит `ccc1499` («Прототип 46: предзапись своя у каждого хранилища — …»). Версия контракта — 0.7.0. Мы только добавили необязательное поле и ничего не сняли и не переименовали. Устаревшего в 0.7.0 нет. Описание — `api/README.md`, раздел «Что добавлено в 0.7.0», и `api/BACKEND.md`, «Настройки записи» и таблица свойств `vms.camera/1`.

`index.html` не изменён. Поле показывает прототип 46 (`index_46_ponyatnye-knopki-kamery.html`, вкладка «Архив», строка хранилища).

## Что проверить

1. **`preRecordSec` в строке `extraArchives`.** Схема вида камеры (`demo.json`, `kinds` → `vms.camera/1`): необязательное целое, `minimum: 0`. Поля нет — строка берёт `preRecordSec` камеры, как до 0.7.0. Значение меньше нуля — `422 VALIDATION_FAILED`, `field: /properties/extraArchives/<i>/preRecordSec`. Строка без поля в новой правке теряет своё значение: `extraArchives` заменяется целиком, как и раньше.
2. **`preRecordSec` камеры — предзапись основного архива.** Описание поля уточнено: «Предзапись основного архива (archiveId), с. Строки extraArchives без своего preRecordSec берут это значение». Правка камеры строку со своим значением не меняет.
3. **Снятие хранилища.** Основное хранилище сняли (`archiveRemove` в `api/profiles.js`): основным становится следующая строка, и её свой `preRecordSec` переходит к камере. Строка без своего значения брала значение камеры, оно остаётся. Тест — `tests/api-storage.js`, «Хранилище: удалить — …».
4. **`replica`.** Строка `replica` забирает готовые записи, поэтому её `preRecordSec` сервер хранит, но не применяет. Новой проверки и нового отказа нет.
5. **Тесты.** `tests/api-archive.js`, «Предзапись (0.7.0)»: своя у строки, строка без поля, правка камеры не трогает строку, отказ на `-1`, строка без поля снимает своё значение. Тест падает на контракте 0.6.0 (`422 VALIDATION_FAILED`: поле строки вне схемы). `api/TESTS.md`: 357 на эталонном наборе, 239 на `one-domain`.

## Сверх запросов

- Решение самого автора: пустая предзапись строки — «как у камеры», а не 0 и не умолчание сервера. Так клиенты 0.6.0 не меняют поведения.
- Решение самого автора: при снятии основного хранилища своя предзапись строки переходит к камере (п. 3), как `retentionDays` и `minDepthDays`.
- Проверки: `check_api`, `run_api_tests` (оба набора), `check_ui` и `check_ui --page` прототипа 46 проходят. `check_perf --quick` падает только на известном шаге «поиск в дереве «Кластер»» (`search-klaster`, 482 мс), который `api/TESTS.md` называет пограничным; правка поиск не затрагивает.
