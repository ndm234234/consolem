# Запрос от команды ngp: вкладка «Камеры» сервера запускает поиск в сети без проверки `startDiscovery`

2026-11-15 · коммит контракта `564ba43` (0.35.0; ссылки пересчитаны 2026-11-20, первая редакция — `590e3cc`) · от команды ngp (бэкенд конфигуратора поверх NGP)

Кому: владелец контракта

**Статус: новый**

## Зачем

Бэкенд поверх NGP в прототипе 0.2 не объявляет `startDiscovery`: поиск устройств в сети придёт позже. Дымовая проверка открывает в WebUI карточку сервера и хранилища и требует, чтобы в консоли браузера не было ошибок.

Вкладка «Камеры» строится функцией `lanCardBuild` (`index.html:15485-15486`). Она вызывает `lanEnsure`, а та — `lanSearch` (`index.html:15036-15049`). `lanSearch` сразу отправляет `POST /units/{uid}/discovery` (`uid` — объект области; до 0.32.0 — `POST /domains/{id}/discovery`) через `discStart` (`index.html:15055-15059`, `:13647-13653`). Объявлена ли операция, код не проверяет. Бэкенд отвечает `404 NO_ROUTE`, как и положено для необъявленной операции, а Chrome пишет в консоль ошибку загрузки ресурса.

В других местах WebUI ту же операцию проверяет: мастер добавления устройства показывает вкладку «В сети», только если `can("startDiscovery")` (`index.html:34671`, `:38566`, `:38571`).

Пока ответа нет, наша дымовая проверка допускает ровно этот запрос — поиск в сети с ответом `404` (по контракту `590e3cc` — `POST /domains/{id}/discovery`) — и печатает его отдельной строкой. Любая другая ошибка консоли по-прежнему считается отказом.

## Пункты

1. **Поиск только при объявленной операции.** Предлагаем, чтобы `lanEnsure` вызывал `lanSearch`, только если `can("startDiscovery")`. Без операции вкладка показывает камеры домена без строк «найдено в сети», как мастер добавления сейчас.
