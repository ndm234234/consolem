## Что проверить

1. **Страницы назад.** В ответе `GET /journal` необязательные `prevCursor` (страница перед этой, передаётся в `cursor`) и `offset` (записей отбора перед страницей). У страницы `around` их нет. Тест — «страницы назад».
2. **Возможность `journalAudit`** (`Feature`): с ней система пишет запись аудита на каждое изменение через API, заполняет `actor` у каждой записи и отдаёт `prevCursor`, `offset`. Без неё клиент ничего из этого не ждёт; бэкенд без неё проходит те же тесты, что и с 0.8.0.
3. **Запись аудита.** `level: audit`, `kind: api.<operationId>` (виды — в `GET /journal/kinds`, подпись — `summary` операции), `actor`, в `fields` — `ip`, `operation`, `method`, `path`, для `PUT` и `PATCH` — `change` и новый ключ `changes`. Секреты — «••••». Тесты — «аудит», «секреты и удаления».
4. **Выгрузка CSV.** `GET /journal/export` (`exportJournal`): все записи отбора `GET /journal`, `text/csv`, UTF-8 с BOM, время ISO 8601 со смещением пояса `tz`, `lang`, `delimiter`, защита от формул; выгрузка — запись аудита `jexport`. Тест — «выгрузка CSV».
5. **`actor`** — описание поля дополнено, прежний смысл (нет поля — автор неизвестен) сохранён.

## Сверх запросов

- **Склейка частых команд.** PTZ, живое видео и разговор одного пользователя по тому же пути за 30 с — одна запись. Остальные изменения — каждое своей записью.
- **Адрес клиента** у встроенного сервера — последний адрес `X-Forwarded-For`; BACKEND.md советует адрес сокета или адрес своего прокси, не первый адрес заголовка.
- **Стенд HTTP** (`tools/serve_api.mjs`) отдаёт файл как есть и открывает странице `Content-Disposition`.
- **Клиент API** (`api/client.js`): ответ не JSON приходит строкой.
- **Пропуск в аудите**: ход ассистента, наблюдение потока, `validateUnits`, `checkExport`, `testRule` — без записей.

## Что сломается у тех, кто уже работает по контракту

Ничего не снято. В ответе `GET /journal` могут прийти новые поля `prevCursor` и `offset`, в `fields` записи — новые ключи. Клиент, который пропускает незнакомые поля, их не заметит. Во встроенном сервере у каждой записи теперь есть `actor`, а изменения через API добавляют записи в журнал: число записей в отборе растёт после каждого изменения.

## Что решить владельцу

- Принять `journalAudit`, `prevCursor` и `offset` или назвать свои — тогда поправим `index.html` и тесты.
- Ответить на запрос об обязательном `actor`.
