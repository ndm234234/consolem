## Что мы делаем

Мы закрываем пробел A23 против Axxon One (`docs/axxon-one-gaps.html`): карточка сервера показывает версии и состояние лицензии. В Axxon One объект «Сервер» показывает их прямо в карточке (документ lexiro 568876): **Server version** `3.0.0.42`, **AxxonOne client** `3.0.0.42 x64`, **Driver pack** `3.89.467`, **License status** «Active license file of the demo mode», **Server name** `DESKTOP-5VRITM5`, **Server status** «Active server».

Сейчас в контракте этого нет: у вида `server` в схеме есть только `ip`, `port`, `role`, `netmask`, `gateway`, `dns`, `labels`, `allocated` и `webServer`. Версию показывает только карточка камеры, и то как параметр драйвера. Прототип 66 (`index_66_versii-servera.html`) рисует блок «Версии и лицензия» на заглушке: значения живут в браузере.

## Источники

Axxon One 3.0, документы lexiro: 568876 («Server»: поля карточки сервера и их смысл), 282280 («Drivers Pack Update»: Drivers Pack обновляют отдельным установщиком), 282281 («Automatic update of the remote client»: клиент обновляется с сервера, вместе с ним обновляются DetectorPack и Drivers Pack). Живого сервера Axxon мы не проверяли.

## Что нужно

Имена полей — наше предложение. Владелец контракта может выбрать другие.

1. **Версии сервера.** Поля вида `server`, только для чтения (`readOnly: true`):
   - `version` — версия установленного VMS на этом сервере (`3.0.0.42`);
   - `clientVersion` — версия клиента, который сервер раздаёт (`3.0.0.42 x64`);
   - `driversPackVersion` — версия пакета драйверов (`3.89.467`);
   - `detectorPackVersion` — версия пакета детекторов.
   Зачем: администратор обновляет домен по одному серверу и должен видеть, где какая версия стоит. Без этих полей консоль не покажет ни одной версии.
2. **Имя компьютера и состояние сервера.** Поля вида `server`, только для чтения:
   - `hostname` — сетевое имя компьютера; имя объекта его не повторяет, пользователь может его изменить;
   - `state` — `active`, `starting`, `stopped`, `noLink`, и `stateText` — текст сервера, если он есть.
   Зачем: в Axxon One это **Server name** и **Server status**. Сейчас консоль берёт связь из `link` объекта и не отличает «сервер остановлен» от «нет сети».
3. **Состояние лицензии у сервера.** Сервер работает по ключу домена, поэтому состояние мы возьмём из ключа. Запрос лицензий (`2026-11-06-094022Z-mockup-domain-licenses-request.md`, пп. 1 и 1а) уже просит у ключа `product`, `expiresAt`, `state` и `stateText`. Сверх него нужно одно:
   - `licenseKeyId` у вида `server` или у домена — чтобы карточка сервера нашла ключ и показала его состояние со ссылкой на вкладку «Лицензии» домена.
   Если владелец примет пункт 1а того запроса, этого поля хватит, и отдельного состояния лицензии у сервера не нужно.
4. **Несовпадение версий.** Отдельного поля не просим: консоль сравнит `version` серверов одного домена и `clientVersion` с `version` сама. Нужен ответ на один вопрос: сервер сам знает, что его версия отличается от версии домена, или это считает клиент? Если знает — назовите поле, и консоль покажет текст сервера.
5. **Событие в потоке.** Изменение версий — событие с новой версией объекта, как у `settings`. Тогда карточка обновляется сама после обновления сервера.

## Что сломается

Ничего. Все поля новые, необязательные и только для чтения. Клиент, который их не знает, пропускает их по правилу контракта о незнакомых полях. Поле `licenseKeyId` пункта 3 зависит от ответа на запрос `2026-11-06-094022Z`: если ключи не станут отдельными объектами, вместо него нужно состояние лицензии прямо у сервера.
