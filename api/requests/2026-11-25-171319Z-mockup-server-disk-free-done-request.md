## Что мы сделали

Мы сделали часть пункта `F92` отчёта о пробелах против Axxon One ([`docs/axxon-one-gaps.html`](../../docs/axxon-one-gaps.html)): «Размер тома архива». Axxon One показывает свободное место диска при создании тома и не даёт создать том больше этого места (axxonnext.ui `ArchiveSizeValidator`). Консоли для этого нужно свободное место каждого диска сервера. Поле входит в профиль `vms.server/1`, поэтому правку проверяют его reviewers — w2c. `python3 tools/layers.py` назвал и владельца контракта (подсистема).

- Профиль `vms.server/1` 1.3 ([`api/profiles/vms.server.json`](../profiles/vms.server.json), таблица [`vms.server.md`](../profiles/vms.server.md)): поле `freeBytes` в элементах `status.observed.disks`. Хук встроенного сервера — `api/profiles.js`, функция `diskFree`. Описание — [`api/BACKEND.md`](../BACKEND.md), абзац «Свободное место дисков сервера». Контракт не меняется: `api/openapi.json` правка не трогает.
- Интерфейс — прототип 102 (https://ndm234234.github.io/consolem/index_102_razmer-toma.html, коммит `167d7d2`): окно «Новый том», мастер «Новое хранилище» и карточка тома показывают «Свободно X из Y на диске D:» и не дают задать том больше свободного места. `index.html` поле пока не читает.
- Тест: `tests/api-storage.js`, тест «Диски сервера: freeBytes — не больше размера диска; новый том уменьшает его на свой объём» — слой `profile:vms.server/1`, `since: "1.3"`, нужна возможность `implements:vms.server/1`.

## Что проверить

1. **Поле `freeBytes`** (integer, не меньше 0, необязательное) в каждом элементе `status.observed.disks`: сколько байт диска свободно сейчас. Тома всех хранилищ на диске уже вычтены. Ваш бэкенд знает свободное место каждого диска сервера?
2. **Раздел хранилища целиком.** Если на диске есть том в режиме `part`, `freeBytes` — 0: том занимает весь раздел. Так ли это у вас?
3. **Нет поля.** Если система не знает место, поля нет: консоль место не показывает и размер тома по диску не проверяет. Прежние клиенты поле пропускают.
4. **Новый том уменьшает место.** После `createUnits` тома в режиме `file` или `dir` с `sizeBytes` поле `freeBytes` его диска становится меньше на `sizeBytes`. Место считается по объёму тома, а не по записям на нём: так делает Axxon One, когда создаёт файл тома сразу на весь объём.

## Сверх запросов

- Отказ сервера на том больше свободного места — ломающая правка (новый отказ на прежнем запросе), поэтому мы его не делали. Для него есть отдельный запрос: [`2026-11-25-162356Z-mockup-volume-no-space-request.md`](2026-11-25-162356Z-mockup-volume-no-space-request.md).
- Встроенный сервер считает место моделью: системный диск — 50 % объёма, другие — 90 %, минус объём томов на диске. Модель нужна только тестовому стенду.
- К месту тома, который уже стоит на диске, консоль прибавляет его же объём: так человек может увеличить том до «свое + свободное».
