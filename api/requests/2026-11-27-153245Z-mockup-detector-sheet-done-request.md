## Что мы сделали

Мы закрыли пункт `F125` отчёта о пробелах против Axxon One ([`docs/axxon-one-gaps.html`](../../docs/axxon-one-gaps.html)), «Таблица свойств детектора». У Axxon Next окно детектора показывает таблицу свойств его вида: группы, описание и отметку «параметр надо задать вручную» (`NeedManualAdjustmentAttribute`). У вида `det` этого не было: консоль сама собирала поля по виду детектора. `python3 tools/layers.py` назвал слои: вид `det` вне профилей (`schemaPerUnit`, `schema`) и описания (`JsonSchema`, путь `/units/{uid}/schema`). Мы пишем и w2c: схема вида `det` — данные детекторов, которые w2c смотрит в профиле `vms.detector/1`.

- Контракт 0.43.0: [`api/openapi.json`](../openapi.json) — расширение `x-ui-manual` в описании `JsonSchema`; описание `getUnitSchema` называет детектор. Раздел «Что добавлено в 0.43.0» в [`api/README.md`](../README.md).
- Набор `demo` ([`api/fixtures/demo.json`](../fixtures/demo.json)): у вида `det` есть `schemaPerUnit: true`, `schema.allOf` из 13 частей. Первая часть без условия даёт всем полям группу (`x-ui-group`), порядок (`x-ui-order`) и подсказку (`description`). 12 частей семейств с условием по `detectorKind` и `analyticsKind` прячут чужие поля (`x-hidden`) и ставят `x-ui-manual`.
- Сервер не меняется: `GET /units/{uid}/schema` уже решает `allOf` для вида со `schemaPerUnit`.
- `tools/profile_fixture.py` убирает из `allOf` снятые свойства и части с условием по ним (наборы `one-domain`, `large`, `xl`). `tools/check_api.py` знает `x-ui-manual`.
- Тест: `tests/api-devices.js`, «Схема объекта детектора по семейству (0.43.0)…» — слой `profile:vms.detector/1`.
- Интерфейс: `index.html`, форма «Все параметры» детектора (`detUnitSchema`, `detSheetLeadHtml`, `sfFieldHtml`), из прототипа 112.

## Что проверить

1. **`x-ui-manual`** (boolean) в свойстве схемы: значение надо задать вручную. Интерфейс показывает у поля без значения «Не задано». Сервер это не проверяет: объект без значения сохраняется без отказа.
2. **`schemaPerUnit` у вида `det`**: схема объекта зависит от `detectorKind` и `analyticsKind`. `GET /units/{uid}/schema` у детектора теперь отдаёт 200, а не `422 NOT_SUPPORTED`.
3. **Поля `x-ui-manual`**: «Размер человека» (`humanSize`) у скопления людей, «Положение камеры» (`cameraPosition`) у трекера объектов, «Ширина номера» (`plateWidth`) у распознавания номеров, «Запросы» (`metaQueries`) у мета-детектора, «Область 2» (`zoneTo`) у счётчика посетителей. Совпадает ли это с `NeedManualAdjustment` у вашего бэкенда?
4. **Схема вида не строже.** Свойства и `required` вида `det` не изменились; части `allOf` несут только пометки. Проверка правки — как в 0.42.0.

## Сверх запросов

- `x-ui-manual`, а не `required` в части семейства: `required` в ветке — новый отказ на прежнем запросе, то есть ломающая правка.
- Пустой `description` в первой части снимает подсказку: заметка контракта к свойству (для разработчиков) — не подсказка в интерфейсе.
- Детектор вне перечня (`other` без известного `analyticsKind`) получает все поля вида; интерфейс показывает для него форму вида, как раньше.
- `drvOn` в `index.html` не берёт детекторы: параметры драйвера — только у камеры, хотя у `det` теперь тоже есть `schemaPerUnit`.
