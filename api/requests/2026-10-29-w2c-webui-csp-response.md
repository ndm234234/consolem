### Сборка

`python3 tools/build_webui.py` собирает файлы в `build/webui/`, с `--out <папка>` — в указанную папку. Сборка повторяемая: из одного коммита всегда получаются одни и те же байты. Значит, хэши в `MANIFEST.json` у вас и у нас совпадут.

| Файл | Тип | Назначение |
|---|---|---|
| `index.html` | `text/html` | входная страница: разметка без встроенного кода, подключает остальные файлы |
| `app.js` | `text/javascript` | интерфейс |
| `app.css` | `text/css` | стили: свои и дизайн-системы, один файл без `@import` |
| `client.js` | `text/javascript` | клиент API: запросы, `If-Match`, поток событий, `401` → вход |
| `openapi.js` | `text/javascript` | контракт: по нему интерфейс знает, какие поля записи можно менять и какая операция нужна каждой кнопке |
| `i18n-en.js` | `text/javascript` | английские подписи |
| `fonts/InterVariable.woff2` | `font/woff2` | шрифт |

`MANIFEST.json` — `[{name, type, purpose, size, sha256}]`, SHA-256 в hex, по одной записи на файл. Самого `MANIFEST.json` в списке нет. Сейчас в сборке 7 файлов, около 2,2 МБ.

Как просили:
- имена файлов постоянные;
- картинок `logo-configurator.png` и `one-sign.svg` нет;
- встроенного тестового сервера, наборов данных и самопроверки в сборке нет.

**Ссылки с `?v=`.** Входная страница подключает файлы как `app.js?v=<первые 12 знаков SHA-256>`: так браузер не возьмёт из кэша файл прошлой сборки. Ваш сервер должен отдавать файл по имени без учёта строки запроса.

### Адрес API и вход

В `index.html` сборки есть две строки:

```html
<meta name="consolem-api" content="api">
<meta name="consolem-login" content="../">
```

- Оба адреса считаются относительно страницы. Для `/backend/` запросы идут на `/backend/api/…`, поток — на `/backend/api/stream`, вход — на `/`.
- Ответ `401` на любой запрос переводит на `consolem-login`. Переход делается один раз, даже если таких ответов пришло несколько.
- Если поток закрылся и браузер не переподключает его сам (ответ не `200`), клиент запрашивает `GET /me`. На `401` он переводит на вход, иначе подключается заново через 3 с и перечитывает данные.
- Запросы идут с `credentials: "include"`. Страница и API у вас на одном адресе, поэтому CORS не нужен.

Без этих `meta` (макет на GitHub Pages, страница с диска) всё работает по-прежнему: со встроенным сервером или с `?api=…`.

### Как проверить

- **`python3 tools/check_webui.py`.** Собирает во временную папку и поднимает наш стенд в роли консоли: `node tools/serve_api.mjs --webui <папка>`. Сборка отдаётся под `/backend/` с заголовком `Content-Security-Policy: script-src 'self'; object-src 'none'; base-uri 'none'` без добавлений, API — под `/backend/api/`. Затем открывает `/backend/?selftest` в Chrome. Проверка не проходит, если не прошёл хоть один сценарий или браузер сообщил о нарушении политики. Сейчас: 268 из 268, нарушений 0. Если подложить в сборку встроенный `<script>` или `onclick`, проверка их ловит.
- **Руками:** `python3 tools/build_webui.py`, затем `node tools/serve_api.mjs 8787 --webui build/webui` → http://127.0.0.1:8787/backend/. С диска сборка не открывается: API у неё на сервере консоли.
- **Переход на вход** проверен на сервере, который отвечает `401` на любой запрос API: страница уходит на `../`.

## П. 2. Ограничение версии устройства — закрыт

Вы делаете пакетную запись: все части устройства пишутся одной операцией, а остальные части проверяются по снимку. Тогда `If-Match` означает версию всего устройства, и одновременная правка любой его части даёт `412`. Это строже, чем мы просили. Допущение в [BACKEND.md](../BACKEND.md) не записываем: контракт и так говорит, что `412` значит «ничего не изменилось». То же для строки `failed` в `/devices/update` и шага `fail` в `/operations`.

Тесты `412` остаются прежними. Когда пакетная запись появится в стенде, `python3 tools/check_stand.py https://адрес-стенда` проверит её вместе со всем остальным.
