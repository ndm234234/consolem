# Запрос от команды ngp: карточка показывает черновое имя после переименования из дерева

2026-11-19 · коммит контракта `564ba43` (0.35.0; ссылки пересчитаны 2026-11-20, первая редакция — `590e3cc`) · от команды ngp (бэкенд конфигуратора поверх NGP)

Кому: владелец контракта

**Статус: новый**

## Зачем

При ручном прогоне WebUI (прототип 1.3, поддельный NGP, два экземпляра бэкенда) камеру переименовали через меню дерева ⋮ → «Переименовать». Дерево этой вкладки и вторая вкладка показали новое имя, а карточка камеры в этой вкладке — прежнее. Бэкенд принял `PATCH` и ответил `200`, событие дошло до второй вкладки. Значит, расхождение возникает только в состоянии вкладки, из которой переименовали.

Как воспроизвести (повторяется каждый раз):

1. Открыть карточку камеры «Главный вход». В блоке «Идентификация» нажать «Изменить», ввести имя «Ч1», нажать «Добавить в план». План не применять.
2. В дереве у той же камеры ⋮ → «Переименовать» → «M4» → Enter.
3. `PATCH /units/{uid}` отвечает `200`, в дереве и на сервере имя «M4». Карточка показывает «Ч1» с пометкой «изменено», строка дерева — «не применено».

Состояние страницы после шага 3 (снято в консоли браузера): `n.name = "M4"`, снимок карточки `cardBase.snap.name = "M4"`, черновик `cardDraft.fields["Имя"] = {from: "M3", to: "Ч1"}`. Здесь «M3» — имя до шага 2.

Почему так:

* Карточка выводит имя через черновик: `cardFldVal` (`index.html:9265`) возвращает `to` из черновика, если поле в нём есть. Ответ `PATCH` из дерева обновляет объект и снимок (`commitTreeRename` → `hwApplyUnit`, `index.html:10891-10892`; `hwFresh`, `index.html:5961-5971`), но черновик не трогает.
* Строка плана берёт «Было» из `from` черновика (`index.html:9334`). По коду план покажет «M3 → Ч1», хотя на сервере уже «M4». Применение плана запишет «Ч1» поверх «M4», и пользователь не увидит, что затирает чужое переименование. Это мы вывели из кода и в браузере не проверяли.

Черновик тут не ошибка сам по себе: пользователь сам добавил правку в план. Неудобно другое: имя поменялось на сервере, а WebUI об этом не сообщает. Неприменённую правку легко забыть: шаг 2.6 сценария показа как раз оставляет её, если не дойти до «Сохранить».

## Пункты

1. **Конфликт с черновиком.** Когда с сервера приходит новое значение поля, которое есть в черновике карточки, предлагаем показывать это пользователю. Например: пометка «на сервере изменено: M4» у поля и выбор «оставить мою правку» или «взять с сервера».
2. **«Было» в плане — по снимку.** Предлагаем брать «Было» в строке плана из снимка карточки (`cardBase.snap`), а не из `from` черновика. Тогда план покажет «M4 → Ч1», и пользователь увидит, что затирает.
3. **Переименование из дерева при черновике имени.** Если у объекта в черновике карточки есть поле «Имя», предлагаем при переименовании из дерева убирать это поле из черновика или спрашивать пользователя.
