## Что мы сделали

Мы закрыли пункт `F85` отчёта [`docs/axxon-one-gaps.html`](../../docs/axxon-one-gaps.html) («Сервер в домене: исключить сервер из домена»). Исходного запроса нет: пункт ждал поля `Me`, а данные сервера — поле профиля `vms.server/1`, его ведёт mockup. В Axxon One исключение удаляет макросы, раскладки, карты, группы объектов, роли и пользователей, которые создали на сервере. Клиент, который вошёл через этот сервер, выгружает интерфейс и просит войти снова (документ «Removing a Server from a domain», Axxon One 3.0).

- Контракт 0.39.0 ([`api/README.md`](../README.md), «Что добавлено в 0.39.0»; [`api/BACKEND.md`](../BACKEND.md), «Исключение сервера из домена»).
- Профиль `vms.server/1` 1.2 ([`api/profiles/vms.server.json`](../profiles/vms.server.json)): `status.observed.ownConfig`.
- Тест — `tests/api-domains.js`, «Серверы: ownConfig — исключение обнуляет числа, откат их не возвращает; Me.serverId — сервер сессии».
- Интерфейс — прототип 101 ([`index_101_preduprezhdenie-isklyucheniya.html`](../../index_101_preduprezhdenie-isklyucheniya.html), на Pages: https://ndm234234.github.io/consolem/index_101_preduprezhdenie-isklyucheniya.html).

## Что проверить

1. **`status.observed.ownConfig`** (профиль `vms.server/1` 1.2, кому — w2c). Объект с шестью целыми числами от 0: `macros`, `layouts`, `maps`, `groups`, `roles`, `users`. Все шесть сразу или поля нет (`absent: unsupported`). Исключение (`move`, `parentId: null`) и перенос в другой домен удаляют это: после этого все числа 0, откат переноса их не возвращает. Ваш бэкенд может считать эти числа на сервере?
2. **`Me.serverId`** (кому — владелец контракта). Необязательное поле: uid сервера, через который вошла сессия. Поле VMS в общей схеме `Me`: мы поставили `x-layer: vms.server/1` и добавили его в `KNOWN_LEAKS` (`tools/layers.py`). Подходит ли такое место, или вы хотите поле в другой схеме?
3. **Сессия после исключения сервера сессии.** Встроенный сервер сессию не закрывает: после исключения он отвечает как раньше, выход делает клиент. Настоящая система, скорее всего, ответит `401` на следующий запрос. Мы не описали этот отказ в контракте: новый отказ на прежнем запросе — ломающая правка. Нужно ли описать его вам?

## Сверх запросов

- Решение mockup: числа — в status сервера, а не в ответе пробного переноса (`dryRun`). Так окно получает их вместе с сервером, без нового пути.
- Перенос распределённого сервера в другой домен тоже обнуляет `ownConfig`: в Axxon One это исключение и новый приём.
