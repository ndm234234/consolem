## Что проверить

1. **`alarmEndSec`** (integer, 0–600): сколько секунд событие длится после того, как условие пропало. Нет поля — 10. Детектор движения, оставленные предметы, скопление.
2. **`analysisFps`** (number, 0,1–100): сколько кадров в секунду детектор разбирает. Нет поля — умолчание детектора: 12 у детектора движения и трекера объектов, 6 у нейросетевого трекера.
3. **`frameWidth`** (integer, одно из 0, 640, 1280, 1920): до какой ширины сервер сжимает кадр перед анализом; 0 — без сжатия. Нет поля — 1280.
4. **`abandonedSensitivity`** (integer, 1–100): чувствительность трекера объектов к оставленным предметам; действует, когда поиск идёт (`detectUnattendedObjects`). Нет поля — 9.
5. **`objectSpeed {min, max}`** (number, 0–500): условная скорость объекта Axxon One. Нет поля или части — без ограничения. min выше max — `422 VALIDATION_FAILED`, `field: /properties/objectSpeed/min`, `params.reason: minAboveMax`.
6. **Нет возможности.** У всех пяти полей `absent: unsupported`: система без такой возможности не кладёт поле в схему вида, и консоль поле не показывает. Есть ли эти поля у вашего бэкенда?

## Сверх запросов

- Имя `analysisFps`, а не `fps`: у камеры и потока уже есть `fps`, а одно имя с другим смыслом путает клиента, который читает свойства объекта без вида.
- `frameWidth` — перечень из четырёх значений, как в Axxon One, а не любое число.
- Сервер не отклоняет поле у чужого семейства (например, `abandonedSensitivity` у детектора движения): хранит его, как другие поля детектора. Какое поле у какого семейства — смысл поля в профиле.
- Пределы `alarmEndSec` (до 600 с) и `analysisFps` (0,1–100) выбрали мы: документация Axxon One их не называет.
