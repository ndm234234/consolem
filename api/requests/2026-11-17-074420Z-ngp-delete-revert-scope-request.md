# Запрос от команды ngp: какие удаления откатываются

2026-11-17 · коммит контракта `564ba43` (0.35.0; ссылки пересчитаны 2026-11-20, первая редакция — `590e3cc`) · от команды ngp (бэкенд конфигуратора поверх NGP)

Кому: владелец контракта

**Статус: новый**

## Зачем

Прототип 1.3 добавляет `deleteUnit`, `deleteObjects` и шаг `delete`. Нужно отличить объекты, которые `revertOperation` возвращает, от объектов, для которых шаг отката должен завершиться `fail NOT_SUPPORTED`.

`BACKEND.md:119` говорит общей фразой: «Удаление … не откатывается: шаг `fail NOT_SUPPORTED`». Тесты камеры и хранилищ подтверждают это правило (`tests/api-hardware.js:447-459`, `tests/api-storage.js:187-203`, `:335-345`). Но тест универсального ядра требует обратное: восстановить родителя и ребёнка с прежними uid, свойствами, секретом и папками (`tests/api-units.js:772-801`), а групповое удаление также откатить (`:803-814`). Удалённый поддетектор тоже возвращается (`tests/api-devices.js:823-832`). Образец реализует восстановление через `unitRestore` (`api/server.js:3871-3888`).

## Пункты

1. **Область правила.** Верно ли, что `NOT_SUPPORTED` относится только к удалению видов с профильным обработчиком VMS (камера, хранилище), а ядро восстанавливает остальные виды и поддетекторы? Просим явно перечислить исключения или признак в `UnitKind`, по которому бакенд выбирает поведение.
2. **Формулировка контракта.** Просим уточнить `BACKEND.md:119`, чтобы общее правило не противоречило обязательным тестам ядра.
3. **Снимок удаления.** Если восстановление обязательно для `det` и `subdet` NGP, подтвердить, что бакенд обязан хранить полное поддерево, секреты, папки и очищенные ссылки до отката. Отдельно просим тест для удаления обычного `det`, потому что сейчас восстановление проверяется только для `subdet` и тестовых видов.

Для NGP это важно: удалённый серверный детектор `AVDetector` нельзя вернуть с прежним uid — NGP выдаёт новый (`../ngp.axxon/BL/NativeBL/DetectorConfigurator.cpp:2117-2124`). Если восстановление `det` обязательно, бакенд сможет вернуть только новый объект с теми же свойствами.

До ответа реализация различает доказанные тестами случаи: камеру и хранилища не восстанавливает; тестовые виды ядра и `subdet` восстанавливает. Поведение обычного `det` остаётся открытым.
