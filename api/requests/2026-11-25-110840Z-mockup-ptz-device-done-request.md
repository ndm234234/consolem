## Что проверить

1. **Новые поля камеры (профиль 1.1):**
   - `ptzEnabled` — флажок, нет поля — включён;
   - `ptzSource` — `self` (сама камера, её драйвер) или `port` (порт другого устройства), нет поля — `self`;
   - `ptzPort` — `{unitId, port}` или `null`: `unitId` — `x-ref` на `server` или `channel`, `port` — имя порта, `examples` `RS-485`, `COM1`, `COM2`;
   - `ptzProtocol` — строка без умолчания, `examples` — `Pelco-D`, `Pelco-P` и другие;
   - `ptzAddress` — целое 0–255, нет поля — 1.

   Скорость и чётность линии в камеру не входят: они у порта. Ваш бэкенд хранит эти поля? Какие порты и протоколы он знает?
2. **Новый отказ сервера.** При `ptzEnabled: false` аренда движения (`PUT /units/{uid}/ptz`) и запись положения пресета (`PUT /units/{uid}/presets/{n} {}`) отвечают `422 NOT_SUPPORTED`, `field: /properties/ptzEnabled`. Подпись пресета (`PUT {name}`) и `DELETE` поле не судит. Прежний запрос отказа не получает: до 1.1 поля не было, умолчание — включён. Для этого в `api/server.js` в `SUBJECT_POINTER` добавлен `ptzEnabled`.
3. **`ptz` при телеметрии через порт.** Мы написали в смысле `ptzSource`: сервер, который подключил устройство на порту, ставит камере `ptz: true`. Встроенный сервер этого не делает: камерами он не движет. Это верно для вашего бэкенда?
4. **Параметры драйвера PTZ без `x-dev` — меняет п. 2 уведомления [142629Z](2026-11-24-142629Z-mockup-camera-streams-mode-done-request.md).** У девяти параметров группы `group.camera.ptz` (`defaultEnablePatrol`, `homePreset`, `homePresetTimeout`, `savePresetsOnDevice`, `useDevicePresets`, `enableMultipleControl`, `discreteOverContinous`, `patrolTimeout`, `patrolSpeed`) снят `x-dev`. Снята и часть `allOf`, которая делала их только для чтения при `streamsMode: device`. В п. 2 уведомления 142629Z сказано «их три … у PTZ ещё ptz»: теперь таких частей две. Причина: патрулирование и предустановки хранит сервер (Axxon One хранит их в объекте PTZ), в устройство они не идут. Подпись группы теперь «Патрулирование и предустановки».
