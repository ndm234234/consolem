# Запрос от команды mockup: отказ `NO_SPACE` на том больше свободного места диска

2026-11-25 · коммит `9f19008` · от команды mockup

Кому: владелец контракта, w2c

**Статус: новый**

## Зачем

Пункт `F92` отчёта о пробелах против Axxon One ([`docs/axxon-one-gaps.html`](../../docs/axxon-one-gaps.html)): «Размер тома архива». Axxon One не даёт создать том больше свободного места диска: ошибка «Free disk space is not enough to create new archives» (axxonnext.ui `ArchiveSizeValidator`). Свободное место консоль теперь получает в профиле `vms.server/1` 1.3 (`status.observed.disks[].freeBytes`) и проверяет размер сама, до плана (прототип 102). Сервер такой том принимает. Сегодня `POST /units` и `patch` с `sizeBytes` больше свободного места проходят без отказа.

Новый отказ на прежний запрос — ломающая правка (скилл `api-contract`, «Правка контракта без владельца», п. 1). Поэтому мы просим, а не делаем.

## Что нужно

1. **Код `NO_SPACE` в `ProblemCode`.** Сервер отвечает `422 NO_SPACE`, `field: /properties/sizeBytes`, когда том на диске сервера (адрес `disk`, размещение «папка» или «файл») больше свободного места диска. Свободное место для тома, который уже есть на диске, включает его же нынешний объём. В `params` — `freeBytes` и `disk`, чтобы консоль назвала число и диск.
2. **Где действует.** `POST /units` (том и хранилище с первым томом), `patch` тома с большим `sizeBytes` и шаги `create` и `patch` в `POST /operations`: шаг получает `fail NO_SPACE`, остальные шаги идут по правилам частичного успеха.
3. **Где не действует.** Раздел целиком (`mode: part`): его объём — весь диск. Тома сетевого и облачного хранилищ: у них нет диска сервера.

## Что сломается у тех, кто уже работает по контракту

- Клиент, который создаёт том больше свободного места, получит отказ, а не том. Консоль (`index.html` после переноса прототипа 102) такой запрос не шлёт: она проверяет размер до плана.
- Бэкенд без свободного места дисков (нет `freeBytes`) отказ не делает: проверять не по чему.
- Тест в `tests/api-storage.js` с новым отказом будет строже к прежнему поведению. Его слой — `profile:vms.volume/1` со `since` новой версии профиля.
