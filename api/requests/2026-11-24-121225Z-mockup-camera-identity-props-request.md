## Почему этот запрос

Основа — пункт `F31` отчёта о пробелах против Axxon One ([`docs/axxon-one-gaps.html`](../../docs/axxon-one-gaps.html), функция `cam-008` страницы покрытия). Владелец макета (Maxim Kabenin) решил написать на него запрос.

Консоль по-настоящему настраивает у камеры адрес, порт, MAC, производителя, модель, логин и пароль. Прошивка, версия драйвера, серийный номер, комментарий и тип камеры живут в заглушке `camDrvSchema0` (`index.html`, блок «Идентификация»). Блокировка конфигурации тоже заглушка (`cvCfgOf(n).mode`).

Источники Axxon One:
- свойства `DeviceIpint`: `firmware`, `driverVersion`, `deviceSerialNumber` (только Axis), `blockingConfiguration` — Lexiro, QA Confluence «Протокол gRPC», «Properties of DeviceIpint:1» (doc 297870); ИнтеллектX 5.5, «Работа с устройствами через gRPC API», «Получение информации об устройстве» (doc 85824);
- `ModelDisplayName` («Отображаемое имя модели») и `BlockingConfiguration` — `axxonnext.ui` `IpDeviceUnitTypeDescriptor.cs`, `CameraTypeDescriptor.cs`; `model_display_name` — `web-configurator` `showUnitSettings.ts`, `constants.ts`;
- `BlockingConfiguration` «соответствует чекбоксу "отправлять настройки устройству" в клиенте» — DevDep Confluence, «RSG HTTP API», «ipint» (doc 103984). Имя свойства в gRPC — «Preserve device settings», в `ListUnitsStream` — «Использовать настройки устройства» (doc 119000).

Что уже решено и в запрос не входит:
- **Широта, долгота, азимут.** В контракте они есть: `lat`, `lon`, `azimuth` у вида `camera`. Заглушка `geoLocationLatitude`… на карточке — ошибка интерфейса. Её исправит mockup в `index.html`.
- **Группы камер** контракт даёт папками: `Unit.folders`.
- **Параметры драйвера** (буфер, RTSP, резервное отображение и другие) — данные стенда по [ответу о параметрах драйвера камеры](2026-11-09-182805Z-mockup-camera-driver-params-response.md), п. 6. `schemaPerUnit: true` у камеры mockup ещё не сделал.

## 1. `firmware` — прошивка устройства, а версия драйвера — новое поле `driverVersion`

- **Что нужно.**
  - `firmware` у вида `camera` и в профиле `vms.camera/1` значит прошивку устройства: что сообщает камера, только для чтения (`readOnly`).
  - Новое необязательное поле `driverVersion` (строка, `readOnly`) — версия драйвера, через который сервер работает с камерой.
- **Зачем.** Сейчас описание `firmware` — «Версия драйвера. Обновления прошивки нет» (так ответил владелец на запрос [2026-11-01 о записи](2026-11-01-135335Z-w2c-recording-detectors-ptz-archives-response.md)). В Axxon One это два разных свойства `DeviceIpint`: `firmware` и `driverVersion`. Карточка показывает оба, и пользователь отличает их.
- **Что сломается.** Смысл прежнего поля меняется. Это ломающая правка, поэтому её делает владелец.
  - w2c: в `firmware` бэкенд отдаёт версию драйвера. После правки бэкенд отдаёт в `firmware` прошивку, а версию драйвера — в `driverVersion`.
  - `configMode: template` копирует `firmware` (описание `templateId`). Прошивку копировать нельзя: её сообщает камера. Из описания `templateId` и из `meaning` в профиле `firmware` надо убрать.
  - `index.html` поле `firmware` из записи не показывает: карточка берёт значение из заглушки.
- **Вариант без ломающей правки.** `firmware` остаётся версией драйвера с `deprecated: true`, а прошивка приходит новым полем, например `deviceFirmware`. Решение за владельцем.

## 2. `modelDisplayName` — отображаемое имя модели

- **Что нужно.** Необязательное поле `modelDisplayName` (строка, `readOnly`) у вида `camera`: имя модели из каталога устройств для показа. `model` остаётся ключом модели для `probe` и подключения.
- **Зачем.** В Axxon One `ModelDisplayName` — отдельное свойство (`IpDeviceUnitTypeDescriptor.cs`). Ключ модели и имя для показа бывают разными, например у моделей `generic`. Сейчас карточка показывает ключ `model`.
- **Что сломается.** Ничего, поле новое. Нет поля — интерфейс показывает `model`, как сейчас.
- **Вопрос.** Это поле профиля `vms.camera/1` (его ведёт mockup, смотрит w2c) или данные стенда? Если поле профиля — w2c, ваш бэкенд может отдать это имя?

## 3. `deviceSerialNumber`, `cameraType`, `comment` — поля профиля или данные драйвера?

- **Что нужно.** Решение, где живут эти поля:
  - `deviceSerialNumber` (строка, `readOnly`) — серийный номер устройства. В Axxon One он есть только у драйвера Axis; после «Применить» устройство переподключается, и сервер сверяет номер с настоящим;
  - `cameraType` (`""`, `bullet`, `speed_dome`, `fix_dome`; правится) — тип камеры;
  - `comment` (строка, правится) — комментарий к камере.
- **Вариант A — данные стенда** по п. 6 ответа о параметрах драйвера: поля приходят схемой объекта (`schemaPerUnit`), в `api/openapi.json` и в профиль их не вносят. Этот вариант подходит к `deviceSerialNumber`: поле есть только у одного драйвера.
- **Вариант B — поля профиля `vms.camera/1`.** Этот вариант подходит к `comment` и `cameraType`: они не зависят от драйвера. Для `comment` возможно и общее поле объекта (`Unit`), если оно нужно другим видам.
- **Что сломается.** Ничего: в обоих вариантах поля новые и необязательные.
- **Предложение mockup.** `deviceSerialNumber` — вариант A; `cameraType` и `comment` — вариант B. После ответа mockup сделает это сам и уведомит владельца.

## 4. Блокировка конфигурации — это `streamsMode`?

- **Что нужно.** Подтверждение, что `streamsMode` из [ответа о вкладке «Видео»](2026-11-08-174207Z-mockup-camera-video-streams-tours-response.md), п. 1, — это `blockingConfiguration` Axxon One, и отдельного признака не нужно. Мы понимаем соответствие так: `streamsMode: device` ↔ `blockingConfiguration: true` («Использовать настройки устройства»), `streamsMode: console` ↔ `false`.
- **Зачем.** Карточка Axxon One показывает «Блокировку конфигурации» в блоке подключения, а консоль — флажок «Отправлять настройки устройству» в строке вкладок. Это один признак. Два поля разошлись бы.
- **Что сломается.** Ничего: `streamsMode` ещё не в наборе. mockup добавит его после `schemaPerUnit` у камеры, по условиям того ответа.
- **w2c.** Если ваш бэкенд работает с Axxon One, `streamsMode` — это `blockingConfiguration` устройства. Соответствие верное?

## Что в `index.html` сейчас

- `camDrvSchema0`: `firmware`, `driverVersion`, `deviceSerialNumber`, `cameraType`, `comment` — значения по умолчанию заглушки, в браузере (`drvStore`).
- `cvCfgOf(n).mode` — заглушка флажка «Отправлять настройки устройству».
- Поля подключения — `camConnHtml`, `camConnSet`: адрес, порт, MAC, производитель, модель, логин, пароль идут через `PATCH /units/{uid}`.
