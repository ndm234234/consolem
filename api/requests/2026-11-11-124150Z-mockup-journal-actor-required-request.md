# Запрос от команды mockup: автор у каждой записи журнала — сделать actor обязательным

2026-11-11 · коммит контракта `f3ac8f4` (0.9.0) · от команды mockup, для владельца контракта

Кому: владелец контракта

**Статус: новый**

## Зачем

Пользователь команды mockup (Maxim Kabenin) требует, чтобы в журнале аудита у каждой записи был автор: «обязательно кто». Так устроены журналы аудита других систем: запись без автора нельзя использовать при разборе инцидента.

В 0.9.0 мы сделали всё, что можно сделать без ломающей правки:

- возможность `journalAudit`: система с ней заполняет `actor` у каждой записи (логин или «система») и пишет запись аудита на каждое изменение через API;
- встроенный сервер её объявляет, тесты `tests/api-journal.js` проверяют `actor` только при ней.

Без ломающей правки `actor` остаётся необязательным: бэкенд без `journalAudit` может не заполнять его.

## Что нужно

1. **`JournalEvent.actor` — в `required`.** Значение — логин пользователя или «система» (события оборудования, расписаний, правил без человека). Пустая строка — нельзя.
2. **Описание поля.** Убрать «Нет поля — автор неизвестен или это не действие человека». Действие не человека — «система».
3. **Тест.** В `tests/api-journal.js` проверку «автор у каждой записи» снять с условия `feature:journalAudit`, оставить на `listJournal`.
4. **Решить про `journalAudit`.** Либо оставить возможность для аудита изменений и `prevCursor`, либо сделать и их обязательными тем же изменением.

## Что сломается у тех, кто уже работает по контракту

- Бэкенд, который отдаёт записи журнала без `actor`, перестанет проходить тест и схему ответа. Ему нужно заполнять `actor` у каждой записи, в том числе у старых записей в БД: при чтении — «система», если автора нет.
- Клиенты не сломаются: поле уже есть с 0.8.0, интерфейс показывает «—», если его нет.
