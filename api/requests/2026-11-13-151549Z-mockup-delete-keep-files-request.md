# Запрос от команды mockup: удаление хранилища и тома с сохранением файлов

2026-11-13 · коммит контракта `f080e13` (0.12.0) · от команды mockup, для владельца контракта

Кому: владелец контракта

**Статус: новый**

## Зачем

Пробел B5 против Axxon One (`docs/axxon-one-gaps.html`): администратор удаляет хранилище или том и
решает, что делать с записями — удалить файлы или оставить их для нового хранилища. Это обратная
сторона пробела B4 (запрос `2026-11-12-144153Z-mockup-existing-volumes-request.md`): B4 подключает
тома с записями, B5 эти записи сохраняет.

Источники:
- Документация Axxon One 3.0, «Removing archives» (lexiro doc 292116) и «Removing archive volumes»
  (doc 292115): при удалении архива и тома администратор отмечает флажок на удаление файлов.
  «If you don't delete archive files, you can re-use them to create another archive». Там же:
  «If there is only one volume in the archive, you cannot remove it».
- Код клиента Axxon One (Bitbucket `ONE/axxonnext.ui`, коммит `603a05a1b53b`): у блочного тома
  свойство `remove_file` (`ArchiveBlockVolumeUnitTypeDescriptor`), у объектного —
  `erase_volume_data` (`ArchiveObjectVolumeUnitTypeDescriptor`).
  `ArchiveTypeDescriptor.RemoveVolumeFiles` ставит оба признака всем удаляемым томам архива.
  Признак уходит на сервер в `DestructionArgs` удаляемого объекта. Страницы документации и код
  не делят это правило на блочное и объектное хранение: оно общее.

Сейчас в контракте 0.12.0 у `DELETE /units/{uid}` есть только `moveTo`. Признака «что делать с
файлами» нет ни у хранилища (вид `archive.*`), ни у тома (вид `volume`), поэтому макет не может
сказать серверу, что файлы нужно оставить.

Прототип 67 (`index_67_udalenie-s-failami.html`) показывает это на заглушке: окно подтверждения
даёт две радиокнопки — «Оставить файлы записей» (по умолчанию) и «Удалить файлы записей», — а
выбор живёт в памяти страницы и на сервер не уходит. Пункт «Удалить том» у последнего тома
прототип делает неактивным и считает это сам, по списку томов хранилища.

## Пункты

1. **Признак «что делать с файлами» при удалении.** Параметр у `DELETE /units/{uid}` для видов
   `archive.*` и `volume`, например `keepFiles=true`: сервер снимает объект из конфигурации, а
   файлы записей (раздел SolidStore, файл `.afs`, папку NAS, объекты в папке бакета) оставляет.
   Умолчание — `false`, прежнее поведение: сервер удаляет файлы вместе с объектом. Параметр
   действует одинаково для блочного и объектного хранения (`storage: "block"` и `storage: "object"`),
   у локального, сетевого и облачного хранилища.
2. **Хранилище передаёт признак своим томам.** `keepFiles=true` у хранилища означает то же для
   каждого его тома: так это сделано в клиенте Axxon One (`ArchiveTypeDescriptor.RemoveVolumeFiles`).
3. **Запрет на удаление последнего тома.** Сервер отказывает на `DELETE` последнего тома
   хранилища: `422` с понятным `code` (например `volume.last`), `field` — `/uid`. Хранилище без
   томов писать не может, поэтому администратор удаляет хранилище целиком. Сейчас макет считает
   это сам, по списку томов.
4. **Оставленные файлы видны в поиске томов.** Том, удалённый с `keepFiles=true`, попадает в список
   найденных томов с записями (пункт 2 запроса `2026-11-12-144153Z-mockup-existing-volumes-request.md`),
   поэтому новое хранилище может подключить его.
5. **Групповое удаление.** То же поле у `POST /objects/delete` (у `ObjectsDeleteRequest.items` сейчас только
   `id` и `version`, `additionalProperties: false`): прототип даёт выбор по файлам и в групповом окне.
6. **Тесты:** `DELETE` тома с `keepFiles=true` оставляет файлы, и том виден как найденный;
   без параметра — прежнее поведение; `DELETE` последнего тома — `422`.

## Что сломается у тех, кто работает по контракту

Пункты 1, 2, 4, 5 и 6 — новый необязательный параметр, умолчание сохраняет прежнее поведение.
Интерфейс открывает окно на «оставить файлы», а умолчание сервера — удалить. Поэтому консоль будет
слать `keepFiles` всегда, явным значением.
Пункт 3 — ломающая правка: прежний запрос (удаление последнего тома) получит новый отказ.
Поэтому пункт 3 делает владелец контракта. Если отказ не нужен, скажите об этом в ответе: макет
оставит запрет только в интерфейсе.
