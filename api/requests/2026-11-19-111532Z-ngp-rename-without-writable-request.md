# Запрос от команды ngp: «Переименовать» предлагается объекту, у которого имя нельзя менять

2026-11-19 · коммит контракта `564ba43` (0.35.0; ссылки пересчитаны 2026-11-20, первая редакция — `590e3cc`) · от команды ngp (бэкенд конфигуратора поверх NGP)

Кому: владелец контракта

**Статус: новый**

## Зачем

Наш бэкенд пока не умеет переименовывать папки. У папки он отдаёт `writable: []`, а на `PATCH` с `name` отвечает `422 NOT_SUPPORTED`, `field: /name`. При ручном прогоне WebUI (прототип 1.3, поддельный NGP) меню папки всё равно предложило «Переименовать». После ввода имени и Enter поле ввода осталось открытым с новым именем. Сообщения об отказе в прогоне не заметили (скриншот прогона, `docs/прогоны/2026-11-19-удаление-хранилище-папки/screens/38-pereimenovanie-zavislo.jpg` в репозитории `configurator-backend`). После Esc вернулось прежнее имя.

Как воспроизвести: дерево → папка → «Ещё» → «Переименовать» → новое имя → Enter.

Почему так:

* Пункт «Переименовать» в меню дерева показывается по типу узла, без проверки `writable`: `canRename` (`index.html:13340`) включает любую папку, домен, сервер и архив.
* При отказе `commitTreeRename` вызывает `toast(problemText(e, f.n))` и снова ставит фокус в поле ввода (`index.html:10896-10903`). Поле остаётся открытым, пока пользователь не нажмёт Esc. Для `NOT_SUPPORTED` повтор не поможет. С 0.35.0 поле закрывается только при отказе с `params.kept` (`problemKept`, `index.html:6459`); у `NOT_SUPPORTED` такого параметра нет.

Похожий запрос уже есть для карточки: «Ручной экран показывает поля ввода, когда записи нет» (`2026-11-14-195811Z-ngp-writable-without-patch-request.md`). Этот запрос — про меню дерева.

## Пункты

1. **«Переименовать» по `writable`.** Предлагаем показывать пункт, только если `name` есть в `writable` объекта, а для короткого имени — `short`. Без записи пункт скрыт или недоступен с причиной, как другие недоступные пункты меню.
2. **`NOT_SUPPORTED` закрывает поле.** При отказе `NOT_SUPPORTED` закрывать поле ввода, возвращать прежнее имя и показывать причину, а не оставлять поле открытым для повтора.
