# Запрос от команды mockup: допустить `Discovery.ipScanMax` = 0

2026-11-23 · контракт 0.36.0 · от команды mockup

Кому: владелец контракта

**Статус: новый**

Основа — сверка w2c по полям профилей в [ответе на запрос 154325Z](2026-11-18-154325Z-owner-profile-files-response.md), п. 3.1, строка `vms.discovery/1`. Профиль `vms.discovery/1` ведёт mockup, но поле лежит в схеме `Discovery` в `api/openapi.json` (слой `vms.discovery/1`). Новое значение в поле ответа — ломающая правка (скилл `api-contract`, «Правка контракта без владельца», п. 1). Поэтому мы не правим поле сами и просим владельца.

## 1. `ipScanMax`: `minimum` 0 вместо 1

- **Что нужно.** В схеме `Discovery` у `ipScanMax` — `minimum: 0`. Описание: «0 — сервер не перебирает адреса: поиск идёт по подсетям серверов».
- **Зачем.** Поиск w2c идёт по подсетям серверов и не перебирает диапазоны адресов. Предела адресов у w2c нет, а поле обязательное. Сейчас w2c должен отдать число, которого у него нет.
- **Что сломается.** Клиент, который делит на `ipScanMax` или показывает «до N адресов», получит 0. `index.html` поле не читает (`grep ipScanMax index.html` — пусто). Встроенный сервер отдаёт `stand.ipScanMax` и не меняется. Тест `tests/api-read.js:158` требует `ipScanMax > 0`: его нужно ослабить до `≥ 0`, иначе бэкенд w2c не пройдёт проверку готовности.
