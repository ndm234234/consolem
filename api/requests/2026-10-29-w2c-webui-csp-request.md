# Запрос от команды w2c: WebUI под CSP консоли; ограничение версии устройства

2026-10-29 · коммит контракта `3a838cf` · от команды w2c (бэкенд VMS)

**Статус: в работе** · [предварительный ответ](2026-10-29-w2c-webui-csp-response.md)

Спасибо за быстрый ответ на [первый запрос](2026-10-29-w2c-capabilities-request.md). Ниже — два пункта, которые
вышли из нашей сборки бэкенда.

1. **Приложение WebUI — файлами, без встроенного кода.** Наша консоль отдаёт страницы под политикой
   безопасности (CSP):
   - скрипты только файлами со своего адреса;
   - встроенный `<script>` только по хэшу;
   - атрибуты-обработчики `on…=` запрещены.

   Просим собрать боевое приложение WebUI так:
   - JS и CSS — отдельными файлами;
   - обработчики — через `addEventListener`, без `onclick=`, `onchange=` и подобных (в `index_api_server.html`
     их сейчас около 870);
   - вместе со сборкой — список её файлов: имя, тип, назначение.

   Файлы мы закрепляем по SHA-256 и отдаём байт в байт. Разметку входной страницы делаем сами, по вашему
   `index.html`. Картинки PNG и SVG (`logo-configurator.png`, `one-sign.svg`) отдаём файлами — укажите их в том же
   списке. SVG у нас отдаётся с изолирующей политикой (`sandbox`), скрипты внутри SVG работать не будут.
2. **Ограничение версии устройства (к п. 4 первого запроса).** Устройство у нас собрано из нескольких записей,
   и его `version` — склейка версий частей. `If-Match` сверяется с прочитанным снимком частей, а каждая часть
   пишется с проверкой своей версии. Поэтому:
   - правка той же части между проверкой и записью — `412`;
   - одновременную правку **другой** части того же устройства мы не ловим: запись пройдёт, а следующий читатель
     увидит новую `version`.

   Если вам нужна полная атомарность изменения устройства (всё или ничего по всем частям), скажите — это отдельная
   работа у нас.
