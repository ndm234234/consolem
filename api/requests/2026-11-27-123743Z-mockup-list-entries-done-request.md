# Запрос от команды mockup: записи списков лиц и номеров страницами внесены в контракт 0.42.0 — проверить

Кому: владелец контракта

**Статус: новый**

## Что мы сделали

Мы продолжили пункт `C17` отчёта о пробелах против Axxon One ([`docs/axxon-one-gaps.html`](../../docs/axxon-one-gaps.html)), «Списки лиц и номеров». Контракт 0.41.0 отдаёт записи списка только целиком, в поле `entries` объекта ([уведомление о 0.41.0](2026-11-27-105734Z-mockup-face-plate-lists-done-request.md)). В настоящем списке — десятки тысяч записей. Интерфейс прототипа 109 (`index_109_spiski-lic-i-nomerov.html`) показывает записи страницами с номерами, итогом и поиском. Для этого нужен путь записей.

- Контракт 0.42.0: путь `GET /units/{uid}/entries` (`listUnitEntries`), схемы `ListEntry`, `ListEntryPage`. Описание — [`api/README.md`](../README.md), «Что добавлено в 0.42.0»; для бэкенда — [`api/BACKEND.md`](../BACKEND.md), абзац «Списки лиц и номеров».
- Данные видов `facelist` и `platelist`: свойство `entryCount`; `entries` — `deprecated: true`, работает как раньше.
- Сервер: `api/server.js` (маршрут `GET /units/{uid}/entries`, `entryCount` в `unitView`).
- Тест: `tests/api-devices.js`, «Записи списков лиц и номеров (0.42.0)…», слой механизма.
- Слой по `tools/layers.py` — механизм: путь и схемы без `x-layer`.

## Что проверить

1. **Путь `GET /units/{uid}/entries`** — необязательная операция. Бэкенд, который её не объявил в `capabilities.operations`, оставляет клиенту `properties.entries`, как в 0.41.0.
   - Параметры: `q`, `ids` (не больше 200), `limit` (1–1000, по умолчанию 200), `offset` или `cursor`.
   - Ответ: `{items, total, offset, nextCursor?}`. `total` — точное число записей под `q` и `ids`.
   - Отказы: `offset` вместе с `cursor` — `422 VALIDATION_FAILED`, `field: offset`, `params.reason: withCursor`; больше 200 `ids` — `field: ids`; вид не `facelist` и не `platelist` — `422 NOT_SUPPORTED`, `field: /kind`; нет объекта — `404`.
   - Поиск: `name` содержит `q` без учёта регистра, или `id` равен `q`. У номеров ещё `plate` содержит `q` после приведения: без пробелов и `-`, в верхнем регистре, кириллица А В Е К М Н О Р С Т У Х — латиницей.
   Может ли ваш бэкенд отдать записи так?
2. **`entryCount`** у видов `facelist` и `platelist` — число записей, только чтение. Оно равно `total` без `q` и `ids`.
3. **`entries` устарело.** Поле работает как раньше: сервер его отдаёт и проверяет по нему `match.entryId` правила.

## Сверх запросов

- **`offset` рядом с `cursor`.** Общее правило страницы — только `cursor`. Интерфейс показывает номера страниц и переходит сразу на страницу N, поэтому нужен `offset`. Список — снимок синхронизации, поэтому `total` точный, а не оценка.
- **Курсор держит версию списка.** Синхронизация меняет `version` объекта, и прежний курсор получает `422 INVALID_CURSOR`. Так обход курсором не пропускает и не повторяет записи. `offset` версию не держит.
- **Слой — механизм.** Путь принимает только виды `facelist` и `platelist`, то есть служит VMS. Можно дать ему `x-layer: vms`; мы оставили механизм, как предлагает `tools/layers.py`.
- **Мост подсистем закрыт.** Путь без `x-bridge`, строка в `BRIDGE_CLOSED` (`tools/check_api.py`). Его можно открыть для чтения.
- **`entryCount` считает сервер** из `entries`, а не хранит.
- **`offset` в ответе есть всегда**, и при `ids`, и при `q`.
- **`ids` — в порядке списка**, а не в порядке запроса. Пустой `ids` — без отбора, как пустой `q`. `id` записи — без запятой.
- **`tools/profile_fixture.py`:** `listUnitEntries` в `MISSING`. Наборы `one-domain`, `large`, `xl` списков не имеют и операцию не объявляют.
- **Набор `demo`:** в списке «Сотрудники» 240 записей, в «Автопарке» 120, чтобы были страницы. Новые `id` — `f-0301…f-0536` и `p-0301…p-0415`.
