> **Исторический документ.** Инвентарь сделан перед первым переводом макета на API — на прототипе 09. Сейчас основной макет `index.html` работает через API. «Оборудование», «Права», «Опции» и «Журнал» в нём устроены так, как описано ниже. «Автоматизация» основного макета здесь не описана, она другая: правила с условиями и шагами, расписания, режимы объекта — см. [контракт](openapi.json) и [BACKEND.md](BACKEND.md). Номера строк ниже — по старому файлу.

Этап 2 переделки прототипа 09 под API (промт — [`prompts/api-server.md`](../prompts/api-server.md)).
Исходник — `index_10_api-server.html` (прототип 10, удалён; в момент инвентаря — точная копия `index_09_one-psim.html`). Номера строк указаны по нему.

Принятые решения: переводится **весь макет**; идентификаторы — **UUID**, номер для показа хранится отдельным полем (`short`, `identifier`); настоящего API продукта нет, имена путей и полей придумываем сами; GitHub Actions не добавляем.

Что есть в прототипе 09 на самом деле (промт мог устареть):

- **«Автоматизация»** — простой редактор правил из `index.html`: событие → действия, частота, окно. Правила можно только править, создания и удаления нет. Библиотека расписаний, режимы и «Ждать событие» есть только в прототипе 08, в 09 их нет, поэтому в контракт они не входят.

- **«Журнал»** — 24 строки, сгенерированные в коде (`LOG_EVENTS`, 10663). Фильтр по категории, поиск и страницы работают на клиенте.

## 5. Как это ляжет на API — ключевые решения

### 5.1. Кэш в интерфейсе

Синхронный рендер дерева обходит весь граф сотни раз за кадр (`find` 2346, счётчики, поиск), поэтому рендер не переписываем. При старте клиент читает коллекции (`GET /domains`, `/servers`, `/devices`, `/folders`, `/archives`, `/rules`, `/access`, …) и собирает из них **те же структуры, что сейчас** (`domains` со ссылками на серверы, `devicePool` с вложенными `devices[]`, `folders`, `arch`, `ACC.srv`…). Это кэш прочитанного.

- Кэш меняется только ответом сервера или событием потока, никогда до ответа.
- Константы-данные из HTML уходят в `api/fixtures/demo.json`.
- Первая отрисовка ждёт загрузки. Сейчас всё строится синхронно на старте; после переделки старт станет `await`.

### 5.2. Версии

- **Оборудование, правила, хранилища, тома**: поле `version` у каждой записи, `ETag` в ответе, `If-Match` в изменении. Нет заголовка — `428`, версия не совпала — `412` с актуальной записью в теле.
- **Права** — одна версия на весь снимок прав: черновик строится от снимка, применяется пакетом.

### 5.3. «Применить» карточки и групповые операции — одна серверная «операция»

Сейчас и план карточки, и правка выборки, и копирование настроек идут в одну очередь `bq`: план → ход → пауза и стоп → отчёт по объектам → «Повторить неудачные» → «Отменить». Предлагаю один ресурс:

- `POST /operations {idempotencyKey, items:[{target, version, steps:[{key, value}]}], dryRun?}`
  - `dryRun: true` возвращает план: «было → станет», пропуски `skip` с причиной, исключённые `excl`, оценку времени;
  - без него — `202 {id}`; ход приходит событиями `operation.progress` и `operation.item {target, step, state, code}`.
- `POST /operations/{id}/pause`, `/resume`, `/cancel`, `/retry-failed`, `/revert` («Отменить» — сервер помнит снимок «до»).
- `GET /operations/{id}` — состояние и отчёт.

Частичный успех — норма: по каждому объекту `done` или `failed` с кодом (`SERVER_OFFLINE`, `LICENSE_EXCEEDED`, `DEVICE_OFFLINE` — коды из `opFail` 13451). Повтор с тем же `idempotencyKey` ничего не выполняет снова.

Замыкания `run/undo` заменяются декларативными шагами `{key, value}`, ключи — из `bulkChanges` 13459: `enabled`, `creds`, `folderAdd/Remove`, `p:*`, `arch`, `rec`, `pre`, `video`, `addDet`, `copyDets`, `rename`.

**Мгновенные операции в обход очереди** остаются отдельными запросами, каждый со своим «Отменить» обратным запросом:
- `setNvrArch`/`setNvrRec`;
- `bulkExcludeServers`/`bulkAddToDomain`;
- `lanBind`/`lanUnbind`.

### 5.4. Удаление с «Отменить»

Отсчёт остаётся у клиента, `DELETE` уходит по истечении. Так сохраняется нынешнее «ничего не отправлено», и серверу не нужно мягкое удаление.

- Каскад делает сервер: устройство → дочерние и ссылки из папок; хранилище → снятие записи камер; домен → перенос содержимого в `moveTo`; роль → назначения.
- Последствия для диалога («что пропадёт, что останется») клиент считает из кэша, как сейчас.
- Групповое удаление — `POST /operations` с шагом `delete` и частичным успехом.

Минус такого решения: другой администратор видит объект до истечения отсчёта и может его править. В памятке это будет записано как известное упрощение.

### 5.5. Права — снимок и пакет изменений

- Черновик `ACC.ed` остаётся у клиента. `GET /access` отдаёт снимок (роли, пользователи, группы, каталоги, история) и `ETag`.
- `POST /access/changes {ops[]}` с `If-Match`:
  - `dryRun: true` возвращает план, последствия для людей (`accImpact`), проблемы (`accIssues`) и отказы защиты от самоблокировки (`accGuard`);
  - без него — применяет.
- Пароли передаются в пакете, в ответах их нет (`hasPassword`). История пишется сервером структурно, а не разбором текста.

### 5.6. Остальное

| Раздел | Запросы |
|---|---|
| Правила | `PUT /rules/{id}` целиком с `If-Match`; правка поля уходит сразу, как сейчас |
| Опции | `GET /settings`, `PATCH /settings` |
| Журнал | `GET /journal?category&q&page&pageSize` |
| Пароли устройств, томов, каталогов | только запись; в ответах `hasPassword: true`. Групповая правка не затирает пароль маской «••••••••», как сейчас (13469); копирование настроек передаёт `copyCredentialsFrom: <id>` |
| Ошибки | `application/problem+json` с `code`: `NAME_TAKEN`, `IDENTIFIER_TAKEN`, `INVALID_IP`, `NO_FREE_DISK`, `LAST_DOMAIN`, `PASSWORD_POLICY`, `LOGIN_TAKEN`, `SELF_LOCKOUT`, `VERSION_MISMATCH`, `PRECONDITION_REQUIRED`, `NOT_FOUND`, `PERMISSION_DENIED`… Интерфейс показывает их там же, где сейчас свои проверки |
| Идентификаторы | UUID выдаёт сервер. Создание — `POST`, в ответе id. Где интерфейс сразу открывает новый объект (`addSubfolder` → переименование, `addDomain`), он ждёт ответа: без временных id |

**Как будет собран эталонный набор.** Прототип 09 открывается в headless Chrome, после инициализации из памяти выгружаются `domains`, `servers`, `devicePool`, `folders`, `arch`, `rules`, `ruleFires`, `ACC.srv`, `SETTINGS`, `LOG_ROWS` и т. д. Демо-генерация при этом уже выполнена, то есть «запечена». Затем данные нормализуются: id → UUID детерминированно от старых id, русские строки-значения → коды, размеры → числа. Так набор совпадает с тем, что видно сейчас.

## 9. Вопросы

1. **«Применить» карточки и групповые операции — через одну серверную операцию** (5.3) с ходом в потоке, паузой, отчётом и «Отменить» через `revert`. *Рекомендую.* Альтернатива — `PATCH` на каждый объект от клиента: проще для бэкенда, но пауза, отчёт и «Отменить» останутся клиентской имитацией.
2. **Права — черновик у клиента, применение одним пакетом**, предпросмотр (`dryRun`) считает сервер (5.5). Матрица итоговых прав черновика рисуется синхронно на каждую ячейку, поэтому для неё алгоритм остаётся и в клиенте как показ, а решает сервер. Тесты проверяют, что ответ сервера и показ клиента совпадают. *Рекомендую.*
3. **Правила ссылаются на устройства по id, а не по имени.** Внешне ничего не меняется, имя показывается из кэша. *Рекомендую.* Иначе переименование устройства ломает правило.
4. **Избранное и «больше не предупреждать про учётные данные»** остаются в `localStorage` или уходят на сервер «на пользователя» (`/me/preferences`)? *Рекомендую оставить локально*: так сейчас, и это не общие данные.
5. **Удаления в «Правах»** (п. 1 и 6 раздела 7) довести до правила `CLAUDE.md`: ввод числа, перечень, отсчёт в тосте? Это видимое изменение поведения прав, но правило требует. *Рекомендую довести*: роли и пользователи удаляются в черновике, поэтому отсчёт идёт до удаления из черновика.
6. **Журнал**: сервер хранит только 24 строки набора или ещё и пишет аудит на каждое изменение через API? Второе — новое поведение (в журнале станут появляться строки). *Рекомендую* в этой итерации только набор, а аудит записать в открытые вопросы памятки.
7. **Списки без страниц.** Дерево и права требуют полного снимка, поэтому `GET /devices` и `GET /access` отдают всё. Постраничную выдачу для больших инсталляций записываю в открытые вопросы памятки. *Рекомендую.*
