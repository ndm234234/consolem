# Памятка для команды фронтенда

> **Для чего этот прототип.** Прототип 10 — это **спецификация поведения и эталон для проверки**, а не код продукта. По нему видно, что пользователь видит на каждом экране, что происходит при каждом действии и какие запросы при этом уходят на сервер. Он работает: его можно открыть, покликать и сравнить со своей реализацией.
>
> **Чем он не является.** Это **не готовое решение и не основа для кода**. Прототип — один HTML-файл на 1,1 МБ: глобальные функции, разметка, собранная строками, демо-данные, встроенный сервер и слой, который переводит ответы API в структуры старого макета. Так пишут макет, чтобы быстро проверять идеи, а не продукт. **Ни целиком, ни частями в продукт его не переносят** — интерфейс пишется заново на вашем стеке, с вашими компонентами, состоянием и тестами.
>
> **Что из него брать:**
> - **поведение** — [критерии приёмки](ACCEPTANCE.md);
> - **запросы** — [контракт](openapi.json);
> - **внешний вид** — сам прототип и дизайн-система ONE PSIM;
> - **решения сложных мест** — раздел «Что из прототипа — требование» ниже.
>
> Код прототипа читают, только чтобы понять, *как задумано* поведение. Копировать из него не нужно.

## Главное: у интерфейса нет своих данных

Всё, что в продукте хранит бэкенд, интерфейс получает и меняет только запросами контракта. Прототип так и сделан, и это проверяется: в его HTML не осталось ни одной константы с данными сервера.

- **При старте** интерфейс читает коллекции (`GET /domains`, `/servers`, `/devices`, `/folders`, `/archives`, `/volumes`, `/rules`, `/access`, `/settings`, …) и строит из них своё состояние. Рисует только после того, как всё пришло.
- **Состояние меняется только ответом сервера или событием потока** — никогда до ответа. Оптимистичных обновлений в прототипе нет нигде. Если они понадобятся вам, это отдельное решение с откатом при ошибке.
- **Что остаётся у клиента** (на сервер не уходит): выбранный раздел и объект, раскрытие дерева, фильтры, ширина панели, тема, язык, избранное, черновики — карточки, групповой правки, прав.

## Что из прототипа — требование

Это решения, которые надо повторить по смыслу. Реализуйте их своими средствами. В скобках — где посмотреть поведение в прототипе (имена функций в `index_10_api-server.html`), чтобы понять задумку, а не чтобы скопировать.

| Решение | Как должно работать |
|---|---|
| **Черновик карточки** (`cardDiff`, `cardPlan`, `cardApply`) | Правки в карточке «Оборудования» копятся в черновике. Внизу — «Не применено: N», «Сбросить», «Показать план». План — строки «было → станет». «Применить» отправляет одну групповую операцию (`POST /operations`). При уходе с карточки с черновиком — вопрос «Сбросить и перейти / Остаться» |
| **Чужая правка при открытом черновике** (`hwFresh`) | Пришло изменение записи, у которой открыт черновик: поля, которые пользователь не трогал, берут новое значение; его правки остаются поверх. Чужое изменение не должно попасть в «было → станет» |
| **Очередь операции** (`apiQueue`, `opOnEvent`) | После «Применить» в шапке — очередь с ходом «N из M». Ход и итог по каждому шагу приходят событиями `operation.progress` и `operation.finished`, интерфейс сам ничего не отсчитывает. Пауза, «Отменить оставшееся», «Повторить неудачные» — запросы к операции. Есть отказы — открывается отчёт по шагам. Без отказов — тост с «Отменить», и «Отменить» — это `POST /operations/{id}/revert` |
| **Быстрые групповые действия** (`serversAssign`, `devicesMutate`) | Добавить серверы в домен, привязать к хранилищу на вкладке «Сеть», добавить устройства — один запрос с ответом `{done, failed}`. Не выполненное — тостом с причиной. «Отменить» — обратный запрос |
| **Удаление с отсчётом** (`askConfirm(…, {typeCount})`, `scheduleDelete`) | Подтверждение с вводом числа удаляемых объектов → отсчёт 10 с (15 с — больше трёх объектов) в тосте с «Отменить», отсчёт останавливается при наведении. Запрос уходит, только когда отсчёт кончился. Объекты на время отсчёта помечены в дереве и недоступны для правки |
| **Переименование в дереве** (`commitTreeRename`) | Enter или потеря фокуса → `PATCH`. Поле ввода остаётся открытым, пока нет ответа, чтобы старое имя не мелькнуло. Ошибка — тост, поле снова в фокусе |
| **Права — черновик целиком** (`accPlan`, `accSetSnapshot`) | Снимок прав (`GET /access`) — основа черновика. «Применить» — план, последствия для людей, затем `POST /access/apply` со всем черновиком и версией снимка. Защиту от самоблокировки интерфейс проверяет заранее как подсказку, но решает сервер (`409 SELF_LOCKOUT`). id новых ролей и пользователей — UUID, их создаёт клиент |
| **Поток событий** (`apiOnEvent`) | `entity.changed` → перечитать запись по id, если её версия новее известной. `entity.created` / `deleted` чужих записей → добавить или убрать. Своя запись могла прийти ответом раньше события — тогда событие ничего не делает. `stream.reset` или долгий обрыв → перечитать всё |
| **Поиск в сети** (`discStart`, `discOnEvent`) | «Обновить» запускает поиск на сервере. Находки приходят событиями по одной, с процентом хода. Мастер и вкладка «Сеть» одного домена слушают один и тот же поиск; если он уже идёт, второй экран к нему подключается |
| **Ошибки по коду** (`problemText`) | Текст для пользователя — по `code` из ответа (`ProblemCode`), своими словами раздела. Поле `message` сервера — для журнала, не для экрана. Неизвестный код — «ошибка: КОД» |
| **Коды → подписи** | Сервер отдаёт коды и числа (`recordMode: "motion"`, `detectorKind: "linecross"`, `sizeBytes`, `usedPercent`). Подписи, единицы («4 ТБ») и переводы — на клиенте |
| **Время** | Всё время с сервера — в UTC. Показывается в часовом поясе системы (`GET /me` → `timezone`), а не браузера. Сроки («истекает через 3 дня») — от `serverTime`, а не от часов компьютера |
| **Моргание при переходе** (`accFlash`, `hwFlashLanding`) | Переход по ссылке подсвечивает место, куда пришли (критерий О-01) |

## Что не переносится — только для демо

| В прототипе | Почему не переносится |
|---|---|
| Сам HTML прототипа: разметка строками, глобальные переменные, обработчики в атрибутах `onclick` | макет для быстрых проверок идей; в продукте — компоненты вашего стека |
| Встроенный сервер [`server.js`](server.js) и всё, что идёт с ним: [`fixture.js`](fixture.js), [`openapi.js`](openapi.js), [`contract.js`](contract.js) | это сторона бэкенда и средства стенда; в продукте сервер — настоящий |
| Слой перевода ответов API в структуры старого макета (`devNode`, `srvNode`, `hwFill`, `accFromApi`, поля `_f`, русские значения вроде «Основной» или «AxxonNet») | нужен только потому, что макет был написан до API. Ваш интерфейс работает с записями API напрямую |
| [`client.js`](client.js) | образец на сто строк: два режима (вызов функции и `fetch`), обещания, `If-Match`. Нужен свой клиент на вашем стеке; режим «встроенный сервер» продукту не нужен |
| Заглушки: «отвечает ли адрес» по хешу, модель по сумме чисел адреса, LDAP «изменений нет», придуманные имена новых серверов | стенд не ходит в сеть; в продукте это делает бэкенд |
| Самопроверка `?selftest`, `tests/ui-*.js`, `tools/check_ui.py`, `tools/compare_screens.py` | проверяют прототип через его внутренние функции; для вашей реализации те же проверки описаны в [`ACCEPTANCE.md`](ACCEPTANCE.md) |
| Демо-данные: имена объектов, журнал, история прав | эталонный набор стенда, а не данные продукта |

## Что ещё за вами

Этого в прототипе нет вовсе или есть только обозначено:

- **Вход и сессия.** В прототипе администратор уже вошёл. Ответ `401 UNAUTHORIZED` должен вести на вход.
- **Права администратора.** В прототипе все кнопки доступны всем. В продукте кнопки и разделы зависят от функций роли (`DEVICES_SETUP`, `USERS_RIGHTS_SETUP` и т. д.), а `403 PERMISSION_DENIED` и `404` для невидимого объекта надо показывать. Модель прав администратора ещё не согласована — [BACKEND.md, «Что ещё не решено»](BACKEND.md#что-ещё-не-решено).
- **Каталог строк и переводы.** Подписи сейчас разбросаны по коду прототипа и `assets/i18n-en.js`; нужен свой каталог.
- **Большие инсталляции.** Прототип читает всё целиком, на демо-объёме это работает. На тысячах объектов нужна постраничная загрузка и серверный поиск — тоже открытый вопрос.
- **Доступность, клавиатура, поддерживаемые браузеры** — по вашим стандартам. Прототип проверялся в Chrome.
- **Видео, карты, живые кадры** в прототипе нарисованы.

## Как говорить с бэкендом

- **Адрес API** — настройка сборки или окружения. Все запросы — с `credentials: "include"`, тело — JSON.
- **Версии.** Запомните `version` (или `ETag`) каждой прочитанной записи. Это непрозрачная строка: сравнивайте её только на равенство, не разбирайте и не вычисляйте следующую. Изменение отправляйте с `If-Match: "<version>"`, групповую операцию — с `expectedVersions` всех объектов. `412` — запись изменилась: перечитать и показать пользователю. `428` — ошибка вашего кода: версию не передали.
- **`idempotencyKey`** создавайте один раз на действие пользователя и повторяйте его при повторе после сетевой ошибки — тогда сервер не выполнит действие дважды.
- **Поток.** `new EventSource(адрес + "/stream", { withCredentials: true })`; сообщения без `event:`, тип — в `data.type`. После переподключения браузер сам пошлёт `Last-Event-ID`. Пришёл `stream.reset` — перечитайте всё.
- **Частичный успех** — норма, а не ошибка: в ответах `{done, failed}` и в шагах операции у каждого объекта свой итог.
- **Разрабатывать можно уже сейчас**, не дожидаясь бэкенда: `node tools/serve_api.mjs` поднимает стенд на эталонных данных с тем же контрактом. `POST /test/reset` возвращает данные в исходное состояние.

## Когда готово

1. Все критерии [`ACCEPTANCE.md`](ACCEPTANCE.md) выполняются против стенда (`tools/serve_api.mjs`, затем стенд бэкенда), и при задержке ответа 300 мс тоже.
2. Экраны выглядят как в прототипе: в светлой и тёмной теме, по-русски и по-английски (критерий О-05).
3. В коде интерфейса нет данных сервера: всё, что хранит бэкенд, приходит запросами контракта.
