# Критерии приёмки интерфейса конфигуратора

Что должен уметь интерфейс и как это проверить — шагами пользователя, без кода прототипа. По этим критериям проверяют реализацию на любом стеке: вручную (тестировщик) или автотестами фронтенда.

**Условия.** Интерфейс работает с тестовым стендом: со встроенным сервером прототипа, с образцом `node tools/serve_api.mjs` или со стендом бэкенда. Перед каждым разделом стенд сброшен: `POST /test/reset` загружает эталонный набор `api/fixtures/demo.json`. Имена объектов ниже — из этого набора.

**Как читать.** У каждого критерия: что делаем, что видно на экране и что должно оказаться на сервере. Проверить «на сервере» — значит прочитать запись запросом API (`GET /devices/{id}` и т. п.) или открыть объект в другой вкладке.

**Общее правило для всех критериев:** экран меняется только после ответа сервера. До ответа видно прежнее значение (поле ввода может оставаться открытым), после — новое, без лишнего мигания. Все критерии должны выполняться и при задержке ответа 300 мс: в прототипе это `?latency=300`, в своей реализации — задержка сети в DevTools.

В прототипе каждый раздел автоматизирован файлом `tests/ui-*.js` (указан в заголовке). Самопроверка `index_10_api-server.html?selftest` проходит их все.

## 1. Карточка устройства — `tests/ui-hardware.js`

**П-01. Данные приходят с сервера.** Открыть «Оборудование» → камеру «Главный вход».
Видно: карточка с полями камеры. Id камеры — UUID из набора.

**П-02. «Применить» уходит операцией.** В карточке «Главный вход» изменить имя на «Вход — пилот» и режим записи на «По детектору».
Видно: внизу «Не применено: 2 изменения». «Показать план» → две строки «было → станет» → «Применить».
Видно: в шапке появилась очередь с ходом выполнения; пока сервер не ответил, имя в дереве прежнее. Когда очередь завершилась — новое имя в дереве и в карточке.
На сервере: имя «Вход — пилот», режим `motion`, версия выросла на 2.

**П-03. «Отменить» после применения.** Сразу после П-02 нажать «Отменить» в тосте.
Видно: имя и режим вернулись («Главный вход», «Всегда»).
На сервере: прежние значения. Откат выполнила обратная операция (`POST /operations/{id}/revert`).

**П-04. Переименование в дереве.** Двойной клик по имени камеры в дереве → ввести «Главный вход 2» → Enter.
Видно: пока сервер не ответил, поле ввода открыто и старое имя не мелькает; после ответа — новое имя в строке.
На сервере: новое имя.

**П-05. Пустое имя не принимается.** То же с пустым именем.
Видно: тост «Укажите имя», поле ввода остаётся открытым.

**П-06. Сервер без связи.** Открыть камеру сервера «Сервер — Филиал» (он без связи), изменить имя, «Применить».
Видно: очередь завершилась, открылся отчёт, у шага — «сервер «Сервер — Филиал» не отвечает».
На сервере: имя не изменилось.

## 2. Домены, серверы, папки — `tests/ui-domains.js`

**Д-01. Новый домен.** В меню дерева «Создать домен».
Видно: после ответа сервера в дереве новый домен «Домен N», его имя сразу открыто на переименование. Переименовать в «Филиал Юг» → Enter.
На сервере: домен с этим именем.

**Д-02. Имя домена занято.** Переименовать домен в имя существующего («Домен 1», без учёта регистра).
Видно: тост «Домен с таким именем уже есть», поле ввода открыто, имя не изменилось.

**Д-03. Исключить сервер из домена и вернуть.** У сервера домена «Исключить из домена».
Видно: сервер переехал в «Нераспределённые серверы» домена. Добавить его обратно — он в конце списка серверов домена, а в «Нераспределённых» его строка осталась с пометкой «Добавлен».
На сервере: `allocated: false`, затем `true`.

**Д-04. Групповое исключение и «Отменить».** Отметить два сервера домена → «Исключить из домена».
Видно: оба в «Нераспределённых». «Отменить» в тосте — оба вернулись на прежние места в списке.
На сервере: оба снова в домене.

**Д-05. Карточка сервера.** В карточке сервера изменить имя → «Применить».
Видно: очередь, затем новое имя.
На сервере: новое имя.

**Д-06. Опрос адресов.** «Добавить серверы по IP» → ввести `10.77.0.5:20111` и адрес уже заведённого сервера → «Проверить».
Видно: у известного — «уже в домене», у нового — найден (или «не отвечает»). Добавить найденный.
На сервере: новый сервер в домене.

**Д-07. Папка.** «Создать подпапку» → после ответа сервера папка «Новая папка» открыта на переименование → «Склад-3».
На сервере: папка с этим именем.

**Д-08. Очистить папку.** У папки с устройствами «Убрать все объекты» → подтвердить.
Видно: папка пуста. Сами устройства остались в дереве.
На сервере: `deviceIds: []`.

**Д-09. Удалить папку — с вводом числа и отсчётом.** «Удалить папку».
Видно: «Удалить» неактивна, пока не введено число `1`. После подтверждения — тост с отсчётом и «Отменить»; во время отсчёта папка на месте и на сервере. По истечении папка пропадает.
На сервере: папки нет (`404`).

**Д-10. Удалить домен с переносом.** «Удалить домен» у «Домен 2» → выбрать «Перенести в домен 1» → ввести `1` → подтвердить → дождаться отсчёта.
Видно: домена нет; его серверы — в «Нераспределённых» домена 1.
На сервере: домена нет, серверы — `domainId` домена 1, `allocated: false`.

**Х-01. Новое хранилище.** У сервера со свободными дисками «＋ Хранилище…» (или «Создать хранилище…» в меню) → имя «Хранилище — сценарий» → «Создать».

На сервере: хранилище на этом сервере.

**Х-02. Ещё том.** «＋ Том».
Видно: том добавлен и открыт.

**Х-03. Правка тома.** В карточке тома изменить размер на 700 ГБ → «Применить».
На сервере: `sizeBytes` = 700 ГБ.

**Х-04. Чужая правка при открытом черновике.** Пока у тома не применён новый размер, в другой вкладке изменить у этого тома папку и сохранить.

**Х-05. Правка хранилища.** Изменить глубину хранения на 45 дней → «Применить».
На сервере: `retentionDays: 45`.

**Х-06. Проверить подключение.** Новое сетевое хранилище без пользователя NAS → «Проверить подключение».
Видно: тост «Не удалось подключиться».

**Х-07. Форматировать.** У тома «раздел целиком» → «Форматировать…» → подтвердить.
Видно: состояние «Форматируется», затем «Готов (0%)» и тост «Том отформатирован». Таймера в интерфейсе нет: готовность приходит с сервера.

**Х-08. Удалить том.** «Удалить том» → ввести `1` → отсчёт.
Видно: во время отсчёта том на месте; по истечении пропал.
На сервере: тома нет.

**Х-09. Удалить хранилище, в которое пишут камеры.** «Удалить хранилище» → `1` → отсчёт.
Видно: хранилища нет; его камеры остались — пишут в следующее хранилище или перешли в «Без записи».

## 8. Общее для всех экранов

**О-01. Моргание при переходе.** Любой переход по ссылке — из карточки, пути в шапке, списка, поиска, тоста, избранного, диалога — подсвечивает место, куда пришли: заголовок (или последний шаг пути), активную вкладку и строку дерева, и дерево прокручивается к строке. Клик в самом дереве и по вкладкам не моргает. На синем фоне вспышка белая. Образец — раздел «Права», правило — `CLAUDE.md`.

**О-02. Удаление — с вводом числа.** Каждое подтверждение удаления, одиночного и группового, содержит поле для числа удаляемых объектов; для одного — `1`. Пока число не введено, «Удалить» неактивна, а Enter в поле подтверждает только при верном числе. В диалоге перечислено, что пропадёт и что останется. После подтверждения — отсчёт в тосте с «Отменить». Во время отсчёта на сервер ничего не уходит.

**О-03. Ошибки по коду.** Интерфейс показывает свой текст по коду ошибки (`ProblemCode` в контракте), а не `message` сервера. Ошибка на отдельном шаге групповой операции попадает в отчёт против этого шага.

**О-04. Чужие изменения.** Изменение в другой вкладке или у другого администратора появляется на экране без перезагрузки. Если связь с потоком событий потеряна дольше, чем сервер помнит, — интерфейс перечитывает всё.

**О-05. Внешний вид — как в прототипе.** Экраны «Оборудования» (все срезы и вкладки карточек), «Автоматизации», «Опций», «Журнала» и «Прав» в светлой и тёмной теме, по-русски и по-английски выглядят как в прототипе 10.
