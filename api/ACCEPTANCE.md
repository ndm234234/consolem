# Критерии приёмки интерфейса конфигуратора

Что должен уметь интерфейс и как это проверить — шагами пользователя, без кода прототипа. По этим критериям проверяют реализацию на любом стеке: вручную (тестировщик) или автотестами фронтенда.

**Условия.** Интерфейс работает с тестовым стендом: со встроенным сервером прототипа (`index.html`), с образцом `node tools/serve_api.mjs` или со стендом бэкенда. Перед каждым разделом стенд сброшен: `POST /test/reset` загружает эталонный набор `api/fixtures/demo.json`. Имена объектов ниже — из этого набора.

**Как читать.** У каждого критерия: что делаем, что видно на экране и что должно оказаться на сервере. Проверить «на сервере» — значит прочитать запись запросом API (`GET /units/{uid}` и т. п.) или открыть объект в другой вкладке.

**Общее правило для всех критериев:** экран меняется только после ответа сервера. До ответа видно прежнее значение (поле ввода может оставаться открытым), после — новое, без лишнего мигания. Все критерии должны выполняться и при задержке ответа 300 мс: в прототипе это `?latency=300`, в своей реализации — задержка сети в DevTools.

В прототипе каждый раздел автоматизирован файлом `tests/ui-*.js` (назван в заголовке раздела). Самопроверка `index.html?selftest` проходит их все. Разделы 1–8 и «Просмотр» — те же критерии, что у старого макета, на тех же данных: известные виды (камера, хранилище, сервер, домен, папка) выглядят и работают как прежде. Раздел «Незнакомый вид» в конце — для видов, о которых интерфейс ничего не знает.

## 1. Карточка устройства — `tests/ui-hardware.js`

**П-01. Данные приходят с сервера.** Открыть «Оборудование» → камеру «Главный вход».
Видно: карточка с полями камеры. Id камеры — UUID из набора.

**П-02. «Применить» уходит операцией.** В карточке «Главный вход» изменить имя на «Вход — пилот» и режим записи на «По детектору».
Видно: внизу «Не применено: 2 изменения». «Показать план» → две строки «было → станет» → «Применить».
Видно: в шапке появилась очередь с ходом выполнения; пока сервер не ответил, имя в дереве прежнее. Когда очередь завершилась — новое имя в дереве и в карточке.
На сервере: имя «Вход — пилот», режим `motion`, версия записи сменилась.

**П-03. «Отменить» после применения.** Сразу после П-02 нажать «Отменить» в тосте.
Видно: имя и режим вернулись («Главный вход», «Всегда»).
На сервере: прежние значения. Откат выполнила обратная операция (`POST /operations/{id}/revert`).

**П-04. Переименование в дереве.** Двойной клик по имени камеры в дереве → ввести «Главный вход 2» → Enter.
Видно: пока сервер не ответил, поле ввода открыто и старое имя не мелькает; после ответа — новое имя в строке.
На сервере: новое имя.

**П-05. Пустое имя не принимается.** То же с пустым именем.
Видно: тост «Укажите имя», поле ввода остаётся открытым.

**П-06. Сервер без связи.** Открыть камеру сервера «Сервер — Филиал» (он без связи), изменить имя, «Применить».
Видно: очередь завершилась, открылся отчёт, у шага — «сервер «Сервер — Филиал» не отвечает».
На сервере: имя не изменилось.

## 2. Домены, серверы, папки — `tests/ui-domains.js`

**Д-01. Новый домен.** В меню дерева «Создать домен».
Видно: после ответа сервера в дереве новый домен «Домен N», его имя сразу открыто на переименование. Переименовать в «Филиал Юг» → Enter.
На сервере: домен с этим именем.

**Д-02. Имя домена занято.** Переименовать домен в имя существующего («Домен 1», без учёта регистра).
Видно: тост «Домен с таким именем уже есть», поле ввода открыто, имя не изменилось.

**Д-03. Исключить сервер из домена и вернуть.** У сервера домена «Исключить из домена».
Видно: сервер переехал в «Нераспределённые серверы» домена. Добавить его обратно — он в конце списка серверов домена, а в «Нераспределённых» его строка осталась с пометкой «Добавлен».
На сервере: `allocated: false`, затем `true`.

**Д-04. Групповое исключение и «Отменить».** Отметить два сервера домена → «Исключить из домена».
Видно: оба в «Нераспределённых». «Отменить» в тосте — оба вернулись на прежние места в списке.
На сервере: оба снова в домене.

**Д-05. Карточка сервера.** В карточке сервера изменить имя → «Применить».
Видно: очередь, затем новое имя.
На сервере: новое имя.

**Д-06. Опрос адресов.** «Добавить серверы по IP» → ввести `10.77.0.5:20111` и адрес уже заведённого сервера → «Проверить».
Видно: у известного — «уже в домене», у нового — найден (или «не отвечает»). Добавить найденный.
На сервере: новый сервер в домене.

**Д-07. Папка.** «Создать подпапку» → после ответа сервера папка «Новая папка» открыта на переименование → «Склад-3».
На сервере: папка с этим именем.

**Д-08. Очистить папку.** У папки с устройствами «Убрать все объекты» → подтвердить.
Видно: папка пуста. Сами устройства остались в дереве.
На сервере: `deviceIds: []`.

**Д-09. Удалить папку — с вводом числа и отсчётом.** «Удалить папку».
Видно: «Удалить» неактивна, пока не введено число `1`. После подтверждения — тост с отсчётом и «Отменить»; во время отсчёта папка на месте и на сервере. По истечении папка пропадает.
На сервере: папки нет (`404`).

**Д-10. Удалить домен с переносом.** «Удалить домен» у «Домен 2» → выбрать «Перенести в домен 1» → ввести `1` → подтвердить → дождаться отсчёта.
Видно: домена нет; его серверы — в «Нераспределённых» домена 1.
На сервере: домена нет, серверы — `domainId` домена 1, `allocated: false`.

## 3. Хранилища и тома — `tests/ui-storage.js`

**Х-01. Новое хранилище.** У сервера со свободными дисками «＋ Хранилище…» (или «Создать хранилище…» в меню) → имя «Хранилище — сценарий» → «Создать».
Видно: до ответа сервера хранилища в дереве нет, после — есть, с первым томом.
На сервере: хранилище на этом сервере.

**Х-02. Ещё том.** «＋ Том».
Видно: том добавлен и открыт.

**Х-03. Правка тома.** В карточке тома изменить размер на 700 ГБ → «Применить».
На сервере: `sizeBytes` = 700 ГБ.

**Х-04. Чужая правка при открытом черновике.** Пока у тома не применён новый размер, в другой вкладке изменить у этого тома папку и сохранить.
Видно: в карточке появилась новая папка. В плане «было → станет» её нет, а свой размер остался.

**Х-05. Правка хранилища.** Изменить глубину хранения на 45 дней → «Применить».
На сервере: `retentionDays: 45`.

**Х-06. Проверить подключение.** Новое сетевое хранилище без пользователя NAS → «Проверить подключение».
Видно: тост «Не удалось подключиться».

**Х-07. Форматировать.** У тома «раздел целиком» → «Форматировать…» → подтвердить.
Видно: состояние «Форматируется», затем «Готов (0%)» и тост «Том отформатирован». Таймера в интерфейсе нет: готовность приходит с сервера.

**Х-08. Удалить том.** «Удалить том» → ввести `1` → отсчёт.
Видно: во время отсчёта том на месте; по истечении пропал.
На сервере: тома нет.

**Х-09. Удалить хранилище, в которое пишут камеры.** «Удалить хранилище» → `1` → отсчёт.
Видно: хранилища нет; его камеры остались — пишут в следующее хранилище или перешли в «Без записи».
На сервере: ни одна камера не ссылается на удалённое хранилище.

## 4. Поиск в сети, мастер, детекторы — `tests/ui-devices.js`, `tests/ui-plan.js`

**М-01. Итог прошлого поиска.** Открыть «Найденные устройства» домена 1.
Видно: 5 найденных из прошлого поиска.

**М-02. Новый поиск.** «Обновить».
Видно: список очистился, находки появляются по одной, ход в процентах; в конце снова 5.
На сервере: поиск в состоянии `done`.

Шаги М-03…М-05 — мастер добавления с планом, сценарий `tests/ui-plan.js`. Общее для них: вкладки «В сети», «По адресу», «Из файла» ничего не создают в системе, а кладут строки в план кнопкой «В план». Пока план не применён, в дереве и на сервере новых устройств нет. «Применить план» — один `POST /devices` на все строки плана. Строка с отказом остаётся в плане со своей причиной. «Повторить неудачные» отправляет только такие строки и с тем же ключом повтора, пока состав плана не менялся.

**М-03. Найденные — в план.** Вкладка «В сети»: отметить два найденных, задать логин и пароль → «В план».
Видно: две строки в плане, у найденных метка «В плане». В дереве новых устройств нет.
Затем «Применить план». Логин и пароль заданы, замечаний нет — план применяется сразу, без диалога. Диалог «Применить план» с кнопкой «Добавить N» бывает, только когда у отправляемых строк есть предупреждения: нет логина или пароля, нет архива, модели нет в справочнике.
Видно: план пуст, в дереве два новых устройства, у каждого свой номер от сервера (у двух подряд номера разные).
На сервере: один `POST /devices` с двумя строками; устройства с адресами найденных, `hasPassword: true`; в итоге поиска их больше нет.

**М-04. По адресу.** Вкладка «По адресу»: IP, порт, производитель Axis → «Определить модель» → «В план» → «Применить план».
Видно: подставлена модель, тост «Модель устройства определена»; после применения устройство в дереве.
На сервере: устройство с этой моделью.
Производитель `RTSP` (выбирается из списка): вместо полей IP и порта — одно поле «RTSP» с адресом потока, «Определить» нет; без адреса строка в план не идёт.

**М-05. Из файла.** Вкладка «Из файла»: загрузить CSV с камерой, регистратором (модель со словом «NVR») и строкой с производителем вне списка → «В план».
Видно: производитель в другом регистре поправлен по списку; у строки вне списка — предупреждение, в плане она с ошибкой, пока производитель не поправлен в самой строке плана.
«Применить план» с ошибочной строкой: она остаётся в плане с причиной, остальные добавлены; поправить производитель → «Применить план (1)» — уходит только она. Строка с производителем вне списка на сервер не уходила, отказа не было, поэтому «Повторить неудачные» здесь нет: эта кнопка — для строк, которым отказал сервер.
Видно: у регистратора каналы с короткими именами от его номера: «57.1», «57.2».
На сервере: производитель записан в регистре из списка.

**М-06. Детектор из карточки камеры.** Камера → вкладка «Детекторы» → «＋ Детектор» → «Применить».
Видно: в плане — «Добавить: Детектор»; после очереди — новый детектор у камеры.
На сервере: детектор под этой камерой.

**М-07. Удалить детектор.** «Удалить» у детектора → `1` → отсчёт.
Видно: по истечении детектора нет.
На сервере: нет; его нет и в «Записи по детекторам» других камер.

**М-08. Вкладка «Сеть» сервера.** Открыть у сервера вкладку «Сеть».
Видно: поиск идёт, находки появляются. «Добавить» у нового устройства; если учётных данных нет — в окне «Добавление устройства» «Продолжить».
Видно: устройство в дереве под этим сервером.
На сервере: пишет в хранилище сервера, `serverId` — этот сервер.

## 5. Групповые операции — `tests/ui-bulk.js`

**Г-01. Правка выборки одной операцией.** Отметить три камеры → «Выключить», режим «По детектору», логин и пароль, «В папку», «Детектор: Пересечение линии» → «Показать план».
Видно: в плане 5 шагов. «Применить» → очередь в шапке; до ответа сервера камеры прежние; по ходу — меняются.
На сервере: камеры выключены, режим `motion`, логин задан, `hasPassword: true`, в папке, новые детекторы у тех камер, где такого не было. Сам пароль в интерфейсе нигде не виден.

**Г-02. Занятые объекты.** Запустить правку 12 камер. Пока операция идёт, у её объектов в дереве «выполняется операция», карточка говорит об этом, план не показывается, переименование отказывает тостом. «Отменить оставшееся» останавливает неначатые шаги, выполненное остаётся. После конца объекты свободны.

На сервере: правка занятого объекта — `409 BUSY`.

**Г-03. Сервер без связи — исключён.** В выборке камера рабочего сервера и две камеры сервера без связи → правка.
Видно: у двух — «сервер без связи» (исключены и на сервер не отправлены), у первой — выполнено.

**Г-04. Групповое удаление.** Отметить две камеры → «Удалить» → «Удалить» неактивна до ввода `2` → ввести → отсчёт.
Видно: по истечении камер нет; из папок они тоже пропали.
На сервере: камер нет, одним запросом `POST /objects/delete`.

## 6. Автоматизация — `tests/ui-rules.js`, `tests/ui-rule-links.js`

**А-01. Правила, запуски, расписания с сервера.** «Автоматизация».
Видно: 9 правил по группам запуска, «Обзор» с причинами, по которым правила не работают, и последними отказами; у «Охраны входа ночью» — журнал запусков со временем «ЧЧ:ММ:СС», в трассе — события, проверки условий, шаги по устройствам с причиной отказа («Запасной вход: выключена правилом «Обслуживание — выключить камеры входа»», «реле не ответило за 2 с»). Библиотека «Расписания», «Особые дни», «Режимы» — как в `index.html`.

**А-02. Правка правила и «Отменить».** Переименовать «Охрану входа ночью», «Применить».
Видно: до ответа сервера на сервере прежнее; после — новое имя, во вкладке «История» — новая версия. «Отменить» в тосте возвращает имя.
На сервере: правило сохранено целиком (`PUT`), автор и время изменения — с сервера; после «Отменить» — прежнее содержимое с **новой** версией записи, отменённая версия истории убрана.

**А-03. Включённое с ошибкой не сохраняется.** Убрать из включённого правила все действия, «Применить».
Видно: подсказка об ошибке, «Применить» не уходит. Выключенное незаконченное правило сохраняется.
На сервере: включённое с ошибкой — `422 RULE_INVALID`.

**А-04. Новое правило.** «＋ Правило» → с нуля, выбрать действие, «Применить».
Видно: до «Применить» правило помечено новым и есть только в этой вкладке; после — у правила id сервера, оно выбрано, в «Истории» — «Правило создано». «Отменить» удаляет его.

**А-05. Состояние и приглушение группой.** Отметить два правила → «Только журнал»; затем у одного «Приглушить до…».
Видно: оба в «Только журнал» с датой, «Отменить» возвращает прежнее; приглушённое — с плашкой «Сейчас не действует: приглушено до …».
На сервере: одним запросом `POST /rules/update`; приглушение версию истории не пишет; когда срок истёк, версия записи не меняется.

**А-06. Порядок на одно событие.** У «Входа на видеостене» «Выполнять раньше».
Видно: правило выше «Охраны входа»; «Отменить» возвращает порядок.

**А-07. Удаление правила.** «Удалить правило» → `1` → отсчёт.
Видно: во время отсчёта правило помечено; после — его нет. В диалоге — что пропадёт (история версий, кнопки оператора) и что останется (журнал запусков).
На сервере: до конца отсчёта правило есть; потом — `POST /objects/delete`, правила нет.

**А-08. «Запустить».** У «Открыть шлагбаум» «Запустить» → подтвердить.
Видно: тост «Правило выполнено: N из M», в журнале — новый запуск «вручную» с шагами по устройствам.
На сервере: запуск в `GET /rules/{id}/fires`; трасса — кодами.

**А-09. Пробный запуск.** У «Охраны входа ночью» «Проверить» → выбрать события, время, исходы ветвлений → «Проверить» → «Записать в журнал».
Видно: проверки событий и условий, шаги «выполнилось бы»; после «Записать в журнал» — запись «Проверка».
На сервере: без «Записать» — ничего; с ним — запуск `by: test` в журнале.

**А-10. «Повторить невыполненное».** В запуске с отказом реле «Повторить».
Видно: новый запуск только с отказавшими шагами и итог «выполнено N из M».

**А-11. История версий.** «История» → у версии 1 «Вернуть эту версию» → «Применить».
Видно: план «было → станет»; после — новая версия с пометкой «Возврат к версии 1».

## 8. Общее для всех экранов

**О-01. Моргание при переходе.** Любой переход по ссылке — из карточки, пути в шапке, списка, поиска, тоста, избранного, диалога — подсвечивает место, куда пришли: заголовок (или последний шаг пути), активную вкладку и строку дерева, и дерево прокручивается к строке. Клик в самом дереве и по вкладкам не моргает. На синем фоне вспышка белая. Образец — раздел «Права», правило — `CLAUDE.md`.

**О-02. Удаление — с вводом числа.** Каждое подтверждение удаления, одиночного и группового, содержит поле для числа удаляемых объектов; для одного — `1`. Пока число не введено, «Удалить» неактивна, а Enter в поле подтверждает только при верном числе. В диалоге перечислено, что пропадёт и что останется. После подтверждения — отсчёт в тосте с «Отменить». Во время отсчёта на сервер ничего не уходит.

**О-03. Ошибки по коду.** Интерфейс показывает свой текст по коду ошибки (`ProblemCode` в контракте), а не `message` сервера. Ошибка на отдельном шаге групповой операции попадает в отчёт против этого шага.

**О-04. Чужие изменения.** Изменение в другой вкладке или у другого администратора появляется на экране без перезагрузки. Если связь с потоком событий потеряна дольше, чем сервер помнит, — интерфейс перечитывает всё.

**О-06. Неподдержанного не видно.** Система с частью контракта (в прототипе — `?fixture=one-domain`, сценарий `tests/ui-profile.js`): нет «Создать домен» и «Удалить домен», «Добавить найденные», «Лицензий» в опциях, «＋ Том» и «Удалить том», шифрования хранилища, вкладки «Сеть» и поля «Роль» у сервера; мастер добавления открывается на «Вручную», виды — только те, что есть в системе. Всё остальное работает как обычно. Ни одна кнопка на экране не приводит к ответу `404 NO_ROUTE` или `422 NOT_SUPPORTED`.

**О-05. Внешний вид — как в прототипе.** Экраны «Оборудования» (все срезы и вкладки карточек), «Автоматизации», «Опций», «Журнала» и «Прав» в светлой и тёмной теме, по-русски и по-английски выглядят как в прототипе API и в `index.html`.

## Устройства: виды, детекторы, СКУД (запросы w2c)

1. Откройте датчик: номер только для чтения, правятся имя, включение и нормальное состояние. Канал и встроенное хранилище не правятся. В мастере нет датчика, реле и микрофона, в меню нет «Удалить». На сервере `POST`, `DELETE` — `422 NOT_SUPPORTED`.
2. Удалите регистратор с записью устройства: в подтверждении сказано, что камеры останутся, после отсчёта они в дереве без родителя. Выведенный регистратор удалить нельзя.
3. Камера с вариантами разрешения: на вкладке «Видео» выбор из них; без вариантов — ввод руками, поле пустое, своего значения нет. Добавьте поток, удалите его с вводом числа.
4. Новый детектор: «Где работает» предлагает то, что умеет камера. Нарисуйте зону мышью на кадре, «Применить»: `Device.zone` на сервере в долях кадра. Включение несовместимого — отказ со словами «несовместим с включённым детектором».
5. Камера с PTZ: кнопка нажата — `PUT /devices/{id}/ptz` с продлением, отпущена — `DELETE`. «Пресет» заводит строку с первым свободным номером, без подписи она показана номером, «Запомнить здесь» пишет положение, пустое имя снимает подпись, удаляет только «Удалить». В правиле номер выбирается из списка.
6. Источник событий: адрес `0.0.0.0` не сохраняется, сервер выбирается, камера титров — из списка, слова правятся. Вкладка «Титры» (0.5.0): камеры добавляются чипами, у каждой своя зона (тянуть мышью, числа, пресеты); вид титров виден в примере; слова начала и конца чека берутся из строк от кассы; слово подсветки — с флажками «С учётом регистра», «Вся строка», «Менять фон»; после «Применить» сервер хранит `overlays`, а `cameraId` равен первой камере. «Подключение»: RS-232 просит порт и скорость, при TCP их нет.
7. Единица СКУД: «Добавить единицу СКУД» — родитель, адрес, шаблон, папки нет. Кнопка команды выполняет её, правило берёт команду из списка.
8. «Журнал»: отбор по подсистеме приходит с сервера. «Права» → «Учётки потоков»: пароль показывается один раз.

## Откат и повтор

1. Сделайте две правки. В «Журнал» → «Операции» кнопка «Отменить» только у последней. Отмените её: кнопка появилась у предыдущей, у отменённой — «Повторить».
2. Отмените обе, повторите: сначала предыдущая, потом последняя. Новая правка убирает «Повторить» совсем.
3. Измените глубину хранилища и имя тома: обе правки в «Журнал» → «Операции», откатываются по одной. Измените размер тома: строка есть, «Отменить» отвечает «не выполнено», размер остался.
4. Добавьте детектор и в том же плане измените короткое имя камеры, примените и отмените: детектора нет, имя вернулось.
5. Пока идёт операция, откат или повтор: карточка объекта говорит, что он занят, план не показывается, переименование и удаление отказывают тостом. После конца снова можно. Кнопки «Пауза» нет.

## Встроенное хранилище и репликация — `tests/ui-edge.js`

1. «Запасной вход» → «Периферия» → строка «Встроенное хранилище»: вкладка «Репликация». Два постоянных типа, выбран «Забирать всё», состояние «в норме», обе проверки зелёные. «Выключена»: `PATCH replication {mode: off}`, камера снова пишет сама (`always`); «Забирать всё» возвращает `replica`.
2. «Главный вход»: тип «Забирать всё» берёт хранилище записи камеры как «Куда забирать». «Предел скорости» сохраняется. У хранилища «Зона хранения 1» носитель с ошибкой: при «Забирать всё» проверка красная, с пояснением.
3. Регистратор «Dahua NVR»: таблица камер, у «Камера NVR 9» флажка нет. Снять флажок у другой камеры: сервер ставит ей `always`; вернуть — `replica`. Сервер делает всё, кроме исключённых, и сам считает состояние каждой камеры.
4. «Забрать период…»: окно с началом и концом; сервер принимает просьбу `archive-fetch` и забирает пропуски внутри периода.
5. Блок «Репликация по правилам»: три шаблона. Нажатие открывает мастер правила с шаблоном и камерами хранилища; «Отмена» возвращает на страницу хранилища. Правило «Заполнять пропуски после обрыва связи» видно у хранилищ своих камер.
6. «Хранилища» → сервер → «Встроенные хранилища»: таблица камер с картой или диском, проблемы наверху («записи потеряны», «нет связи»), фильтр по состоянию, итог «Показано N из M»; камера регистратора — своя строка. Нажатие на строку открывает хранилище. То же у домена.
7. «Хранилища» → хранилище сервера → «Встроенные хранилища»: отметить два устройства, «Постоянная репликация…» → «Выключена» задаёт её сразу обоим.
8. Состояние меняет сервер по часам: пропуск камеры регистратора забран, страница хранилища показывает это сама, без перезагрузки.

## Просмотр в карточке камеры

Настоящего видео и записей на стенде нет: тестовая картинка и подставные куски, подпись видна.

1. Карточка камеры, закладка «Просмотр»: «Смотреть». Подпись «Подключаюсь…», затем «Идёт» и через какой шлюз, на кадре надпись, что это не камера. Выберите поток или сеть: показ начнётся заново. Уход на другую закладку или камеру закрывает соединение.
2. Сеть «Извне», пока раздача создана для локальной: «Раздачу создали для другой сети», кнопка «Переразместить» с подтверждением.
3. Камера с PTZ: тяните по кадру или держите кнопку зума на кадре, камера движется, отпустили — стоп. Фокус, пресеты и туры — на закладке «Видео». «Главный вход»: «Говорить», реле по строкам.
4. Пока идёт видео, новые события появляются в «События» сами, строки кассы привязанного источника — титром поверх кадра.
5. Шкала под видео: голова стоит в центре. Тяните шкалу: отпустили — запись с момента под головой, кусок за куском; щелчок — с момента под курсором. «Час», «6 часов», «Сутки», колесо, «−» и «+» меняют масштаб; «Всё» показывает все записи. Шкала дочитывает записи сама, когда её утащили за загруженный участок; таймера нет. Под головой нет записи — запись с начала следующей. Календарь отмечает сутки с записью; выбор суток — запись с начала суток. Щелчок по событию ведёт к его моменту. Фильтр по подсистеме сужает список.
6. «Удержать показанное»: окно, заметка, записи. То же окно ещё раз не теряет заметку. «Проверить» отвечает словом, «Снять» — с вводом числа. Нет держателя тома инцидентов — предупреждение.
7. «Отметить»: при проигрывании отметка встаёт на момент кадра, она на шкале и в списке. Правки у отметки нет.
8. Строка «Только в резервном или на устройстве»: «Закрепить», ответ говорит, сколько просьб подано и что отказано.

## Незнакомый вид — `tests/ui-unknown.js`

Объект вида, о котором интерфейс не знал заранее: `security_controller/CONTROLLER` и `/SENSOR` (настоящий плагин psim) и синтетический `test.unknown`. Всё, что ниже, должно работать **без кода под вид**: только по описанию из `GET /kinds`. Каждый пункт — шагами пользователя; проверка на сервере — прочитать `GET /units/{uid}`.

1. **Дерево.** Объект `test.unknown` в дереве — со значком и подписью вида из `/kinds` (не код, а `label.text` или словарь по `label.key`). Известные виды (камера, хранилище, том) по-прежнему открываются своими ручными экранами.
2. **Карточка по схеме.** Откройте объект: вкладки «Основное» и «Дополнительно» (`x-ui-tab`), группы полей («Опознание», «Подключение» — `x-ui-group`) в заданном порядке, единица у числа («%»), переключатель вместо поля для флага (`x-ui-widget: switch`). Подписи полей — из схемы.
3. **Правка и план.** Измените «Заголовок»: внизу «Не применено: 1», в плане «было → станет» с подписью из схемы. «Применить» — очередь, имя в дереве и значение в карточке обновляются после ответа. На сервере новое значение, версия сменилась.
4. **Ошибка по указателю.** Введите порт больше допустимого и примените: поле подсвечено красным, в подсказке — предел (`65535`), окно плана закрыто, ничего не записано.
5. **Незнакомое поле — только чтение.** Поле неизвестного типа (`hologram`) показано текстом без возможности правки; значение не потеряно. Поле `readOnly` недоступно, остальные правятся.
6. **Мастер.** У контроллера есть кнопка добавления: в окне — только допустимые вид дочерних (`security_controller/SENSOR`). Создайте датчик: он в дереве под контроллером и на сервере (`GET /units?parentId=`).
7. **Команда.** «Поставить на охрану» у контроллера выполняется сразу (`instant`): на сервере `status.observed.armed` сменился, в карточке и дереве — тоже. Команда с параметрами открывает форму по схеме `params`; без обязательного параметра — ошибка по указателю `/params/<имя>`.
8. **Страница плагина.** Кнопка «Страница плагина» — ссылка в новой вкладке с `type=<вид>`, `id=<uid>`, `lang=<язык интерфейса>`.
9. **Удаление.** Удалите созданный датчик: окно просит ввести `1`, пока числа нет — «Удалить» неактивна; после отсчёта объект исчез из дерева и с сервера (`404`).
10. **`kinds.changed` при открытом черновике.** Откройте карточку, измените поле (черновик), на стенде поменяйте описание вида (`PUT /test/kinds/{kind}`, например добавьте поле): карточка перерисовывается с новым полем, **правка не потеряна**. Если описание вида пропало (`GET /kinds/{kind}` — 404) — объект остаётся в дереве с общей иконкой и кодом вида, правка запрещена, черновик на месте.
11. **Свойства сверх профиля у известного вида.** У камеры во вкладке «Дополнительно» — поля, которых нет у ручного экрана (например, `configMode`); они правятся тем же черновиком. Команды, помеченные `ruleOnly`, кнопками не показываются.
12. **Добавить в корень домена.** У домена кнопка «Объект» предлагает виды с пустым `parents` в корне (`security_controller/CONTROLLER`, `test.unknown`), но не камеру и не датчик. Созданный контроллер виден в дереве под доменом.
13. **Поиск по полям `x-search`.** В строке поиска введите IP-адрес контроллера: он найден, в фильтре полей есть «IP-адрес» (`ip_address`, подпись из схемы). Переход на найденный объект моргает (О-01). Фильтр дерева по полю `ip_address` показывает только подходящие контроллеры. Чип «Контроллер охраны» (подпись из `/kinds`) в фильтрах дерева сужает дерево до объектов вида.
14. **Права и правила** (в `ui-unknown.js` нет — проверяется вручную; на уровне API это `api-rules.js` и `api-access.js`). В «Правах» у роли есть столбец класса доступа вида (`security_controller`) с уровнями из `UnitKind.access`; роль с уровнем ниже не может выполнить команду (`403`). В «Автоматизации» событие датчика (`ALARM`) и действие контроллера (`ARM`) берутся из описаний видов, цель выбирается по объекту.
